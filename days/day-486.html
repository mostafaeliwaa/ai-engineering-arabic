المشكلة: ليه patches مش pixels؟

تخيل إنك عايز تحكي لحد عن صورة في التليفون. لو قعدت تقوله لون كل بيكسل لوحده، هتقعد سنة. ولو قلتله «الصورة كلها» في جملة واحدة هيضيع منه مين جنب مين. الحل الوسط: تقسمها مربعات وتوصف كل مربع في جملة. ده بالظبط الـ patch.

صورة 224×224 RGB لو كل بيكسل token = 150,528 token. والـ attention تكلفتها تربيعية في طول الـ sequence:

196 × 196 = 38,416 vs 150,528 × 150,528 ≈ 22.6 billion

يعني الـ patches بتوفّر حوالي 590,000 مرة في حساب الـ attention لكل head في كل layer. ومربع 16×16 فيه إشارة كفاية للمهام العالية زي التصنيف.

وفي الناحية التانية، لو فردت الصورة كلها في متجه واحد ضخم، هترمي الـ locality (مين جنب مين)، والـ attention مش هتعرف ترجّعها.

02

linear projection واحدة كفاية · وحيلة الـ Conv2d

كل patch بيتعامل كمتجه مستقل. الـ projection بتتعلم basis: كواشف حواف (edges)، فلاتر ألوان، textures بسيطة. layer واحدة صغيرة (768 × 768 = 589,824 وزن في ViT-Base) وبتتدرب بسرعة. فيه stems أعمق بالـ convolution (الـ hybrid ViT)، بس الـ linear projection المسطحة هي الـ standard، ومعظم الـ open-weight encoders الحديثة بتيجي بنفس الشكل ده بالظبط.

الحيلة: Conv2d(in_channels=3, out_channels=hidden, kernel_size=patch, stride=patch) من غير padding بتدي نفس الرقم بالظبط زي unfold-then-linear. ليه؟ لأن الـ stride = حجم الـ kernel، فالفلتر بيقع على كل patch مرة واحدة من غير تداخل، وكل output عبارة عن dot product بين بيكسلز الـ patch وفلتر واحد. يعني كل فلتر = صف واحد في مصفوفة الـ linear.

معمل: نفس الرقم بطريقتين

صورة 8×8 (قناة واحدة) و patch = 4، يعني 4 patches. عندنا فلتر واحد 4×4 (يعني hidden = 1 للتبسيط). دوس «الخطوة الجاية»: الفلتر بيتنطط بالـ stride، وتحت هتلاقي الحسبة بطريقة الـ Conv2d وبطريقة flatten·w + b جنب بعض.

لاحظ: الفرق دايمًا صفر (أو قريب جدًا منه بسبب الـ float). ده بالظبط اللي التيست test_conv2d_matches_unfold_reference بيتأكد منه بـ atol=1e-5.

الـ Position Embedding الـ 2D sinusoidal

بعد الـ projection الـ tokens ملهاش ترتيب: الـ attention بتشوفهم كيس حاجات. فلازم كل token ياخد «عنوان» يقول هو في صف كام وعمود كام.

زي عنوان شقة: نص الأرقام بيقول الدور (row) ونصها بيقول رقم الشقة (col). كل نص فيه sin و cos على ترددات مختلفة، زي عقارب ساعة بسرعات مختلفة: عقرب سريع يفرّق بين الجيران، وعقرب بطيء يفرّق بين الأماكن البعيدة.

inv[k] = exp(−ln(10000)·k / quarter) k = 0..dim/4−1
row_emb = [sin(r·inv), cos(r·inv)] col_emb = [sin(c·inv), cos(c·inv)]
pos[r,c] = [row_emb(r) | col_emb(c)]

عشان كده dim لازم يقبل القسمة على ٤: نص للصف ونص للعمود، وكل نص فيه sin وcos. الـ CLS بياخد position = أصفار.

ليه ثابت مش متعلّم؟ لأنه deterministic: تقدر تغيّر الـ resolution من غير retraining، وبيـ interpolate بنضافة لشبكات الموديل ما شافهاش في التدريب.

جرب بإيدك: فوق خريطة الجدول نفسه (كل صف = token، كل عمود = بُعد). تحت دوس على أي خانة في الشبكة وشوف الـ cosine similarity بين عنوانها وعنوان كل الخانات التانية: الجيران بيبقوا متشابهين أكتر، وخانات نفس الصف أو نفس العمود بتشترك في نص المتجه.

ملحوظة من الكود: النورم بتاع كل position vector ثابت: كل زوج (sin, cos) مربعهم = 1، فالنورم = √(dim/2) لكل الخانات. ده جزء من «التوقيع» اللي الـ demo بيطبعه.

التكافؤ كـ sanity check

الـ patch step ليه طريقتين في الكتابة: Conv2d و unfold-then-linear صريح. لازم يدّوا نفس الـ output لنفس الأوزان. لو ما ادّوش، يبقى حسبة الـ unfold غلط، وكل الـ encoder اللي فوق مبني على رمل.

وفيه اختبار تاني من نفس النوع: لو عملت unfold وبعدين رجّعت (unflatten) من غير projection، لازم ترجع الصورة الأصلية بالظبط، لأن خطوة التقطيع نفسها قابلة للعكس. لو الرحلة دي ما رجعتش نفس البيكسلز، الـ unfold فيه bug.

الـ pipeline كله

224×224×3 → قطّع 16×16 → grid 14×14 → flatten كل patch → linear → 196 token × hidden → + CLS → + 2D position → (B, 197, 768)

from __future__ import annotations
import math
from dataclasses import dataclass
import numpy as np
import torch
import torch.nn as nn

@dataclass(frozen=True)
class FrontEndConfig:
    image_size: int = 224
    patch_size: int = 16
    in_channels: int = 3
    hidden: int = 768

    @property
    def grid_size(self) -> int:
        if self.image_size % self.patch_size != 0:      # لازم الـ patch يقسم الصورة بالظبط
            raise ValueError(f"patch_size {self.patch_size} must divide image_size {self.image_size}")
        return self.image_size // self.patch_size

    @property
    def num_patches(self) -> int:
        return self.grid_size * self.grid_size          # 14*14 = 196

خطوة ٢: جدول الـ position الـ 2D

def sinusoidal_2d(grid_h: int, grid_w: int, dim: int) -> torch.Tensor:
    if dim % 4 != 0:                                    # نص للصف ونص للعمود، وكل نص sin+cos
        raise ValueError(f"sinusoidal_2d dim must be divisible by 4, got {dim}")
    half = dim // 2
    quarter = half // 2

    freq = torch.arange(quarter, dtype=torch.float32)
    inv = torch.exp(-math.log(10000.0) * freq / max(1, quarter))   # ترددات من سريع لبطيء

    rows = torch.arange(grid_h, dtype=torch.float32).unsqueeze(1) * inv.unsqueeze(0)
    cols = torch.arange(grid_w, dtype=torch.float32).unsqueeze(1) * inv.unsqueeze(0)

    row_emb = torch.cat([torch.sin(rows), torch.cos(rows)], dim=1)
    col_emb = torch.cat([torch.sin(cols), torch.cos(cols)], dim=1)

    table = torch.zeros(grid_h, grid_w, dim)
    table[:, :, :half] = row_emb.unsqueeze(1).expand(-1, grid_w, -1)   # النص الأول = الصف
    table[:, :, half:] = col_emb.unsqueeze(0).expand(grid_h, -1, -1)   # النص التاني = العمود
    return table.reshape(grid_h * grid_w, dim)

خطوة ٣: الـ PatchEmbed بالـ Conv2d

class PatchEmbed(nn.Module):
    def __init__(self, cfg: FrontEndConfig) -> None:
        super().__init__()
        self.cfg = cfg
        self.proj = nn.Conv2d(cfg.in_channels, cfg.hidden,
                              kernel_size=cfg.patch_size,
                              stride=cfg.patch_size, bias=True)   # kernel = stride = patch

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        if x.dim() != 4:                                # افحص الـ input قبل أي حسبة
            raise ValueError(f"expected 4D input (B,C,H,W), got shape {tuple(x.shape)}")
        if x.shape[1] != self.cfg.in_channels:
            raise ValueError(f"channel mismatch: got {x.shape[1]}, expected {self.cfg.in_channels}")
        if x.shape[2] != self.cfg.image_size or x.shape[3] != self.cfg.image_size:
            raise ValueError(f"spatial mismatch: got {tuple(x.shape[2:])}, expected "
                             f"({self.cfg.image_size}, {self.cfg.image_size})")
        out = self.proj(x)                              # (B, hidden, 14, 14)
        out = out.flatten(2).transpose(1, 2)            # (B, 196, hidden)
        return out

خطوة ٤: الـ VisionFrontEnd (CLS + position)

class VisionFrontEnd(nn.Module):
    def __init__(self, cfg: FrontEndConfig) -> None:
        super().__init__()
        self.cfg = cfg
        self.patch = PatchEmbed(cfg)
        self.cls_token = nn.Parameter(torch.zeros(1, 1, cfg.hidden))
        nn.init.trunc_normal_(self.cls_token, std=0.02)   # CLS بيتعلم

        pos = sinusoidal_2d(cfg.grid_size, cfg.grid_size, cfg.hidden)
        cls_pos = torch.zeros(1, cfg.hidden)              # الـ CLS ملوش مكان
        full = torch.cat([cls_pos, pos], dim=0).unsqueeze(0)
        self.register_buffer("pos_embed", full, persistent=False)   # buffer مش parameter

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        tokens = self.patch(x)
        b = tokens.shape[0]
        cls = self.cls_token.expand(b, -1, -1)            # نفس الـ CLS لكل صورة في الـ batch
        tokens = torch.cat([cls, tokens], dim=1)          # (B, 197, hidden)
        return tokens + self.pos_embed

خطوة ٥: صورة اختبار ثابتة + المرجع بالـ unfold

def synthesize_image(seed: int, image_size: int = 224, channels: int = 3) -> torch.Tensor:
    rng = np.random.default_rng(seed)                   # seed ثابت = نفس الصورة كل مرة
    noise = rng.standard_normal((channels, image_size, image_size)).astype("float32") * 0.1
    y = np.linspace(0.0, 1.0, image_size, dtype="float32")
    x = np.linspace(0.0, 1.0, image_size, dtype="float32")
    gx, gy = np.meshgrid(x, y, indexing="xy")
    gradient = np.stack([gx, gy, (gx + gy) * 0.5], axis=0).astype("float32")
    img = np.clip(gradient + noise + 0.5, 0.0, 1.0)     # gradient ناعم + noise عالي التردد
    return torch.from_numpy(img).unsqueeze(0)

def unfold_then_linear(x, weight, bias, patch_size):
    if x.dim() != 4:
        raise ValueError(f"expected 4D input, got {tuple(x.shape)}")
    patches = x.unfold(2, patch_size, patch_size).unfold(3, patch_size, patch_size)
    b, c, gh, gw, ph, pw = patches.shape                # (B, C, 14, 14, 16, 16)
    flat = patches.permute(0, 2, 3, 1, 4, 5).reshape(b, gh * gw, c * ph * pw)
    w_flat = weight.reshape(weight.shape[0], -1)        # كل فلتر = صف
    return flat @ w_flat.T + bias
انتبه للـ permute: الترتيب (0, 2, 3, 1, 4, 5) بيحط القنوات قبل بيكسلز الـ patch، عشان الـ flatten يطلع بنفس ترتيب أوزان الـ Conv2d (hidden, C, P, P). لو غيّرته، الفرق هيبطل صفر.

التمارين

  1. Learned vs sinusoidal: بدّل الـ sinusoidal بـ nn.Parameter متعلّم وقارن أول epoch loss على مهمة تصنيف صغيرة synthetic. المتعلّم بيكسب على resolution ثابت، والـ sinusoidal بيكسب لما تغيّر الـ resolution بعد التدريب.
    تلميحself.pos_embed = nn.Parameter(torch.zeros(1, N+1, hidden)) مع trunc_normal_(std=0.02). خلّي كل حاجة تانية زي ما هي (نفس الـ seed ونفس الداتا) عشان المقارنة تبقى عادلة.
  2. Unfold + Linear صريح: بدّل الـ Conv2d بـ nn.Unfold + nn.Linear واتأكد إن الـ outputs متطابقة في حدود الـ float tolerance.
    تلميحnn.Unfold(kernel_size=P, stride=P) بيطلّع (B, C·P·P, N)، فاعمل .transpose(1, 2). انسخ الأوزان: linear.weight.data = conv.weight.reshape(hidden, -1) و linear.bias.data = conv.bias، وقارن بـ torch.allclose(..., atol=1e-5).
  3. Patches مش مربعة: ادعم patch زي 32×16 للصور العريضة، واتأكد إن جدول الـ position شغال مع grid مش مربع.
    تلميحخلي الـ config فيه patch_h و patch_w و image_h و image_w، و kernel_size=(ph, pw). الدالة sinusoidal_2d(grid_h, grid_w, dim) أصلًا بتاخد الاتنين منفصلين، فاختبر إن الشكل (gh·gw, dim).
  4. Profiling: قيس زمن الـ patch step على batch = 1 و 8 و 64. الـ patch projection نادرًا بيبقى الـ bottleneck؛ الـ attention اللي بعده هي اللي بتاكل الوقت.
    تلميحاستخدم time.perf_counter() واعمل warm-up كام مرة الأول، وجوه torch.no_grad(). اقسم الزمن على الـ batch عشان تشوف الزمن لكل صورة.
  5. Frozen feature extractor: استخدم الـ front end مجمد على dataset synthetic من ٤ أشكال (دواير، مربعات، مثلثات، نجوم). الـ CLS output المفروض يتفصل خطيًا.
    تلميحارسم الأشكال بـ numpy على صور 224، عدّيها على الموديل، وخد tokens[:, 0]، ودرّب nn.Linear(hidden, 4) بس فوقيهم. خلي الـ front end requires_grad_(False).
  6. إضافة مني · tokenizer budget لـ VLM: اكتب دالة token_budget(h, w, patch, max_tokens) ترجع عدد الـ patch tokens لصورة مقاسها h×w، ولو عدّى max_tokens ترجع أكبر resolution (مضاعفات الـ patch) تحافظ على الـ aspect ratio وتقع تحت الحد. ده سؤال حقيقي بتقابله لما تبعت صور لموديل multimodal وعايز تتحكم في التكلفة والـ context.
    تلميحعدد الـ tokens = (h // p) * (w // p). لو كبير، اضرب h و w في s = sqrt(max_tokens / tokens) وقرّب لتحت لأقرب مضاعف لـ p، وتأكد بـ assert إن الناتج ≤ max_tokens.

الحدس: الـ patch = «كلمة» بصرية

اسم ورقة الـ ViT نفسه «An Image is Worth 16x16 Words». الـ patch بيلعب دور الـ token في النص، والـ projection بتلعب دور الـ embedding table. الفرق إن في النص الـ embedding بيتعمل lookup بـ ID، هنا بيتحسب بضرب مصفوفة لأن الـ patch مش من vocabulary محدود.

أخطاء شائعة

  • • تنسى إن الـ CLS بيزود token: تعمل مصفوفة position بطول 196 بدل 197 وتاخد shape error.
  • • ترتيب غلط في الـ permute قبل الـ flatten: الكود يشتغل من غير error بس الأرقام مختلفة عن الـ Conv2d. عشان كده تيست التكافؤ مهم.
  • • صورة مقاسها مش من مضاعفات الـ patch: الـ config هنا بيرفضها بـ ValueError بدل ما الـ Conv2d يقطع الأطراف بصمت.
  • • تسجّل الـ position كـ nn.Parameter وانت عايزه ثابت: كده هيتدرب وهيتعد في البارامترز. الكود بيستخدم register_buffer.
  • • تفتكر الـ patch projection هو اللي بيبطّأ: التمرين ٤ هيوريك إن الـ attention هي اللي بتاكل.

بيظهر فين في الـ LLMs والـ agents

أي agent بيشوف screenshot أو PDF مصوّر بيعدّي على front end زي ده. الدرس بيقول نفس الـ front end موجود في CLIP ViT-L/14 و SigLIP و DINOv2 وعيلة Qwen-VL و InternVL؛ الاختلافات بعده (CLS ولا لأ، register tokens، patch 14 ولا 16، dynamic resolution بالـ interpolation). عمليًا: عدد الـ patches = عدد الـ tokens اللي الصورة بتاكلها من الـ context، فكل ما الصورة تكبر، التكلفة تزيد. ده سبب التمرين الإضافي.

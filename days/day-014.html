تسخين ٥ دقايق: فاكر امبارح؟

امبارح في Numerical Stability شفنا إن الكمبيوتر مش بيحسب بالأرقام الحقيقية، بيحسب بـ floating point محدود. جاوب في دماغك الأول، وبعدين افتح الإجابة.

١. ليه 0.1 + 0.2 == 0.3 بترجع False في Python؟

لأن 0.1 و0.2 مالهمش تمثيل مظبوط في الـ binary، فكل واحد فيهم متخزن بقيمة قريبة منه بس. المجموع بيطلع 0.30000000000000004. عشان كده بنقارن الـ floats بتسامح (tolerance) زي math.isclose أو np.allclose.

٢. إيه هي حيلة الـ log-sum-exp (أو softmax المستقر)؟

قبل ما تعمل exp اطرح أكبر قيمة من كل القيم. النتيجة رياضيًا هي هي، بس exp عمرها ما هتاخد رقم كبير فمفيش overflow. كل softmax في أي framework بيعمل كده من جوه.

٣. ليه بنقسم على norm بحذر لما يكون ممكن يبقى صفر؟

القسمة على صفر بتطلع inf أو nan، والـ nan بتنتشر في كل الحسابات اللي بعدها. هتشوف النهاردة إن الكود بيتشيك على norm == 0 قبل الـ cosine similarity لنفس السبب بالظبط.

الـ Norm: «حجم» المتجه

الـ norm بيقيس حجم المتجه، يعني قد إيه هو بعيد عن الصفر. والسر اللي هيبسّط الدرس كله: أي مسافة بين متجهين هي norm الفرق بينهم.

d(a, b) = ‖a − b‖

يعني لو فهمت الـ norms، فهمت المسافات.

L1 Norm: مسافة مانهاتن

‖x‖₁ = |x₁| + |x₂| + … + |xₙ|

اسمها Manhattan distance عشان شبه المشي في شوارع مدينة مقسمة مربعات: تمشي على الشوارع بس، مفيش قطع بالورب. من A=(1,1) لـ B=(4,5): |4−1| + |5−1| = 3 + 4 = 7. يعني ٣ بلوكات شرق و٤ شمال.

إمتى تستخدمها؟ الداتا الـ sparse كتير الأبعاد (features نصية، one-hot)، ولما عايز تبقى مقاوم للـ outliers (فرق واحد ضخم مش بيسيطر)، ومشاكل اختيار الـ features.

علاقتها بالـ Lasso والـ MAE: لو ضفت ‖w‖₁ للـ loss (ده L1 regularization أو Lasso)، الأوزان الصغيرة بتتزق لـ صفر بالظبط، فكأن الموديل بيختار الـ features لوحده. والـ MAE هي متوسط مسافة L1 بين التوقع والهدف: بتعاقب كل الأخطاء بشكل خطي، فهي أقوى قدام الـ outliers من الـ MSE.

L2 Norm: المسافة العادية (Euclidean)

‖x‖₂ = √(x₁² + x₂² + … + xₙ²)

دي فيثاغورس اللي اتعلمته في المدرسة بس في n بُعد. نفس النقطتين: √(3² + 4²) = √25 = 5. الخط المستقيم اللي بيقطع الشبكة بالورب.

إمتى؟ داتا continuous أبعادها قليلة لمتوسطة، والـ features في نفس الـ scale، مسافات فيزيائية (أماكن، حساسات)، ومقارنة صور على مستوى البيكسل.

علاقتها بالـ Ridge والـ MSE: لو ضفت ‖w‖₂² للـ loss (Ridge)، الأوزان الكبيرة بتتعاقب، بس مفيش وزن بيوصل لصفر بالظبط؛ كلهم بيصغروا بنسبة. والـ MSE هي متوسط مربع مسافة L2: التربيع بيخلّي الخطأ الكبير يتعاقب أكتر بكتير من الصغير.
MAE (L1 loss): |y − ŷ| → عقاب خطي، مقاوم للـ outliers
MSE (L2 loss): (y − ŷ)² → عقاب تربيعي، حساس للـ outliers

عيلة Lp كلها، وL∞

L1 وL2 حالتين خاصتين من قانون عام:

‖x‖ₚ = (|x₁|ᵖ + |x₂|ᵖ + … + |xₙ|ᵖ)^(1/p)

كل قيمة لـ p بتدي شكل مختلف لـ «الكورة» (unit ball)، يعني كل النقط اللي بعدها عن الصفر ≤ 1:

pشكل الـ unit ball
p = 1معين (diamond)، أركانه على المحاور
p = 2دايرة / كرة عادية
p = 3superellipse، مربع حوافه مدوّرة
p = ∞مربع / hypercube، جوانبه موازية للمحاور

لما p تكبر لحد ما لا نهاية، الـ norm بيبقى أكبر قيمة مطلقة بس. ده L∞ أو Chebyshev distance: المسافة بيحددها البُعد الوحيد اللي الفرق فيه أكبر، والباقي متجاهَل.

‖x‖∞ = max(|x₁|, …, |xₙ|) A=(1,1), B=(4,5) → max(3, 4) = 4

إمتى؟ لما أسوأ انحراف في أي بُعد هو اللي يهمك: الملك في الشطرنج (خطوة في أي اتجاه حتى بالورب = ١)، وحدود التصنيع (كل بُعد لازم يبقى جوه المواصفات).

قاعدة هتشوفها في الكود: دايمًا L∞ ≤ L2 ≤ L1. وبشكل عام لأي p₁ < p₂: ‖x‖ₚ₂ ≤ ‖x‖ₚ₁. كل ما p تكبر، الـ norm بيركز على مكونات أقل وأكبر.

ليه L1 بيصفّر الأوزان وL2 لأ؟

الـ regularization = loss + عقاب على norm الأوزان:

Lasso (L1): loss + λ·‖w‖₁ → أوزان sparse، بعضها صفر بالظبط، اختيار features أوتوماتيك
Ridge (L2): loss + λ·‖w‖₂² → كل الأوزان بتصغر، مفيش حاجة بتبقى صفر
Elastic Net: loss + λ₁‖w‖₁ + λ₂‖w‖₂² → sparsity من L1 + ثبات من L2

الـ Lasso حلها فيه «أركان» (مش قابلة للتفاضل عند الصفر)، والـ Ridge ناعمة في كل حتة. والـ Elastic Net بتجمع الاتنين، ومجموعات الـ features المترابطة بتتشال أو تفضل مع بعض.

الصورة الهندسية: في فضاء وزنين، قيد L1 شكله معين، وقيد L2 دايرة. منحنيات الـ loss (القطوع الناقصة) غالبًا بتلمس المعين عند ركن، والركن ده على محور يعني وزن فيهم = صفر. أما الدايرة فمفيهاش أركان، فاللمس بيبقى في نقطة ناعمة والوزنين مش صفر.

Cosine وDot Product وMahalanobis

Cosine Similarity: الزاوية بس

cos_sim(a, b) = (a · b) / (‖a‖₂ · ‖b‖₂) cos_dist = 1 − cos_sim

من −1 (عكس بعض) لـ +1 (نفس الاتجاه)، وصفر لو متعامدين. والـ cosine distance من 0 لـ 2. مثال: a=(1,0), b=(1,1) → 1/√2 = 0.707، والمسافة 0.293.

ليه هو ملك الـ NLP؟ مقالة عن القطط طولها الضعف لسه «عن القطط». الطول هنا noise والاتجاه هو المعنى. مستندين بنفس توزيع الكلمات بس طولهم مختلف بيشاوروا لنفس الاتجاه، والـ cosine بينهم = 1. استخدمه في: TF-IDF والـ embeddings، أي مجال الطول فيه noise، الـ recommendation، والبحث في الـ vector databases.

Dot Product مقابل Cosine

a · b = ‖a‖ ‖b‖ cos(θ)

الـ cosine هو الـ dot مقسوم على الطولين. لو المتجهين طولهم ١ (normalized)، الاتنين نفس الرقم بالظبط. الفرق إن الـ dot فيه معلومة الطول: المتجه الأطول بياخد score أعلى. ده مفيد لما عايز الحاجات «المشهورة» تطلع فوق، فالطول بيبقى إشارة جودة أو أهمية.

a=(3,0) b=(1,0) c=(0,1) dot(a,b)=3 dot(a,c)=0 cos(a,b)=1.0 cos(a,c)=0.0

عمليًا: cosine لو عايز الاتجاه بس، dot لو الطول ليه معنى. الـ vector DBs زي Pinecone وWeaviate وQdrant بتخليك تختار. ولو الـ embeddings بتاعتك L2-normalized، الاختيار مش فارق.

Mahalanobis: مسافة فاهمة الارتباط

الـ L2 بيعامل كل الأبعاد زي بعض. بس لو الـ features مترابطة أو مختلفة في الـ scale، النتيجة بتضلل. الـ Mahalanobis بتاخد الـ covariance بتاعة الداتا في الحسبان:

d_M(x, y) = √( (x − y)ᵀ S⁻¹ (x − y) )

تخيل إنك الأول بتعمل whitening: تفك الارتباط وتوحد الـ scale، وبعدين تحسب L2 عادي. لو S هي مصفوفة الوحدة، الـ Mahalanobis بتبقى L2 بالظبط.

مثال الطول والوزن: واحد طوله 6'2" ووزنه 180 lbs طبيعي. واحد 5'0" بنفس الوزن غريب. ممكن الـ L2 يقول الاتنين بنفس البعد عن المتوسط، لكن الـ Mahalanobis بتعرف إن التاني outlier لأنها فاهمة إن الطول والوزن ماشيين مع بعض.

إمتى؟ كشف الـ outliers، التصنيف لما الـ features مختلفة الـ scale ومترابطة، لما عندك داتا كفاية تقدّر منها covariance موثوقة، ومراقبة الجودة في المصانع.

مسافات لحاجات مش متجهات: مجموعات، نصوص، توزيعات

Jaccard: للمجموعات

J(A, B) = |A ∩ B| / |A ∪ B| Jaccard distance = 1 − J

A={cat, dog, fish} وB={cat, bird, fish, snake}: التقاطع ٢، الاتحاد ٥، يعني J = 0.4 والمسافة 0.6.

إمتى؟ مقارنة tags أو categories، تشابه مستندات بوجود الكلمة (مش تكرارها)، كشف النسخ شبه المتطابقة (MinHash بيقرّب الـ Jaccard)، الـ binary features، وتقييم موديلات الـ segmentation: الـ IoU هو الـ Jaccard نفسه.

Edit Distance (Levenshtein): للنصوص

أقل عدد عمليات على حرف واحد (إضافة، حذف، تبديل) عشان تحوّل كلمة لكلمة. kitten → sitten → sittin → sitting = 3. بتتحسب بالـ dynamic programming: خانة (i, j) = المسافة بين أول i حرف من الأولى وأول j حرف من التانية.

معمل صغير: جدول الـ DP

اكتب أي كلمتين وشوف الجدول بيتملي. الخانة الأخيرة تحت على اليمين هي الإجابة. الخانات الملونة هي طريق واحد من أقل الطرق.

بيستخدم في: التصحيح الإملائي، محاذاة الـ DNA (بأوزان للعمليات)، الـ fuzzy matching، وتنضيف النصوص المكررة.

KL Divergence: مش مسافة، بس بيتستخدم كأنها مسافة

D_KL(P ‖ Q) = Σ p(x) · log( p(x) / q(x) )

شفناها في يوم ٩. هنا المهم: هي مش symmetric، D_KL(P‖Q) ≠ D_KL(Q‖P)، ومش بتحقق الـ triangle inequality. يعني divergence مش distance.

  • Forward KL D_KL(P‖Q) «mean-seeking»: Q بتحاول تغطي كل قمم P.
  • Reverse KL D_KL(Q‖P) «mode-seeking»: Q بتركز على قمة واحدة.

بتظهر في: الـ VAEs (ترم الـ KL في الـ ELBO)، الـ knowledge distillation، الـ RLHF (عقاب KL عشان الموديل ميبعدش عن الأصل)، والـ policy gradient.

Wasserstein (Earth Mover's Distance)

تخيل توزيع كوم تراب والتاني حفرة. أقل «شغل» (كمية التراب × المسافة اللي اتنقلها) عشان تملا الحفرة هو الـ Wasserstein. في بُعد واحد بيبقى مجموع الفرق المطلق بين الـ CDFs:

W₁(P, Q) = ∫ |CDF_P(x) − CDF_Q(x)| dx

ليه مهم؟ هو metric حقيقي (symmetric وبيحقق الـ triangle inequality)، وبيدي gradient مفيد حتى لو التوزيعين مش متداخلين خالص، في حين الـ KL بتروح لـ ∞. الخاصية دي هي اللي خلت الـ WGAN يحل عدم استقرار تدريب الـ GANs الأصلية. بيستخدم كمان في الـ optimal transport ومقارنة color histograms في البحث عن الصور.

معمل ٠٤: زق التوزيع وشوف مين بيفهم

إضافة مني: اللي الدرس ما قالهوش صريح

الحدس في سطر: اختيار المسافة = تعريفك لكلمة «شبه». مش تفصيلة تقنية، ده قرار بيزنس: «يوزرين شبه بعض» معناها نفس الذوق (cosine) ولا نفس كمية الاستخدام كمان (dot/L2)؟

غلطات شائعة

  1. L2 على features مش متوحدة الـ scale: لو feature بالجنيه (آلاف) وfeature بالسنين (عشرات)، الـ L2 هيبقى فعليًا مسافة على الفلوس بس. اعمل standardization الأول، أو استخدم Mahalanobis.
  2. تخلط cosine similarity وcosine distance: واحدة الأكبر أحسن والتانية الأصغر أحسن. لو رتبت غلط، الـ RAG هيرجعلك أبعد مستندات.
  3. تستخدم dot product على embeddings مش normalized وانت فاكره cosine: المستندات الطويلة أو اللي متجهها طويل هتطلع فوق دايمًا. لو مش متأكد، اعمل normalize واستريح.
  4. تتعامل مع KL كأنها مسافة: KL(P‖Q) وKL(Q‖P) أرقام مختلفة ومعانيها مختلفة؛ اتأكد إنت حاسب أنهي واحدة.
  5. تنسى إن الـ metric في الـ vector DB بيتحدد وقت إنشاء الـ index: لو الـ embedding model بتاعك متدرب على cosine واخترت L2 من غير normalization، الترتيب هيبوظ بهدوء من غير أي error.

فين بيظهر في الـ LLMs والـ Agents؟

  • RAG وmemory بتاعة الـ agents: كل retrieval هو nearest-neighbor بـ cosine أو dot على embeddings، غالبًا بـ HNSW.
  • Attention: الـ score بين query وkey هو dot product (مقسوم على √d). يعني الـ attention نفسها «مسافة» بالـ dot.
  • Deduplication لداتا التدريب: MinHash بيقرّب الـ Jaccard عشان يشيل الصفحات المكررة قبل تدريب الـ LLM.
  • RLHF: عقاب الـ KL بيمنع الموديل يبعد كتير عن الموديل الأصلي وهو بيتعلم من الـ reward.
  • Fuzzy matching لأسماء الأدوات: لو الـ agent كتب اسم tool غلط حرف، edit distance بتلاقي أقرب اسم صح.

def l1_distance(a, b):
    return sum(abs(ai - bi) for ai, bi in zip(a, b))

def l2_distance(a, b):
    return math.sqrt(sum((ai - bi) ** 2 for ai, bi in zip(a, b)))

def lp_distance(a, b, p):
    diff = [ai - bi for ai, bi in zip(a, b)]
    return lp_norm(diff, p)

def linf_distance(a, b):
    return max(abs(ai - bi) for ai, bi in zip(a, b))

def dot_product(a, b):
    return sum(ai * bi for ai, bi in zip(a, b))

def cosine_similarity(a, b):
    dot = dot_product(a, b)
    norm_a, norm_b = l2_norm(a), l2_norm(b)
    if norm_a == 0 or norm_b == 0:   # حماية من القسمة على صفر (افتكر امبارح)
        return 0.0
    return dot / (norm_a * norm_b)

def cosine_distance(a, b):
    return 1.0 - cosine_similarity(a, b)

def normalize_vector(v):             # نفس الاتجاه، طول = 1
    norm = l2_norm(v)
    if norm == 0:
        return v[:]
    return [vi / norm for vi in v]

a, b = [1, 2, 3], [4, 0, 6]
print(l1_distance(a, b), l2_distance(a, b), lp_distance(a, b, 3), linf_distance(a, b))

خطوة ٣: Mahalanobis (ومعاها inverse بالـ Gauss-Jordan)

def invert_matrix(matrix):
    n = len(matrix)
    # حط مصفوفة الوحدة جنبها: [M | I]
    augmented = [row[:] + [1.0 if i == j else 0.0 for j in range(n)]
                 for i, row in enumerate(matrix)]
    for col in range(n):
        # partial pivoting: اختار أكبر pivot عشان الاستقرار العددي
        max_row = col
        for row in range(col + 1, n):
            if abs(augmented[row][col]) > abs(augmented[max_row][col]):
                max_row = row
        augmented[col], augmented[max_row] = augmented[max_row], augmented[col]
        pivot = augmented[col][col]
        if abs(pivot) < 1e-12:
            raise ValueError("Matrix is singular or near-singular")
        for j in range(2 * n):
            augmented[col][j] /= pivot
        for row in range(n):           # صفّر العمود في باقي الصفوف
            if row != col:
                factor = augmented[row][col]
                for j in range(2 * n):
                    augmented[row][j] -= factor * augmented[col][j]
    return [row[n:] for row in augmented]   # الشمال بقى I، واليمين بقى M⁻¹

def mahalanobis_distance(x, y, cov_matrix):
    n = len(x)
    diff = [xi - yi for xi, yi in zip(x, y)]
    inv_cov = invert_matrix(cov_matrix)
    temp = [0.0] * n
    for i in range(n):
        for j in range(n):
            temp[i] += diff[j] * inv_cov[j][i]
    result = sum(temp[i] * diff[i] for i in range(n))
    return math.sqrt(max(0, result))     # max عشان أخطاء التقريب الصغيرة

def compute_covariance(data):
    n, d = len(data), len(data[0])
    means = [sum(data[i][j] for i in range(n)) / n for j in range(d)]
    centered = [[data[i][j] - means[j] for j in range(d)] for i in range(n)]
    cov = [[0.0] * d for _ in range(d)]
    for i in range(d):
        for j in range(d):
            cov[i][j] = sum(centered[k][i] * centered[k][j] for k in range(n)) / (n - 1)
    return cov

def jaccard_similarity(set_a, set_b):
    if not set_a and not set_b:       # مجموعتين فاضيين = متطابقين
        return 1.0
    return len(set_a & set_b) / len(set_a | set_b)

def edit_distance(s1, s2):
    m, n = len(s1), len(s2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1):
        dp[i][0] = i                    # امسح i حرف
    for j in range(n + 1):
        dp[0][j] = j                    # ضيف j حرف
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if s1[i - 1] == s2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]          # نفس الحرف: ببلاش
            else:
                dp[i][j] = 1 + min(dp[i - 1][j],     # حذف
                                   dp[i][j - 1],     # إضافة
                                   dp[i - 1][j - 1]) # تبديل
    return dp[m][n]

print(jaccard_similarity({"cat", "dog", "fish"}, {"cat", "bird", "fish", "snake"}))
for s1, s2 in [("kitten", "sitting"), ("sunday", "saturday"), ("python", "pytorch")]:
    print(s1, s2, edit_distance(s1, s2))

def kl_divergence(p, q):
    total = 0.0
    for pi, qi in zip(p, q):
        if pi > 0:
            if qi <= 0:
                return float('inf')    # P عندها كتلة وQ صفر: لا نهاية
            total += pi * math.log(pi / qi)
    return total

def wasserstein_1d(p, q):
    assert len(p) == len(q), "Distributions must have the same number of bins"
    n = len(p)
    cdf_p, cdf_q = [0.0] * n, [0.0] * n
    cdf_p[0], cdf_q[0] = p[0], q[0]
    for i in range(1, n):               # الـ CDF = مجموع تراكمي
        cdf_p[i] = cdf_p[i - 1] + p[i]
        cdf_q[i] = cdf_q[i - 1] + q[i]
    return sum(abs(cdf_p[i] - cdf_q[i]) for i in range(n))

print(kl_divergence([0.9, 0.1], [0.5, 0.5]), kl_divergence([0.5, 0.5], [0.9, 0.1]))
print(wasserstein_1d([0.5, 0.5, 0, 0], [0, 0, 0.5, 0.5]))

def find_nearest_neighbor(query, dataset, distance_fn, **kwargs):
    best_idx, best_dist = 0, float('inf')
    for i, point in enumerate(dataset):
        d = distance_fn(query, point, **kwargs)
        if d < best_dist:
            best_dist, best_idx = d, i
    return best_idx, best_dist

def find_k_nearest(query, dataset, distance_fn, k=5, **kwargs):
    distances = [(i, distance_fn(query, p, **kwargs)) for i, p in enumerate(dataset)]
    distances.sort(key=lambda x: x[1])
    return distances[:k]

import numpy as np

def cosine_similarity_matrix(X):
    norms = np.linalg.norm(X, axis=1, keepdims=True)
    norms = np.where(norms == 0, 1, norms)       # حماية من الصفر
    X_normalized = X / norms
    return X_normalized @ X_normalized.T          # كل الأزواج مرة واحدة

embeddings = np.random.randn(1000, 768)           # 1000 مستند، كل واحد 768 رقم

top_k = np.argsort(similarities)[::-1][1:6]       # [1:6] عشان نشيل العنصر نفسه
print(f"Top 5 most similar to item 0: {top_k}")

التمارين

اعمل ١ و٢ و٤ النهاردة على الأقل. ٣ و٥ أطول، ممكن تكمّلهم بكرة.

  1. ترتيب الـ norms: احسب L1 وL2 وL∞ بين (1,2,3) و(4,0,6). اتأكد إن L∞ ≤ L2 ≤ L1، وأثبت ليه ده دايمًا صح.
    تلميح وإجابة

    الفرق (-3, 2, -3): L1 = 8، L2 = √22 ≈ 4.69، L∞ = 3. الإثبات: max|dᵢ|² ≤ Σdᵢ² (أكبر مربع جزء من المجموع)، فـ L∞ ≤ L2. و(Σ|dᵢ|)² = Σdᵢ² + حدود ضرب موجبة ≥ Σdᵢ²، فـ L2 ≤ L1.

  2. cosine عالي وL2 كبير (والعكس): اعمل متجهين cosine بينهم > 0.9 بس L2 > 10، وبعدين متجهين cosine < 0.3 وL2 < 0.5.
    تلميح

    الأولى: نفس الاتجاه تقريبًا وواحد أطول بكتير، زي [1,1] و[10,10.5]. التانية: متجهين صغيرين جنب الصفر في اتجاهات مختلفة، زي [0.1,0] و[0,0.1] (cosine = 0 وL2 ≈ 0.14). جرّبهم في المعمل ٠١ كمان.

  3. أربع مقاييس، أربع إجابات: اعمل دالة بتاخد dataset وquery وترجع أقرب جار بـ L1 وL2 وcosine وMahalanobis. لاقي dataset الأربعة فيها مختلفين.
    تلميح

    نادي find_nearest_neighbor(query, dataset, fn) لكل دالة (والـ Mahalanobis محتاجة cov_matrix=). اقرا demo_different_neighbors الأول، وبعدين حرّك النقط. فكرة: نقطة بعيدة بس في نفس اتجاه الـ query تكسب الـ cosine، ونقطة على اتجاه الارتباط تكسب الـ Mahalanobis.

  4. Wasserstein بالإيد: بين [0.5,0.5,0,0] و[0,0,0.5,0.5]، وبين [0.25,0.25,0.25,0.25] و[0,0,0.5,0.5]. أنهي أكبر وليه؟
    الإجابة

    الأولى: CDFs = [.5,1,1,1] و[0,0,.5,1]، الفروق .5+1+.5+0 = 2. التانية: [.25,.5,.75,1] و[0,0,.5,1]، الفروق .25+.5+.25+0 = 1. الأولى أكبر لأن كل الكتلة لازم تتنقل خانتين، أما في التانية نص الكتلة أصلًا قريب من مكانها.

  5. MinHash: اعمل MinHash لتقريب الـ Jaccard. ١٠٠ مجموعة عشوائية، احسب الـ Jaccard الحقيقي لكل الأزواج، وقارنه بالتقريب بـ 50 و100 و200 hash function، وارسم الخطأ.
    تلميح

    لكل hash function، توقيع المجموعة = أقل hash لعناصرها. نسبة الـ hash functions اللي فيها المجموعتين ليهم نفس الأقل = تقدير الـ Jaccard. الخطأ المفروض يقل تقريبًا زي 1/√k. ممكن تعمل hash functions بـ (a·hash(x) + b) % prime بـ a وb عشوائيين.

  6. إضافة مني · اختبار الـ retriever: خد ١٠ جمل، اعمل لكل جملة متجه عدّ كلمات (زي ميني RAG بتاع يوم ١). لكل query، رتّب الجمل مرة بـ cosine ومرة بـ dot ومرة بـ L2. لاقي query الترتيب فيها بيختلف، واشرح ليه (هتلاقي الجمل الطويلة بتكسب في الـ dot). بعدين اعمل normalize للمتجهات وشوف الترتيبات بقت متفقة إزاي. ده بالظبط القرار اللي هتاخده لما تختار metric لـ vector DB حقيقية.
    تلميح

    بعد الـ normalization: cosine وdot نفس الترتيب بالظبط. وL2 كمان، لأن للمتجهات اللي طولها ١: ‖a−b‖² = 2 − 2·cos، فترتيب L2 تصاعدي = ترتيب cosine تنازلي.

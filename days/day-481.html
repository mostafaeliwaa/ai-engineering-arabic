امبارح بنيت الـ runner (درس ٥٢: Experiment Runner). جاوب في دماغك الأول، وبعدين افتح الإجابة.

  1. إيه الـ terminal labels الأربعة؟ وأنهي بياخد الأولوية؟

  3. ليه الـ seed بيتمرر في config["__seed"]؟
    الإجابةعشان التشغيل يبقى deterministic: نفس الـ seed = نفس الـ metrics، فالـ evaluator يفرّق التغيير الحقيقي عن اختلاف التهيئة.

01

ليه Paired t test؟ الرقم الواحد مش دليل

الـ runner طلّع أرقام. دلوقتي السؤال: الأرقام دي تحسّن ولا تراجع ولا مجرد ضوضاء؟ نفس الـ configuration بـ seed تاني بيدّي perplexity تاني. فرقم واحد لا يقول إن التغيير حقيقي.

تشبيه: عايز تعرف لو دواء جديد بيخفّض الضغط. تقارن ضغط شخص بعد الدواء بضغط شخص تاني تمامًا؟ لأ. بتقارن نفس الشخص قبل وبعد. كل شخص عنده «خط أساس» مختلف، والمقارنة المزدوجة (paired) بتلغي الاختلاف ده. هنا الـ «الشخص» هو الـ seed.

المقارنة الصح: نفس الـ seeds ونفس الداتا، تتشغّل مرة بالـ candidate ومرة بالـ baseline. كل seed بيدّي فرق. متوسط الفروق = حجم التأثير (effect). والـ standard error بتاع الفروق = أرضية الضوضاء (noise floor).

diffs = [a_i - b_i for i in seeds] mean = sum(diffs) / n variance = sum((d - mean)**2 for d in diffs) / (n - 1) t_stat = mean / sqrt(variance / n) df = n - 1 p_value = two_sided_p(t_stat, df)

الدرس بيطبّق الاختبار من الصفر: مفيش scipy.stats. الرياضيات صغيرة وتتقرا في شاشة واحدة. الـ p value بيتحسب من regularised incomplete beta function بـ Lentz continued fraction (حوالي ٦٠ سطر stdlib).

02

التحسّن مع مراعاة الاتجاه (Direction Aware)

بعض الـ metrics بتتحسّن لما تزيد (accuracy، throughput)، وبعضها لما تقل (loss، perplexity، الوقت). فكل metric معاه حقل direction.

higher_is_better: improvement = (candidate - baseline) / |baseline| lower_is_better: improvement = (baseline - candidate) / |baseline|

الـ improvement موقّع (signed): سالب على metric من نوع higher_is_better معناه إن الـ candidate أسوأ. والـ verdict بيقرا الإشارة والحجم مع بعض. وفي كود الدرس لو الـ baseline = 0 بيستخدم قاسم 1 عشان ميقسمش على صفر.

وبعدين في threshold ثابت (improvement_threshold = 0.02 يعني 2%). تحت الـ threshold الحكم «noise» مهما كان الـ p value، لأن الـ loop مش مهتم بتغيير المستخدم مش هيقدر يقيسه.

لاحظ الترتيب: الـ threshold gate بيشتغل قبل الـ significance gate. تغيير دلالته إحصائية بس صغير جدًا = noise برضه.
03

معمل ١: الـ Improvement والـ Threshold والـ Log

حسّب التحسّن بإيدك

غيّر الـ baseline والـ candidate، وبدّل الاتجاه (0 = lower is better زي perplexity، 1 = higher is better زي accuracy)، وبدّل الـ scale (0 = linear، 1 = log).

جرّب 32 → 28 على perplexity بـ log: هتلاقي 3.466 → 3.332 والتحسّن حوالي 0.039 يعدّي الـ 2%.

الـ Log Normalisation: ليه؟

الـ perplexity أُسّية في الـ loss: نزول 0.1 في الـ loss بيبقى نزول أكبر بكتير في الـ perplexity. للمقارنة بين الاتنين في تقرير واحد، أي metric scale بتاعها "log" بنأخد log الطبيعي قبل ما نحسب الـ improvement، وبنطبّق الـ threshold في الـ log space. الـ linear بيعدّي من غير تحويل، والكود واحد للاتنين. وأي قيمة غير موجبة على scale لوغاريتمي بترمي ValueError.

scale == "log": a = log(candidate), b = log(baseline) else: a = candidate, b = baseline
04

معمل ٢: الـ Paired Test في الفعل

الـ evaluator بيجمّع نتيجة لكل seed للـ candidate ولل baseline، وبيزاوجهم بالـ seed (محفوظ في result.metrics["seed"]). لو الـ seeds مش متطابقة بيرمي PairingError (والـ orchestrator يعيد التشغيل). وكمان بيرفض seed مكرر أو ناقص.

ضوضاء الـ seeds مقابل الأثر الحقيقي

كل seed ليه «صعوبة» خاصة بيه بتأثر على الـ baseline والـ candidate مع بعض (shared). الأعمدة بتوري الفرق لكل seed. كبّر الـ seed effect وشوف إن الفروق لسه ثابتة، وإن الـ t بيعتمد على نسبة الأثر لضوضاء الفروق بس.

صغّر عدد الـ seeds لـ 1: الـ p بيبقى None والحكم noise. وصغّر الأثر تحت الـ threshold: الحكم noise حتى لو الـ p صغير.

الـ p value بيرجع None لو n أقل من 2 (مفيش degrees of freedom ولا variance). ولو variance الفروق = 0: الـ p = 0 لو المتوسط مش صفر، و1 لو صفر.

الـ Verdict: جدول القرار

الـ evaluator بيشغّل ٣ حسابات مستقلة (normalise، improvement، paired t test) كلها pure functions من غير state مشترك، وبيجمعهم في الـ verdict path. نفس المدخلات = نفس الحكم دايمًا.

#الشرطالحكم

2|improvement| < improvement_thresholdnoise
3p_value is None أو أكبر من significance (0.05)noise

والـ Verdict بيشيل: hypothesis_id, metric, direction, scale, candidate_mean, baseline_mean, improvement, p_value, significance_threshold, improvement_threshold, verdict, rationale. الـ rationale جملة واحدة مقروءة الـ orchestrator يسجّلها قدام الـ hypothesis id.

خطوة ١: الـ dataclasses والـ ثوابت

import json, math
from dataclasses import dataclass
import numpy as np

HIGHER, LOWER = "higher_is_better", "lower_is_better"
LOG, LINEAR = "log", "linear"

@dataclass
class ExperimentResultLike:        # الجزء اللي الـ evaluator محتاجه من نتيجة الـ runner
    spec_id: str
    terminal: str
    metrics: dict

@dataclass
class MetricSpec:
    name: str
    direction: str = HIGHER
    scale: str = LINEAR
    def validate(self):
        if self.direction not in (HIGHER, LOWER): raise ValueError("bad direction")
        if self.scale not in (LINEAR, LOG): raise ValueError("bad scale")

class PairingError(ValueError):
    pass

خطوة ٢: الـ incomplete beta بـ Lentz

def _lentz_betacf(a, b, x, max_iter=200, eps=1e-12):
    qab, qap, qam = a + b, a + 1.0, a - 1.0
    c, d = 1.0, 1.0 - qab * x / qap
    if abs(d) < eps: d = eps
    d = 1.0 / d
    h = d
    for m in range(1, max_iter + 1):
        m2 = 2 * m
        aa = m * (b - m) * x / ((qam + m2) * (a + m2))     # الحد الزوجي
        d = 1.0 + aa * d
        if abs(d) < eps: d = eps
        c = 1.0 + aa / c
        if abs(c) < eps: c = eps
        d = 1.0 / d
        h *= d * c
        aa = -(a + m) * (qab + m) * x / ((a + m2) * (qap + m2))  # الحد الفردي
        d = 1.0 + aa * d
        if abs(d) < eps: d = eps
        c = 1.0 + aa / c
        if abs(c) < eps: c = eps
        d = 1.0 / d
        delta = d * c
        h *= delta
        if abs(delta - 1.0) < eps:                           # اتقارب
            return h
    return h

def regularised_incomplete_beta(a, b, x):
    if x < 0.0 or x > 1.0: raise ValueError("x out of [0, 1]")
    if x == 0.0: return 0.0
    if x == 1.0: return 1.0
    log_bt = (math.lgamma(a + b) - math.lgamma(a) - math.lgamma(b)
              + a * math.log(x) + b * math.log(1.0 - x))
    bt = math.exp(log_bt)
    if x < (a + 1.0) / (a + b + 2.0):                        # استخدم التماثل للاستقرار
        return bt * _lentz_betacf(a, b, x) / a
    return 1.0 - bt * _lentz_betacf(b, a, 1.0 - x) / b

خطوة ٣: الـ p value والـ paired t test

def two_sided_t_p_value(t_stat, df):
    if df <= 0: return 1.0
    x = df / (df + t_stat * t_stat)                          # تحويل t إلى x في [0,1]
    p = regularised_incomplete_beta(df / 2.0, 0.5, x)
    return max(0.0, min(1.0, p))

def paired_t_test(candidate, baseline):
    if len(candidate) != len(baseline):
        raise PairingError("candidate and baseline lengths disagree")
    n = len(candidate)
    if n < 2:                                                # مفيش df: p = None
        if n == 0: return 0.0, None, 0
        return float(candidate[0] - baseline[0]), None, n
    diffs = np.array(candidate) - np.array(baseline)
    mean_diff = float(diffs.mean())
    var_diff = float(diffs.var(ddof=1))                      # ddof=1 = n-1
    if var_diff == 0.0:
        return mean_diff, (0.0 if mean_diff != 0.0 else 1.0), n
    t_stat = mean_diff / math.sqrt(var_diff / n)
    return mean_diff, two_sided_t_p_value(t_stat, n - 1), n

خطوة ٤: الـ Pairing والـ improvement والـ log

def _pair_by_seed(candidates, baselines, metric):
    def to_map(results, who):
        m = {}
        for r in results:
            seed = r.metrics.get("seed")
            if seed is None: raise PairingError(f"{who} {r.spec_id} missing seed")
            seed = int(seed)
            if seed in m: raise PairingError(f"duplicate {who} seed {seed}")
            m[seed] = float(r.metrics[metric])
        return m
    cm, bm = to_map(candidates, "candidate"), to_map(baselines, "baseline")
    shared = sorted(set(cm) & set(bm))                       # بس الـ seeds المشتركة
    if not shared: raise PairingError("no shared seeds between candidate and baseline")
    return [cm[s] for s in shared], [bm[s] for s in shared]

def _improvement(cand_mean, base_mean, direction):
    denom = abs(base_mean) if base_mean != 0.0 else 1.0
    raw = (cand_mean - base_mean) / denom
    return -raw if direction == LOWER else raw                # lower is better: اقلب الإشارة

def _log_transform(values, scale):
    if scale != LOG: return list(values)
    out = []
    for v in values:
        if v <= 0.0: raise ValueError(f"log scale metric must be positive, got {v}")
        out.append(math.log(v))
    return out

خطوة ٥: الـ Evaluator والـ verdict path

@dataclass
class EvaluatorConfig:
    improvement_threshold: float = 0.02
    significance_threshold: float = 0.05

class Evaluator:
    def __init__(self, config=None):
        self._cfg = config or EvaluatorConfig()

    def evaluate(self, hypothesis_id, metric_spec, candidates, baselines):
        metric_spec.validate()
        bad = [r for r in [*candidates, *baselines] if r.terminal != "ok"]
        if bad:                                              # البوابة ١: failed
            return {"hypothesis_id": hypothesis_id, "verdict": "failed",
                    "rationale": f"runs failed with terminals {sorted({r.terminal for r in bad})}"}
        cand, base = _pair_by_seed(candidates, baselines, metric_spec.name)
        cand_t = _log_transform(cand, metric_spec.scale)
        base_t = _log_transform(base, metric_spec.scale)
        _, p_value, n = paired_t_test(cand_t, base_t)
        improvement = _improvement(float(np.mean(cand_t)), float(np.mean(base_t)),
                                   metric_spec.direction)
        verdict, why = self._verdict(improvement, p_value, n)
        return {"hypothesis_id": hypothesis_id, "metric": metric_spec.name,
                "improvement": round(improvement, 6),
                "p_value": None if p_value is None else round(p_value, 6),
                "verdict": verdict, "rationale": why}

    def _verdict(self, improvement, p_value, n):
        if abs(improvement) < self._cfg.improvement_threshold:        # البوابة ٢
            return "noise", f"improvement {improvement:.4f} is below threshold"
        if p_value is None:                                           # البوابة ٣
            return "noise", f"only {n} paired sample(s); cannot run significance test"
        if p_value > self._cfg.significance_threshold:
            return "noise", f"p value {p_value:.4f} exceeds significance threshold"
        if improvement > 0:
            return "improved", f"improvement {improvement:.4f} significant at p={p_value:.4f}"
        return "regressed", f"regression {improvement:.4f} significant at p={p_value:.4f}"

الأصل بيرجّع dataclass Verdict كامل بكل الحقول (بما فيهم candidate_mean وbaseline_mean من القيم الأصلية مش الـ log)، بس النسخة دي مختصرة. كمّلها لتطابق الأصل.

التمارين

الدرس مفيهوش تمارين مكتوبة؛ دي تمارين مبنية على الـ objectives والـ tests اللي الدرس بيغطيها.

  1. احسب بإيدك: perplexity من 32 لـ 28، lower is better وlog scale. إيه الـ improvement؟ يعدّي threshold 2%؟
    تلميح / إجابة(ln32 - ln28)/ln32 = (3.466 - 3.332)/3.466 ≈ 0.039. أكبر من 0.02، يعني يعدّي الـ gate الأولى. (القرار النهائي لسه بيعتمد على الـ p value.)
  2. شغّل الـ evaluator بـ seed واحد بس. إيه الـ verdict وليه؟
    تلميح / إجابةالـ p_value = None لأن n أقل من 2، فالحكم noise برسالة «only 1 paired sample(s)». (طبعًا لو الـ improvement كان تحت الـ threshold كان هيتقفل في البوابة ٢ الأول.)
  3. غيّر terminal في واحد من الـ baselines لـ "timeout". إيه اللي يحصل؟
    تلميح / إجابةالحكم failed برسالة فيها ['timeout']. لأن الكود بيفحص candidates وbaselines مع بعض، مش بيحاول يكمّل.
  4. اتنين results بـ seed نفسه في candidates، إيه اللي هيحصل؟ ولو الـ seeds مفيهاش أي تقاطع؟
    تلميح / إجابةالأولى: PairingError("duplicate candidate seed ..."). التانية: PairingError("no shared seeds between candidate and baseline"). والـ orchestrator المفروض يعيد التشغيل.
  5. ليه الـ threshold gate قبل الـ significance gate؟ اديني مثال بـ n كبير.
    تلميح / إجابةمع n ضخم حتى فرق 0.1% بيطلع p صغير جدًا. بس مفيد عمليًا؟ لأ. الـ threshold بيفلتر الفروق الصغيرة اللي مش هتتقاس في الواقع.
  6. تمرين إضافي مني (عملي): اكتب test بـ reference value معروفة للـ t distribution: لـ df = 9 والـ t = 2.262 الـ two-sided p لازم يكون حوالي 0.05. اتأكد من two_sided_t_p_value عندك.
    تلميح / إجابة
    assert abs(two_sided_t_p_value(2.262, 9) - 0.05) < 0.001
    الـ 2.262 هي القيمة الحرجة الشهيرة لـ df=9 عند 5%. لو الاختبار فشل، راجع الـ symmetry branch في regularised_incomplete_beta.
08

إضافة مني: اللي الدرس مقالهوش

الحدس: الـ p value مش بتقول «احتمال إن الفرضية صح». بتقول: لو مفيش تأثير حقيقي، قد إيه احتمال أشوف فرق بالحجم ده أو أكبر بالصدفة. والـ threshold بتاع الـ improvement بيجاوب سؤال تاني: هل الفرق كبير كفاية يهم؟ لازم الاتنين.
  • خطأ شائع ١: مقارنة متوسطين من غير pairing. ضوضاء الـ seeds بتغطي على التأثير الحقيقي. المعمل ٢ بيوريك ده.
  • خطأ شائع ٢: n صغير جدًا. مع ٢ أو ٣ seeds الـ t test ضعيف جدًا (df صغير). الدرس بيدّيك الأداة، بس قرار عدد الـ seeds عليك.
  • خطأ شائع ٣: اختبارات كتير. لو قيّمت ٢٠ hypothesis بـ 0.05 هيطلع واحدة «improved» بالصدفة في المتوسط. في loop حقيقي محتاج تصحيح (زي Bonferroni) أو threshold أشد. الدرس مبيعملهوش، فخلّي بالك.
  • الـ paired test بيفترض إن الفروق موزّعة تقريبًا طبيعي. ده مقبول للـ metrics الكبيرة، بس مش مضمون مع n صغير ومنحرف.
  • في الـ LLMs والـ agents: أي مقارنة prompt أو موديل على benchmark بدون seeds متعددة وpairing = ادّعاء ضعيف. نفس الفكرة بتظهر في الـ eval harnesses (دروس ٦٤ و٧٣ في نفس الـ phase) وفي الـ A/B testing للـ agents.

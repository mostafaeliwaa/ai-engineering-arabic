تسخين ٥ دقايق: افتكر امبارح (Debugging Neural Networks)

جاوب في دماغك الأول، وبعدين افتح الإجابة.

١. إيه هو اختبار «Overfit one batch» وبيكشف إيه؟

تاخد batch صغيرة (٨–٣٢ عينة) وتدرّب عليها ١٠٠+ iteration. الـ loss لازم ينزل لقرب الصفر والـ accuracy توصل ١٠٠٪. لو ده محصلش يبقى فيه bug أساسي: loss function بايظة، backward بايظ، optimizer مش متوصل بالـ parameters، أو الداتا والـ labels مش متطابقين.

٢. الـ loss بقى nan. اذكر ٣ أسباب محتملة.

learning rate عالي جدًا، log(0) في الـ cross-entropy (الحل: clamp بـ eps)، قسمة على صفر (std = 0)، أو overflow في exp() جوه الـ softmax (الحل: اطرح الـ max الأول).

٣. إزاي تعرف إن عندك dead ReLUs؟

اطبع نسبة الـ activations اللي بالظبط صفر بعد كل ReLU. لو أكتر من ٥٠٪ ميتة، جرّب LeakyReLU أو قلّل الـ learning rate.

الربط بالنهاردة: امبارح اتعلمت إن أصعب bugs هي اللي مش بتعمل crash. النهاردة هتشوف أشهر نوع فيها في الـ vision: صورة اتحملت غلط (uint8 بدل float، BGR بدل RGB، HWC بدل CHW) والموديل اشتغل عادي وطلّع زبالة.

المشكلة: كل مكتبة فاهمة «الصورة» بشكل مختلف

الكاميرا، والـ JPEG decoder، و PIL، و OpenCV، و torchvision، والـ CUDA kernel: كل واحد ليه ترتيب axes ومدى أرقام وترتيب channels. والمصيبة إن الغلط هنا مش بيرمي error:

  • • تدّي الموديل uint8 وهو مستني float32 ← بيشتغل عادي ويطلّع كلام فاضي.
  • • تدّيله BGR وهو متدرب على RGB ← الـ accuracy ممكن تقع حوالي ١٠ نقط.
  • • تدّيله channels-last وهو مستني channels-first ← أول conv layer هتتعامل مع الطول كأنه channel.

كل نظام vision في الـ production هو نفس السلسلة من الخطوات. لو خطوة واحدة غلط، الموديل بيشوف حاجة غير اللي اتدرب عليها:

File → Decode (uint8 HWC) → Colorspace (RGB) → Resize shorter side → Center crop → ÷255 → (x − mean)/std → HWC→CHW → Batch NCHW → Model
خد بالك: حوالي ٨٠٪ من الأعطال الصامتة بتبقى في خطوتين: نسيان الـ standardization (الطرح والقسمة)، والـ layout الغلط (HWC بدل CHW).

البيكسل عيّنة، مش مربع

الـ sensor في الكاميرا عبارة عن شبكة detectors صغيرة. كل detector بيعد الفوتونات اللي وقعت عليه لجزء من الثانية، ويطلّع voltage، والـ voltage ده بيتحول لرقم صحيح. detector واحد = pixel واحد.

زي ما تكون بتوصف لوحة لحد في التليفون: بدل ما توصف كل تفصيلة، بتقسمها مربعات وتقوله لون كل مربع رقمه كام. فيه قرارين هنا بيحددوا السقف لأي موديل بعد كده:

  • • Spatial sampling: كام detector في كل جزء من المشهد. قليل ← الحواف تبقى مسننة (aliasing). كتير ← التخزين والحساب ينفجروا.
  • • Intensity quantization: الـ voltage بيتقسم لكام درجة. 8 bits = ٢٥٦ مستوى، ده المعتاد للعرض. 10/12/16 bit بيدّوا تدرج أنعم ومهمين في الأشعة الطبية والـ HDR والـ raw.

البيكسل مش مربع ملوّن ليه مساحة؛ هو قياس واحد. لما تعمل resize أو rotate انت بتعمل resampling لشبكة القياسات دي.

جرب بإيدك: قلّل الـ sampling وشوف حواف الدايرة بقت سلالم. قلّل الـ bits لـ 2 أو 3 وشوف التدرج اتحول لخطوط (banding). مرّر الماوس على الصورة وشوف الـ RGB بتاع البيكسل.

ليه ٣ channels؟ وإيه حكاية HWC و CHW؟

الـ detector لوحده بيعد فوتونات من كل الطيف، ده grayscale. عشان الألوان، الـ sensor بيتغطى بموزاييك فلاتر أحمر وأخضر وأزرق. بعد الـ demosaicing كل مكان في الصورة بيبقى ليه ٣ أرقام: رد الـ detector الأحمر والأخضر والأزرق القريبين. دول الـ RGB triplet.

(R, G, B) = (210, 140, 30) ← برتقاني محمر H×W RGB image → shape (H, W, 3), uint8 ∈ [0, 255]

الـ ٣ مش رقم سحري: كاميرات العمق بتزود channel للـ Z، الأقمار الصناعية بتزود infrared و ultraviolet، الأشعة (X-ray، CT) غالبًا channel واحدة، والـ hyperspectral فيها channels كتير. الـ conv layers بتتعلم تخلط بين الـ channels دي.

نفس الأرقام، ترتيبين

HWC (height, width, channels): البيكسلز متخزنة متداخلة R G B | R G B. ده ترتيب PIL و OpenCV و matplotlib وتقريبًا كل ملفات الصور، لأنه بيطابق طريقة خروج السطور من الـ sensor.

CHW (channels, height, width): كل channel لوحة كاملة لوحدها. ده ترتيب PyTorch و cuDNN، لأن الـ conv kernel بيتزحلق على H و W، فلما كل channel تبقى لوحة متصلة في الميموري الحساب بيتعمل vectorize بسهولة.

تخيل علبة ألوان: HWC كأنك حاطط في كل خانة ٣ أقلام (أحمر وأخضر وأزرق) جنب بعض. CHW كأنك عامل ٣ أدراج: درج فيه كل الأحمر، ودرج للأخضر، ودرج للأزرق.

img_chw = img_hwc.transpose(2, 0, 1) # NumPy img_chw = img_hwc.permute(2, 0, 1) # PyTorch

Aspect ratio والـ Resize والـ Interpolation

كل موديل ليه input size ثابت (224×224 لأغلب classifiers بتوع ImageNet، و384 أو 512 لأجهزة الـ detection الحديثة)، وصورك نادرًا ما تبقى بالمقاس. عندك ٣ اختيارات:

  1. Resize للضلع الأصغر وبعدين center crop: وصفة ImageNet. بتحافظ على النسبة، وبترمي شريط من الأطراف.
  2. Resize وpad: بتحافظ على النسبة وكل البيكسلز، وبتزود شرايط سودا. المعتاد في الـ detection والـ OCR.
  3. Resize مباشر للمقاس: بيمط الصورة. رخيص، وبيبوّظ الهندسة، بس كويس لمهام classification كتير.

الـ interpolation هي القاعدة اللي بتقرر قيمة البيكسل الجديد لما الشبكة الجديدة متركبش على القديمة:

الطريقةالطبعاستخدمها في
Nearest neighbourالأسرع، مكعباتالاختيار الوحيد للـ masks والـ labels
Bilinearسريع وناعمالتدريب، الافتراضي
Bicubicأبطأ، أحدّ في التكبيرصور هتتفرج عليها

Nearest بتقرّب كل إحداثي جديد لأقرب بيكسل أصلي. Bilinear بتجيب الـ ٤ بيكسلز المحيطين وتخلطهم حسب المسافة. الكود في الدرس بيستخدم إحداثيات «endpoint-aligned» يعني أول وآخر بيكسل ثابتين.

خطوة ١: اعمل صورة صناعية وافحصها

صورة محسوبة بالمعادلات عشان تشتغل offline من غير ملفات. أول ما أي decoder يرجّعلك bytes بـ RGB، كل اللي جاي واحد.

import numpy as np

def synthetic_rgb(h=128, w=192, seed=0):
    rng = np.random.default_rng(seed)
    yy, xx = np.meshgrid(np.linspace(0, 1, h), np.linspace(0, 1, w), indexing="ij")
    r = (np.sin(xx * 6) * 0.5 + 0.5) * 255      # موجة حمرا أفقي
    g = yy * 255                                 # أخضر بيزيد لتحت
    b = (1 - yy) * xx * 255
    rgb = np.stack([r, g, b], axis=-1) + rng.normal(0, 6, (h, w, 3))   # شوية noise
    return np.clip(rgb, 0, 255).astype(np.uint8)  # زي أي صورة متفكوكة

arr = synthetic_rgb()
print(f"dtype:  {arr.dtype}")          # uint8
print(f"shape:  {arr.shape}")          # (H, W, C) = (128, 192, 3)
print(f"min/max: {arr.min()} {arr.max()}")
print(f"pixel at (0, 0): {arr[0, 0]}")

خطوة ٣: Grayscale و HSV

def rgb_to_grayscale(rgb):
    weights = np.array([0.299, 0.587, 0.114], dtype=np.float32)
    return (rgb.astype(np.float32) @ weights).astype(np.uint8)   # مجموع موزون

def rgb_to_hsv(rgb):
    rgb_f = rgb.astype(np.float32) / 255.0
    r, g, b = rgb_f[..., 0], rgb_f[..., 1], rgb_f[..., 2]
    cmax = np.max(rgb_f, axis=-1)
    cmin = np.min(rgb_f, axis=-1)
    delta = cmax - cmin

    h = np.zeros_like(cmax)
    mask = delta > 0                       # الرمادي ملوش hue
    argmax = np.argmax(rgb_f, axis=-1)     # مين القناة الأكبر؟
    rmax = mask & (argmax == 0)
    gmax = mask & (argmax == 1)
    bmax = mask & (argmax == 2)
    h[rmax] = ((g[rmax] - b[rmax]) / delta[rmax]) % 6
    h[gmax] = ((b[gmax] - r[gmax]) / delta[gmax]) + 2
    h[bmax] = ((r[bmax] - g[bmax]) / delta[bmax]) + 4
    h = h * 60.0                           # لدرجات

    s = np.divide(delta, cmax, out=np.zeros_like(delta), where=cmax > 0)
    v = cmax
    return np.stack([h, s, v], axis=-1)

gray = rgb_to_grayscale(arr)
hsv = rgb_to_hsv(arr)
print(gray.shape, hsv.shape)
print(f"hue: [{hsv[..., 0].min():.1f}, {hsv[..., 0].max():.1f}] deg")

خطوة ٤: Normalize و Standardize ورجوع

mean = np.array([0.485, 0.456, 0.406], dtype=np.float32)
std  = np.array([0.229, 0.224, 0.225], dtype=np.float32)

def preprocess_imagenet(rgb_uint8):
    x = rgb_uint8.astype(np.float32) / 255.0   # [0, 1]
    x = (x - mean) / std                        # broadcasting على آخر axis
    return x.transpose(2, 0, 1)                 # CHW

def deprocess_imagenet(chw_float32):
    x = chw_float32.transpose(1, 2, 0)          # رجّع HWC الأول
    x = x * std + mean
    return np.clip(x * 255.0, 0, 255).astype(np.uint8)

x = preprocess_imagenet(arr)
print(x.shape, x.dtype)                         # (3, 128, 192) float32
print(x.mean(axis=(1, 2)).round(3), x.std(axis=(1, 2)).round(3))
rt = deprocess_imagenet(x)
print(np.abs(rt.astype(int) - arr.astype(int)).max())   # 0 أو 1

خطوة ٥: Resize من الصفر

def resize_coordinates(source_length, target_length):
    if target_length == 1:
        return np.zeros(1, dtype=np.float32)
    return np.linspace(0, source_length - 1, target_length, dtype=np.float32)  # الأطراف ثابتة

def nearest_resize(image, th, tw):
    y = np.rint(resize_coordinates(image.shape[0], th)).astype(int)   # قرّب لأقرب بيكسل
    x = np.rint(resize_coordinates(image.shape[1], tw)).astype(int)
    return image[y[:, None], x[None, :]]

def bilinear_resize(image, th, tw):
    y = resize_coordinates(image.shape[0], th)
    x = resize_coordinates(image.shape[1], tw)
    y0 = np.floor(y).astype(int); x0 = np.floor(x).astype(int)
    y1 = np.minimum(y0 + 1, image.shape[0] - 1)
    x1 = np.minimum(x0 + 1, image.shape[1] - 1)
    wy = (y - y0)[:, None, None]; wx = (x - x0)[None, :, None]   # أوزان المسافة

    s = image.astype(np.float32)
    top = s[y0[:, None], x0[None, :]] * (1 - wx) + s[y0[:, None], x1[None, :]] * wx
    bottom = s[y1[:, None], x0[None, :]] * (1 - wx) + s[y1[:, None], x1[None, :]] * wx
    result = top * (1 - wy) + bottom * wy      # اخلط فوق وتحت
    return np.clip(np.rint(result), 0, 255).astype(image.dtype)

def local_roughness(x):                        # متوسط القفزات بين الجيران
    gy = np.diff(x.astype(float), axis=0)
    gx = np.diff(x.astype(float), axis=1)
    return float(np.abs(gy).mean() + np.abs(gx).mean())

th, tw = arr.shape[0] * 3, arr.shape[1] * 3
for name, out in [("nearest", nearest_resize(arr, th, tw)), ("bilinear", bilinear_resize(arr, th, tw))]:
    print(f"{name:>8}  shape={out.shape}  roughness={local_roughness(out):6.2f}")

المتوقع: nearest ليها أعلى roughness لأنها بتسيب الحواف حادة، والـ bilinear أنعم. ملف main.py بيزود كمان bicubic بـ Catmull-Rom kernel (٤ جيران لكل axis) من غير أي مكتبة صور.

خطوة ٦ (Use It): نفس الكلام بـ PyTorch

import torch
import torch.nn.functional as F

image_hwc = torch.from_numpy(synthetic_rgb(256, 320))
batch = image_hwc.permute(2, 0, 1).unsqueeze(0).float() / 255.0   # ١) float + NCHW

height, width = batch.shape[-2:]
scale = 256 / min(height, width)                                     # ٢) الضلع الأصغر = 256
rh, rw = round(height * scale), round(width * scale)
batch = F.interpolate(batch, size=(rh, rw), mode="bilinear",
                      align_corners=False, antialias=True)

top, left = (rh - 224) // 2, (rw - 224) // 2                         # ٣) center crop
batch = batch[:, :, top:top + 224, left:left + 224]

mean = torch.tensor([0.485, 0.456, 0.406]).view(1, 3, 1, 1)
std  = torch.tensor([0.229, 0.224, 0.225]).view(1, 3, 1, 1)
batch = (batch - mean) / std                                         # ٤) standardize

print(batch.dtype, tuple(batch.shape))   # torch.float32 (1, 3, 224, 224)
الترتيب مهم: float و NCHW ← resize الضلع الأصغر لـ 256 ← crop 224×224 ← اطرح الـ mean واقسم على الـ std. لو قلبت الترتيب، اللي بيوصل للموديل بيتغير من غير ما حد يحس.
08

التمارين

  1. (سهل) اعمل array 2×2 RGB uint8 فيها ٤ ألوان مختلفة. حوّل HWC ← CHW وارجع، واطبع الـ shapes، وأثبت إن كل القيم رجعت زي ما هي.
    تلميحa = np.array([[[255,0,0],[0,255,0]],[[0,0,255],[255,255,0]]], dtype=np.uint8) وبعدين c = a.transpose(2,0,1) و back = c.transpose(1,2,0) و np.array_equal(a, back) لازم True. شوف المعمل ٠٣ تاني لو اتلخبطت في الترتيب.
  2. (متوسط) اكتب standardize(img, mean, std) وعكسها، ويعدّوا اختبار roundtrip_max_diff <= 1 على أي صورة uint8. لازم يشتغلوا على صورة واحدة HWC وعلى batch بـ NCHW بنفس الـ call.
    تلميحالمشكلة كلها في الـ broadcasting: في HWC الـ channel آخر axis، في NCHW هو axis 1. حدد الـ axis بتاع الـ channel (مثلًا: لو img.ndim == 4 يبقى 1، غير كده -1) واعمل reshape للـ mean والـ std على الشكل ده: (1,3,1,1) أو (3,). في العكس اعمل np.rint قبل astype(np.uint8) عشان تفضل جوه فرق 1.
  3. (صعب) خد tensor بـ ٣ channels ومرّره على 1×1 conv بتخلط RGB لقناة رمادي واحدة. ابدأ الأوزان بـ [0.299, 0.587, 0.114]، جمّدها، وتأكد إن الناتج مطابق لـ rgb_to_grayscale بتاعتك في حدود الـ floating point. إيه تحويلات color space تانية ممكن تتكتب كـ 1×1 conv؟
    تلميح وإجابةconv = torch.nn.Conv2d(3, 1, kernel_size=1, bias=False) و conv.weight.data = torch.tensor([0.299,0.587,0.114]).view(1,3,1,1) و conv.weight.requires_grad_(False). قارن على صورة float قبل الـ standardization (أو اعمل deprocess الأول)، وخد بالك إن نسختك بتعمل truncate لـ uint8. أي تحويل خطي لكل بيكسل ينفع 1×1 conv: YCbCr (مصفوفة 3×3 + bias)، تبديل RGB↔BGR (مصفوفة permutation)، وحتى الـ standardization نفسها (أوزان على القطر = 1/std و bias = −mean/std). الـ HSV لأ، لأن فيها max و min وقسمة، يعني مش خطية.
  4. إضافة مني · Image tensor inspector: في الشغل الحقيقي أول حاجة بتعملها لما موديل vision يطلّع نتايج غريبة هي إنك تفحص الـ batch اللي داخل له. اكتب inspect_batch(x) ترجع: الـ dtype، الـ layout المتوقع (لو x.shape[1] == 3 غالبًا NCHW، لو آخر axis = 3 غالبًا NHWC)، المدى، وتحكم: raw أو normalized أو standardized. حطها كسطر أول في الـ dataloader بتاعك وشغّلها على batch واحد.
    تلميحuint8 أو max > 1.5 ← raw. min ≥ 0 و max ≤ 1 ← normalized. فيه قيم سالبة والمتوسط قريب من 0 ← standardized. ده نفس فكرة الـ skill اللي الدرس بيطلّعها في outputs/skill-image-tensor-inspector.md.

إضافة مني: اللي الدرس ما قالهوش صريح

أخطاء شائعة هتقابلها

  • • OpenCV بيقرا BGR: cv2.imread بيرجّع القنوات بالعكس. لازم cv2.cvtColor(img, cv2.COLOR_BGR2RGB) أو img[..., ::-1] قبل ما تدّيها لموديل متدرب على RGB.
  • • صور مش RGB أصلًا: PNG ممكن تبقى RGBA (٤ قنوات) أو grayscale (قناة واحدة). في PIL اعمل .convert("RGB") دايمًا قبل الـ preprocessing.
  • • Overflow في uint8: np.uint8(250) + np.uint8(10) بتلف وتطلع 4 مش 260. حوّل لـ float قبل أي حساب.
  • • Augmentation على الـ mask بـ bilinear: لو بتعمل resize أو rotate للصورة والـ mask، الصورة bilinear والـ mask nearest. نفس الغلطة اللي شفتها في المعمل ٠٦.
  • • stats غلط: مش كل الموديلات متدربة بأرقام ImageNet. اقرا الـ model card دايمًا؛ موديلات زي CLIP ليها mean و std مختلفين.

فين ده في الـ LLMs والـ Agents؟

الموديلات اللي بتشوف صور (Vision-Language Models) بتعدّي الصورة على vision encoder الأول، والـ encoder ده ليه preprocessing ثابت: مقاس معين وmean وstd معينين. في الـ ViT مثلًا الصورة 224×224 بتتقسم patches بحجم 16×16، يعني 14×14 = 196 patch، وكل patch بيبقى token. لو اديته صورة preprocessing بتاعها غلط، الـ tokens كلها بتبقى غلط والموديل «بيهلوس» في وصف الصورة. ولما agent بياخد screenshot ويحلله، نفس السلسلة دي هي اللي بتشتغل من ورا.

الحدس اللي تمسكه: الموديل ما بيشوفش «صورة»، بيشوف tensor بأرقام. شغلتك إن الـ tensor ده يبقى بنفس الشكل والمدى والترتيب اللي اتدرب عليه، بالظبط.

تسخين ٥ دقايق: فاكر الـ Cross-Attention؟

جاوب في دماغك الأول، وبعدين افتح الإجابة.

  1. في الـ cross-attention جوه الـ decoder، الـ Q جاية منين والـ K/V جايين منين؟
    الإجابةالـ Q من الـ text tokens، والـ K والـ V من الـ image tokens (الـ memory اللي طالعة من الـ vision encoder). النص «بيسأل» والصورة «بترد».
  2. ليه الـ self-attention بتاع النص عليه causal mask والـ cross-attention مالوش mask؟
    الإجابةالنص بيتولد كلمة كلمة، فممنوع التوكن يبص على اللي بعده. لكن الصورة كلها معروفة من الأول ومفيش ترتيب زمني بين الـ patches، فأي توكن نص يقدر يبص على أي patch.
  3. إيه اللي بيخلي توليد الكابشن سريع رغم إن الـ ViT تقيل؟
    الإجابةالـ KV cache بتاع الصورة: الـ keys والـ values بتوع الصورة بيتحسبوا مرة واحدة في الأول، وكل توكن نص جديد بيستخدمهم من غير ما يعيد الحساب. النهاردة الـ decoder ده نفسه هو اللي هيتدرّب بالـ LM loss.

المشكلة: موديل واحد محتاج مهارتين

أي vision-language model محتاج يعمل حاجتين:

  1. Ranking: تديله كابشن، يلاقي الصورة الصح وسط صور كتير.
  2. Generation: تديله صورة، يكتب كابشن ليها.

لو دربته على مهارة واحدة بس، معاك نص سيستم. CLIP ممتاز في الـ ranking بس مبيعرفش يكتب كابشن. والدرس بيقول إن GPT-4V بيكتب كابشن بس بيستخدم retrieval head منفصل للـ ranking. الحل: multi-objective pretraining، تدرّب على الاتنين في نفس الـ pass.

تشبيه: طالب بيذاكر لغة. تمرين «وصّل الصورة بالجملة» (matching) بيعلّمه يفرّق بين المعاني، وتمرين «اوصف الصورة بكلامك» (writing) بيعلّمه يعبّر. لو عمل واحد بس هيبقى ناقص. الاتنين مع بعض بيبنوا فهم مشترك في نفس الدماغ (هنا: نفس الـ encoder والـ projection).
batch → vision encoder → CLS pool + projection → image emb (N×D) captions → text encoder (mean pool) → text emb (N×D) image emb · text embᵀ → sim (N×N) → InfoNCE (الاتجاهين) encoder memory + captions → cross-attention decoder → LM cross-entropy total = contrastive + lm_weight · LM

InfoNCE في فقرة واحدة

عندك batch فيه N زوج (صورة، كابشن). رصّ الـ N image embeddings كصفوف، والـ N text embeddings كصفوف. اعمل لكل واحد L2-normalize (طوله يبقى 1). احسب المصفوفة:

S = (I · Tᵀ) / τ shape: (N × N)

القطر (S[i][i]) هو الأزواج الصح: الـ positives، وعددهم N. كل اللي برا القطر negatives، وعددهم N² − N = N(N−1). بعدين اعمل cross-entropy على كل صف والـ target هو القطر: الصف i لازم أعلى قيمة فيه تبقى في العمود i (صورة → نص). واعمل نفس الحكاية على الأعمدة (نص → صورة). الـ loss النهائي = متوسط الاتنين. دي CLIP loss في تمن سطور.

تشبيه: فكّر فيها كامتحان «اختيار من متعدد» لكل صورة: الاختيارات هي كل الكابشنز اللي في الـ batch، والإجابة الصح واحدة. الـ cross-entropy بيعاقبك لو اديت احتمال عالي لإجابة غلط. وعشان كده لو الموديل لسه بيخمّن عشوائي، الـ loss بيبقى ln(N): لـ batch 16 يعني ln(16) ≈ 2.77.

الـ Temperature مهمة

الـ τ بتتحكم في قد إيه الـ softmax «مدبّب». لو صغيرة جدًا (مثلًا τ = 0.01) الـ gradient بييجي تقريبًا من أصعب negative بس، والتدريب بيبقى noisy. لو كبيرة جدًا الـ softmax بيتفرد والـ gradient بيختفي. CLIP بيتعلّم τ كـ parameter، والديمو هنا بيعمل نفس الحاجة: بيخزّن log_tau ويستخدم exp(log_tau) كـ scale (يعني 1/τ)، وبيبدأ من 1/0.07 ≈ 14.3، ومحطوط عليه clamp بين 1e-3 و100.

الـ LM loss: الـ decoder بيتعلم يكتب

الـ decoder بياخد الـ image memory tokens عن طريق الـ cross-attention، ويتنبأ بالتوكن الجاي في كل موضع. الـ loss هو cross-entropy عادي والـ target هو التوكن اللي بعده. في الكود:

inputs = ids[:, :-1] targets = ids[:, 1:]

يعني الموضع t بياخد التوكنز لحد t ويحاول يتوقع التوكن t+1. والـ padding (التوكن رقم 0) بيتشال من الـ loss بـ ignore_index=PAD_ID. ليه؟ لأن الكابشنز أطوالها مختلفة وبنكمّلها بأصفار عشان تبقى نفس الطول. لو حسبنا عليها loss، الموديل هيتعلم «يتنبأ بالـ pad» ويتعاقب على حاجة مالهاش معنى.

الـ baseline: لو الموديل بيدي احتمال متساوي لكل الـ 512 كلمة في الـ vocab، الـ loss = ln(512) ≈ 6.24.

دمج اللوسين: مين بياخد gradient من مين؟

total = contrastive + lm_weight · lm (lm_weight غالبًا = 1.0)

اللوسين بيشاركوا الـ gradient في الـ encoder والـ projection. الـ decoder بياخد gradient من الـ LM loss بس. والـ text-side encoder (embedding + mean pool) بياخد من الـ contrastive بس. ده الـ multi-task recipe اللي CoCa وBLIP بيستخدموه بأوزان مختلفة. أما SigLIP فبيسيب الـ contrastive لوحده وبيبدّل الـ softmax بـ sigmoid pair loss.

خطوة ١: InfoNCE بالاتجاهين

import math
import torch
import torch.nn as nn
import torch.nn.functional as F

PAD_ID = 0

def info_nce_loss(image_emb, text_emb, log_tau):
    if image_emb.shape != text_emb.shape:          # لازم نفس (N, D)
        raise ValueError(f"shape mismatch {tuple(image_emb.shape)} vs {tuple(text_emb.shape)}")
    n = image_emb.shape[0]
    img_n = F.normalize(image_emb, dim=-1)         # طول 1 → الضرب = cosine
    txt_n = F.normalize(text_emb, dim=-1)

    scale = log_tau.exp().clamp(min=1e-3, max=100.0)   # scale = 1/τ
    sim = (img_n @ txt_n.T) * scale                # (N, N): صفوف صور، أعمدة نصوص

    targets = torch.arange(n, device=sim.device)   # الإجابة الصح = القطر
    loss_i2t = F.cross_entropy(sim, targets)       # صورة → نص
    loss_t2i = F.cross_entropy(sim.T, targets)     # نص → صورة
    return (loss_i2t + loss_t2i) * 0.5, sim

خطوة ٢: الـ LM loss مع الـ padding mask

def lm_loss(logits, target_ids, padding_id=PAD_ID):
    # logits: (B, L, V)   target_ids: (B, L)   الـ shift بيتعمل برا
    if logits.dim() != 3 or target_ids.dim() != 2:
        raise ValueError(f"logits must be 3D and targets 2D, got {logits.shape} {target_ids.shape}")
    b, l, v = logits.shape
    flat_logits = logits.reshape(b * l, v)
    flat_target = target_ids.reshape(b * l)
    return F.cross_entropy(flat_logits, flat_target, ignore_index=padding_id)   # الـ pad مش محسوب

خطوة ٣: text encoder صغير (embedding + mean pool)

class TextSideEncoder(nn.Module):
    def __init__(self, vocab_size, embed_dim):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, embed_dim, padding_idx=PAD_ID)

    def forward(self, ids):                        # ids: (B, L)
        x = self.embed(ids)                        # (B, L, D)
        mask = (ids != PAD_ID).float().unsqueeze(-1)
        denom = mask.sum(dim=1).clamp(min=1.0)     # عدد التوكنز الحقيقية
        return (x * mask).sum(dim=1) / denom       # متوسط من غير الـ pad → (B, D)

خطوة ٤: الـ forward بتاع الموديل كله

الموديل بيجمّع: ViT صغير من درس 59 (صورة 32×32، patch 16، hidden 128، depth 2، 4 heads)، والـ MLPProjector من درس 60، والـ text encoder، والـ VisionLanguageDecoder من درس 61 (vision_tokens = 4 patches + CLS = 5)، وparameter اسمه log_tau يبدأ من log(1/0.07).

    # جوه class MultimodalModel(nn.Module)
    def encode_image(self, images):
        tokens, cls = self.encoder(images)         # tokens = memory للـ decoder
        return tokens, self.projector(cls)         # CLS بعد الـ projection = image emb

    def forward(self, images, text_ids):
        memory, image_emb = self.encode_image(images)
        text_emb = self.text_encoder(text_ids)

        contrast, sim = info_nce_loss(image_emb, text_emb, self.log_tau)

        b, l = text_ids.shape
        inputs = text_ids[:, :-1]                  # اللي الـ decoder بيشوفه
        targets = text_ids[:, 1:]                  # اللي المفروض يتوقعه
        logits = self.decoder(inputs, memory)      # cross-attention على الصورة
        lm = lm_loss(logits, targets, padding_id=PAD_ID)

        diag = sim.diag().mean().item()            # متوسط الـ positives
        offdiag = (sim.sum() - sim.diag().sum()).item() / max(1, b * b - b)
        stats = {"diag": diag, "off_diag": offdiag, "tau": self.log_tau.exp().item()}
        return contrast, lm, stats

ملاحظة: الـ stats["tau"] بيطبع exp(log_tau)، يعني الـ scale. والكود الأصلي فيه شرط لو inputs فاضي يرجّع LM = 0.

خطوة ٥: الـ training loop

import numpy as np

def train(cfg):
    torch.manual_seed(cfg.seed)
    model = MultimodalModel(cfg).train()
    opt = torch.optim.Adam(model.parameters(), lr=cfg.lr)        # lr = 5e-4
    corpus = make_mock_corpus(cfg.seed + 1, cfg.n_pairs, cfg.text_vocab, cfg.max_text_len)
    rng = np.random.default_rng(cfg.seed + 2)

    for step in range(cfg.steps):                                # 50 step
        idx = rng.choice(len(corpus), size=cfg.batch_size, replace=False).tolist()
        imgs, ids = sample_batch(corpus, idx)                    # (16,3,32,32), (16,16)
        contrast, lm, stats = model(imgs, ids)
        total = contrast + cfg.lm_weight * lm                    # الدمج
        opt.zero_grad(set_to_none=True)
        total.backward()                                         # gradient لكل الـ stack
        opt.step()
        if step % 5 == 0 or step == cfg.steps - 1:
            print(f"step {step:3d} contrast {contrast.item():.4f} "
                  f"lm {lm.item():.4f} tau {stats['tau']:.3f}")

replace=False مهم: مينفعش نفس الزوج يتكرر في الـ batch، وإلا هيبقى positive وnegative في نفس الوقت. وعشان كده الكود بيرمي error لو الـ batch أكبر من الـ corpus.

التمارين

  1. SigLIP: بدّل InfoNCE بـ sigmoid pair loss وقارن سرعة النزول على الـ mock corpus.
    تلميحبدل softmax على الصف، كل خانة في S بقت مسألة binary لوحدها: label = +1 على القطر و−1 برا. الـ loss = −mean(logsigmoid(labels · (S·scale + bias))). ضيف bias كـ parameter (ورقة SigLIP بتبدأه بقيمة سالبة عشان أغلب الأزواج negatives). مفيش normalization على الصف كله، فكل زوج مستقل.
  2. Hard-negative mining: كل batch والتاني، خد أصعب زوج برا القطر من الـ batch اللي فات وضيفه. هل الـ contrastive بينزل أسرع؟
    تلميحالأصعب = أعلى قيمة برا القطر: sim.fill_diagonal_(-inf) على نسخة وبعدين argmax. خزّن الـ index بتاع الصورة والنص، وفي الـ batch الجاي ضيف الاتنين للـ indices (وخلي بالك متكررش نفس الزوج). قارن منحنيين الـ contrastive.
  3. Image-text matching head: ضيف head ثنائي (match / no match) فوق الـ joint embedding كلوس تالت، زي BLIP.
    تلميحخد concat(img_emb, txt_emb) لأزواج صح (القطر) وأزواج غلط (مثلًا shift الـ text بواحد)، وعديهم على nn.Linear(2D, 1) وBCE. الـ total = contrastive + lm + itm.
  4. Markov captions: بدّل الكابشنز العشوائية بسلاسل من Markov chain مصفوفة الانتقال بتاعتها بتعتمد على hash الصورة. المفروض الـ LM loss ينزل أكتر لأن فيه إشارة حقيقية تتعلمها.
    تلميحاعمل مثلًا 7 مصفوفات انتقال (واحدة لكل i % 7، نفس الـ bias اللي في الصورة)، وولّد كل توكن من صف التوكن اللي قبله. كده الـ decoder يقدر يعرف «أنهي مصفوفة» من الصورة.
  5. lm_weight = 0 ضد 1: درّب مرتين وقارن الـ contrastive. المفروض الـ LM ميبوظش الـ ranking.
    تلميحPretrainConfig(lm_weight=0.0) وبعدين 1.0، نفس الـ seed. ارسم history["contrast"] للاتنين. لو منحنى lm_weight=1 قريب أو أحسن، يبقى الـ multi-task مش بيضر.
  6. إضافة مني · Recall@K زي الشغل الحقيقي: في أي سيستم image search (أو multimodal RAG) المقياس الأساسي مش الـ loss، هو «هل الصورة الصح طلعت في أول K نتايج؟». اكتب دالة تاخد الـ sim وترجّع Recall@1 وRecall@5 للاتجاهين، واطبعها كل 10 steps.

إضافة مني: الحدس، الأخطاء الشائعة، وفين بيظهر

  • InfoNCE = classification بعدد classes = حجم الـ batch: كل صورة بتصنّف «أنهي كابشن من الـ N بتاعي». عشان كده الـ batch الأكبر = negatives أكتر = مهمة أصعب وإشارة أغنى. ورقة CLIP استخدمت batch ضخم جدًا (حوالي 32 ألف) لنفس السبب، وفي التدريب الموزع بيجمعوا الـ embeddings من كل الـ GPUs عشان يكبّروا عدد الـ negatives.
  • نسيان الـ normalize: من غير L2-normalize الموديل يقدر «يغش» ويكبّر طول المتجهات بدل ما يحسّن الاتجاه، والـ loss بيبقى مش مستقر. الـ normalize بيخلي الضرب = cosine similarity.
  • ليه log_tau مش tau مباشرة؟ عشان الـ exp دايمًا موجب، فالـ optimizer مستحيل يخلي الـ scale سالب. والـ clamp لحد 100 بيمنع الـ softmax يتدبّب لدرجة الـ overflow.
  • False negatives: لو فيه في الـ batch كابشنين بنفس المعنى («قطة على كنبة» مرتين)، InfoNCE هيعاقب الموديل على حاجة صح. في الداتا الحقيقية ده بيحصل، وده جزء من سبب إن SigLIP والـ dedup مهمين.
  • الـ pad والـ shift: أشهر bug صامت إنك تنسى الـ shift (الموديل يتعلم ينسخ التوكن الحالي فالـ loss ينزل بسرعة مريبة)، أو تنسى ignore_index (الـ loss يتحسن من مجرد توقع الأصفار).
  • في الـ LLMs والـ agents: الـ vision encoder اللي بيتدرب بالطريقة دي (زي CLIP/SigLIP) هو اللي بيتركّب قدام LLMs زي عيلة LLaVA. وفي agent بيدوّر في صور أو screenshots أو PDFs، الـ joint embedding ده هو اللي بيخليك تعمل search بالنص على الصور في الـ vector DB.

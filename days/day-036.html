المشكلة: آلاف الـ features وداتا قليلة

عايز تصنّف نصوص: إيميلات spam ولا لأ، reviews إيجابية ولا سلبية، tickets الدعم حسب النوع. عندك feature لكل كلمة (آلاف) وداتا تدريب محدودة. معظم الـ classifiers بتتخنق هنا:

  • • الـ Logistic Regression محتاجة عينات كفاية عشان تقدّر آلاف الـ weights بثقة.
  • • الـ Decision Trees بتقسم على كلمة واحدة كل مرة وبتعمل overfitting جامد.
  • • الـ KNN في 10,000 بُعد ملوش معنى، لأن كل النقط بتبقى بعيدة عن بعض تقريبًا بنفس المسافة.

الـ Naive Bayes بيتعامل مع ده. بيعمل فرضية غلط رياضيًا (إن كل feature مستقلة عن التانية بشرط معرفة الـ class)، ومع ذلك غالبًا بيكسب موديلات «أذكى» في تصنيف النصوص، خصوصًا بداتا قليلة. بيتدرب في لفة واحدة على الداتا، بيستحمل ملايين الـ features، وبيطلّع احتمالات (بس غالبًا مش متظبطة، هنرجعلها).

الدرس الأهم النهاردة: أحسن موديل مش هو «الأصح» نظريًا، هو اللي عنده أحسن bias-variance tradeoff للداتا اللي معاك. (فاكر Day 32؟)
02

نظرية Bayes بسرعة، والفرضية الساذجة

نظرية Bayes بتقلب الاحتمال الشرطي:

P(class | features) = P(features | class) · P(class) / P(features)
الجزءاسمهمعناه بالبلدي
P(class | features)Posteriorاللي عايزينه: احتمال إن الإيميل spam بعد ما شفنا كلماته
P(features | class)Likelihoodلو الإيميل spam، احتمال نشوف الكلمات دي قد إيه؟
P(class)Priorقبل ما نقرا حاجة: الـ spam منتشر قد إيه أصلًا؟
P(features)Evidenceنفسه لكل الـ classes، فبنتجاهله واحنا بنقارن

الـ class اللي ليها أعلى posterior هي اللي بتكسب.

ليه «Naive»؟

عشان تحسب P(features | class) بالظبط، محتاج التوزيع المشترك لكل الكلمات مع بعض. بـ vocabulary فيها 10,000 كلمة، ده توزيع على 210,000 توليفة. مستحيل.

الفرضية الساذجة: كل feature مستقلة بشرط معرفة الـ class:

P(w₁, w₂, …, wₙ | class) = P(w₁ | class) · P(w₂ | class) · … · P(wₙ | class)

بدل توزيع واحد مستحيل، بتقدّر n توزيعات بسيطة، كل واحد محتاج «عدّ» بس.

تشبيه: محقق بيقرا قضية. بدل ما يفكر في كل الأدلة مع بعض وعلاقاتها، بيدّي كل دليل نقطة لوحده (البصمة +٣ للمتهم الأول، الشاهد +١…) ويجمع. هو عارف إن الأدلة مرتبطة ببعض، بس الطريقة البسيطة بتوصّل للمتهم الصح في أغلب الأحوال.

الفرضية غلط بشكل واضح: كلمتين زي "machine" و"learning" مش مستقلين في أي document. بس الـ classifier مش محتاج احتمالات صح؛ محتاج ترتيب صح: مين الـ class الأعلى.

ليه بتشتغل؟ ٣ أسباب + سبب عملي

  1. الترتيب أهم من الـ calibration. لو قال P(spam) = 0.99999 والحقيقي 0.7، لسه اختار spam صح. احنا عايزين الكسبان الصح، مش الرقم الصح.
  2. High bias, low variance. فرضية الاستقلال قيد قوي بيمنع الـ overfitting. بداتا قليلة، موديل غلط شوية بس ثابت بيكسب موديل صح نظريًا بس متقلب.
  3. التكرار بيلغي نفسه. الـ features المرتبطة بتدي دليل مكرر، والـ NB بيعدّه مرتين، بس بيعدّه مرتين للـ class الصح كمان. لو "machine" و"learning" دايمًا مع بعض، الاتنين بيزقوا ناحية "tech".
  4. سريع جدًا. التدريب لفة واحدة بتعدّ تكرارات، والـ prediction ضرب مصفوفات. مليون document في ثواني، فتقدر تجرب features وتجارب أكتر.

الحساب خطوة بخطوة: مثال الـ spam

من الدرس: classين (spam وnot-spam) وvocabulary من ٣ كلمات. داتا التدريب:

freemoneymeetingالمجموعPrior
Spam8060101500.4
Not-spam5101001150.6

بـ Laplace smoothing (α = 1):

P(free | spam) = (80 + 1) / (150 + 3) = 81/153 = 0.529
P(free | not-spam) = (5 + 1) / (115 + 3) = 6/118 = 0.051

إيميل جديد فيه: "free" مرتين، "money" مرة، "meeting" صفر:

log P(spam | email) = log 0.4 + 2·log 0.529 + 1·log 0.399 + 0·log 0.072 = −3.109
log P(not-spam | email) = log 0.6 + 2·log 0.051 + 1·log 0.093 + 0·log 0.856 = −8.838

الـ spam كسب بفرق كبير؛ "free" مرتين دليل قوي. ولاحظ إن "meeting" الغايبة بتساهم بـ صفر في الاتنين (0 · log P): في الـ Multinomial NB الكلمات الغايبة ملهاش تأثير. الـ Bernoulli هو اللي بيحسب غياب الكلمة.

الـ log هنا طبيعي (ln). والأرقام دي «scores» قبل التطبيع، مش احتمالات حقيقية لأننا شلنا الـ evidence. عشان تحوّلها لاحتمال: exp لكل واحد وقسّم على المجموع.

معمل ١: آلة حاسبة للـ spam

القيم الافتراضية هي مثال الدرس بالظبط، لازم تطلع −3.109 و−8.838. بعدين العب:

  1. زوّد "meeting" في الإيميل وشوف الكفة بتتقلب إمتى.
  2. نزّل عدد "meeting" في تدريب الـ spam لـ 0، وخلّي α = 0، وحط "meeting" مرة واحدة في الإيميل. كلمة واحدة قتلت كل أدلة الـ spam.

تلات نسخ من الـ Naive Bayes

الفرق بينهم في طريقة نمذجة P(feature | class):

Multinomial: الـ feature عدد

P(wordᵢ | class) = (count of wordᵢ in class + α) / (total words in class + α · vocab_size)

ده الحصان الشغّال في تصنيف النصوص (word counts أو TF-IDF).

Gaussian: الـ feature رقم متصل

P(xᵢ | class) = 1/√(2π·var) · exp(−(xᵢ − mean)² / (2·var))

كل class ليها mean وvariance لكل feature. بيشتغل كويس لما الـ feature فعلًا شكلها bell curve جوه كل class (هتجربه في المعمل ٣).

Bernoulli: الـ feature موجودة ولا لأ

P(wordᵢ | class) = (docs in class containing wordᵢ + α) / (total docs in class + 2α)

عكس الـ Multinomial، الـ Bernoulli بيعاقب غياب الكلمة. لو "free" عادةً موجودة في الـ spam وغايبة من الإيميل ده، ده بيتحسب دليل ضد الـ spam. (ليه 2α؟ عشان فيه حالتين بس: موجودة أو مش موجودة.)

النسخةنوع الـ featureأحسن فيمثال
Multinomialcounts أو frequenciesتصنيف النصوص، bag-of-wordsspam الإيميل، تصنيف المواضيع
Gaussianقيم متصلةداتا tabular شبه normalIris، داتا sensors

Laplace Smoothing و الحساب في الـ log

مشكلة الصفر

كلمة ظهرت في الـ test وعمرها ما ظهرت في تدريب class معينة؟ من غير smoothing: P(word | class) = 0/N = 0. صفر واحد مضروب في الحاصل كله بيخلّي P(class | features) = 0 مهما كانت باقي الأدلة. كلمة واحدة بتهد الـ prediction كله (جربتها في المعمل ١).

الـ Laplace smoothing بيزوّد عدد صغير α (عادة 1) لكل كلمة:

P(wordᵢ | class) = (count(wordᵢ, class) + α) / (total_words_in_class + α · vocab_size)

بـ α = 1 كل كلمة بتاخد احتمال صغير. كلمة غريبة زي "discombobulate" مبقتش تقتل احتمال الـ spam. وليها تفسير Bayesian: كأنك حاطط uniform Dirichlet prior على توزيع الكلمات (يعني قبل ما تشوف داتا، بتفترض كل الكلمات ليها فرصة).

Alphaالتأثيرإمتى
0.001smoothing تقريبًا صفر، صدّق الداتاداتا تدريب ضخمة ومش متوقع كلمات جديدة
0.1smoothing خفيفداتا كبيرة
1.0Laplace القياسينقطة البداية
10.0smoothing تقيل، التوزيعات بتتسطحداتا صغيرة جدًا وكلمات جديدة كتير

α hyperparameter بتظبطه (بطرق Day 34). كبيرة أوي = كل الكلمات شبه بعض والموديل نسي اللي اتعلمه.

الـ Underflow: الكمبيوتر بيقول صفر وهو مش صفر

ضرب مئات الاحتمالات (كل واحد أقل من 1) بيعمل floating-point underflow: الحاصل بيبقى صفر في الكمبيوتر رغم إن قيمته الحقيقية رقم موجب صغير جدًا. الـ float64 مبيقدرش يمثل أصغر من حوالي 5e-324.

الحل: اشتغل في الـ log. بدل ما تضرب احتمالات، اجمع الـ logs:

log P(class | x) = log P(class) + Σᵢ log P(xᵢ | class)

وده بيحوّل الـ prediction لـ dot product:

log_scores = X @ log_feature_probs.T + log_class_priors
prediction = argmax(log_scores)

ضرب مصفوفات. وده سبب سرعة الـ NB: نفس عملية linear model بـ layer واحدة.

معمل ٢: امتى الحاصل يبقى صفر؟

كل كلمة احتمالها p. بنضرب في JavaScript (float64، نفس numpy) كلمة ورا كلمة، وجنبه بنجمع الـ logs.

Gaussian NB بعينك، وإمتى الـ NB يفشل

في الـ Gaussian NB كل class بتتعلم mean وvariance لكل محور لوحده. يعني شكل كل class «بيضاوي» على المحاور (axis-aligned)، ومش بيقدر يتميّل، لأن الميل معناه إن المحورين مرتبطين، وده عكس فرضية الاستقلال.

الـ NB بيفشل لما الفرضية تبوّظ الترتيب نفسه، مش بس الاحتمالات:

  1. Feature interactions قوية: لو الـ class بتعتمد على توليفة featureين ومش على كل واحدة لوحدها (زي XOR)، الـ NB مش هيشوفها خالص: كل feature لوحدها مفيهاش دليل، والـ NB مبيعرفش يجمعهم non-linearly.
  2. Features مرتبطة جدًا بأدلة متعاكسة: لو A بتقول spam وB بتقول not-spam، وهما في الحقيقة دايمًا متفقين، الـ NB هيشوف تعارض مش موجود.
  3. داتا تدريب ضخمة جدًا: الموديلات الـ discriminative بتتعلم الحد الحقيقي وبتكسب؛ الفرضية اللي ساعدت مع الداتا القليلة بقت قيد.

عمليًا الحالات دي نادرة في النصوص: الـ features كتير وكل واحدة ضعيفة، والأخطاء بتلغي بعض. بس في داتا tabular فيها features قليلة ومرتبطة جامد، جرّب logistic regression أو الأشجار الأول.

جرّب: اختار class واضغط على الـ canvas تحط نقط. بعدين جرّب preset «XOR» وشوف الـ accuracy بتقع لحوالي 50%، وpreset «مايلين» وبص على البيضاوي اللي مش راضي يتميّل.

خطوة ١: MultinomialNB.fit = عدّ + smoothing + log

import numpy as np

class MultinomialNB:
    def __init__(self, alpha=1.0):
        self.alpha = alpha
        self.classes_ = None
        self.class_log_prior_ = None
        self.feature_log_prob_ = None

    def fit(self, X, y):
        if np.any(X < 0):                                 # counts مينفعش تبقى سالبة
            raise ValueError("MultinomialNB requires non-negative feature values")
        self.classes_ = np.unique(y)
        n_classes, n_features = len(self.classes_), X.shape[1]
        self.class_log_prior_ = np.zeros(n_classes)
        self.feature_log_prob_ = np.zeros((n_classes, n_features))

        for i, c in enumerate(self.classes_):
            X_c = X[y == c]
            self.class_log_prior_[i] = np.log(X_c.shape[0] / X.shape[0])   # log prior
            counts = X_c.sum(axis=0) + self.alpha                         # عدّ كل كلمة + α
            self.feature_log_prob_[i] = np.log(counts / counts.sum())     # المقام = total + α·V
        return self

لاحظ: counts.sum() بعد إضافة α لكل كلمة = total + α · vocab_size، نفس المعادلة بالظبط.

خطوة ٢: الـ prediction = ضرب مصفوفات

    def predict_log_proba(self, X):
        return X @ self.feature_log_prob_.T + self.class_log_prior_   # (n,d)@(d,k) + (k,)

    def predict_proba(self, X):
        log_proba = self.predict_log_proba(X)
        log_proba -= log_proba.max(axis=1, keepdims=True)   # اطرح الأكبر قبل exp عشان مايحصلش underflow
        proba = np.exp(log_proba)
        proba /= proba.sum(axis=1, keepdims=True)           # طبّع لمجموع 1
        return proba

    def predict(self, X):
        return self.classes_[np.argmax(self.predict_log_proba(X), axis=1)]

    def score(self, X, y):
        return np.mean(self.predict(X) == y)

سطر log_proba -= max مهم: لو الـ scores كانت −1000 و−1002، الـ exp المباشر هيطلع صفرين. لما تطرح الأكبر بتبقى 0 و−2، والنسبة بينهم ما اتغيرتش. اسمها log-sum-exp trick وهتقابلها في الـ softmax بتاع كل LLM.

خطوة ٣: GaussianNB

class GaussianNB:
    def __init__(self, var_smoothing=1e-9):
        self.var_smoothing = var_smoothing

    def fit(self, X, y):
        self.classes_ = np.unique(y)
        k, d = len(self.classes_), X.shape[1]
        self.means_, self.vars_, self.priors_ = np.zeros((k, d)), np.zeros((k, d)), np.zeros(k)
        for i, c in enumerate(self.classes_):
            X_c = X[y == c]
            self.means_[i] = X_c.mean(axis=0)
            self.vars_[i] = X_c.var(axis=0) + self.var_smoothing   # متقسمش على صفر
            self.priors_[i] = X_c.shape[0] / X.shape[0]
        return self

    def _log_likelihood(self, X):
        log_proba = np.zeros((X.shape[0], len(self.classes_)))
        for i in range(len(self.classes_)):
            diff = X - self.means_[i]
            log_pdf = -0.5 * np.log(2 * np.pi * self.vars_[i]) - 0.5 * diff**2 / self.vars_[i]
            log_proba[:, i] = log_pdf.sum(axis=1) + np.log(self.priors_[i])   # جمع = ضرب مستقل
        return log_proba

    def predict(self, X):
        return self.classes_[np.argmax(self._log_likelihood(X), axis=1)]

from sklearn.naive_bayes import GaussianNB, MultinomialNB, BernoulliNB
from sklearn.feature_extraction.text import CountVectorizer, TfidfVectorizer
from sklearn.pipeline import Pipeline
from sklearn.calibration import CalibratedClassifierCV

# نصوص: عدّ الكلمات + Multinomial
text_clf = Pipeline([
    ("vectorizer", CountVectorizer()),
    ("classifier", MultinomialNB(alpha=1.0)),
])
text_clf.fit(train_texts, train_labels)
print(text_clf.score(test_texts, test_labels))

# TF-IDF + Multinomial: من أقوى الـ baselines
tfidf_clf = Pipeline([("tfidf", TfidfVectorizer()), ("classifier", MultinomialNB(alpha=0.1))])

# نصوص قصيرة (SMS، tweets): Bernoulli مع binary=True
short_clf = Pipeline([("vectorizer", CountVectorizer(binary=True)), ("classifier", BernoulliNB(alpha=1.0))])

# محتاج احتمالات تعتمد عليها؟ calibrate
calibrated_nb = CalibratedClassifierCV(MultinomialNB(), cv=5, method="sigmoid")
calibrated_nb.fit(X_train, y_train)
proba = calibrated_nb.predict_proba(X_test)
  • • TF-IDF: الـ counts الخام بتدي كل كلمة نفس الوزن، و"the" و"is" موجودين في كل class ومفيهمش معلومة. الـ TF-IDF بيقلل وزن الكلمات الشائعة ويرفع النادرة المميِّزة. قيمه موجبة فبتشتغل مع الـ Multinomial، والتوليفة دي غالبًا بتكسب موديلات أعقد على داتا أقل من 10,000 عينة.
  • • Bernoulli للنص القصير: الـ counts في الرسايل القصيرة noisy، فالـ presence/absence أوثق. binary=True بيحوّل الـ counts لـ 0/1؛ من غيره الـ Bernoulli بيشوف counts مش متصمم ليها.
  • • Calibration: لما الـ NB يقول 0.95، الحقيقي ممكن يكون 0.7. CalibratedClassifierCV بيدرّب logistic regression فوق scores الـ NB بالـ CV، والاحتمالات بتقرب من الحقيقة. مهم لو هتحط threshold أو تجمع مع موديلات تانية.

Gotchas

  1. قيم سالبة: الـ MultinomialNB محتاج قيم موجبة. features standardized؟ استخدم GaussianNB أو حرّك القيم لفوق.
  2. Variance صفر: لو feature كلها نفس القيمة جوه class، الـ Gaussian بيقسم على صفر. علشان كده الـ 1e-9.
  3. Class imbalance: لو 99% مش spam، الـ prior 0.99 ممكن يغطي على الأدلة. تقدر تحدد الـ priors بإيدك (class_prior في sklearn).
  4. Feature scaling: الاتنين مش محتاجينه (counts، أو إحصائيات لكل feature). ميزة على الـ LR والـ SVM.

التمارين

  1. تجربة الـ smoothing: درّب بـ α = 0.01، 0.1، 1، 10، 100 وارسم accuracy ضد α. الذروة فين؟ وليه α الكبيرة جدًا بتأذي؟
    تلميحاستخدم make_text_data وnp.logspace(-2, 2, 5). α كبيرة جدًا بتغرق الـ counts الحقيقية: لو كلمة اتكررت 5 مرات وα=100، كل الكلمات بقت شبه بعض والموديل بيقرب من «اختار حسب الـ prior».
  2. اختبار الاستقلال: خد كلمتين مرتبطين ("machine" و"learning") واحسب P(w₁|c)·P(w₂|c) وقارنه بـ P(w₁ AND w₂|c). الفرضية غلط قد إيه؟ وده أثّر على الـ accuracy؟
    تلميحاحسبها على مستوى الـ documents (نسبة الـ docs اللي فيها الكلمة). غالبًا الحقيقي أكبر بكتير من الحاصل، يعني الفرضية غلط جامد، ومع ذلك الـ accuracy ممكن متتأثرش. ده بالظبط «الترتيب أهم من الـ calibration».
  3. BernoulliNB من الصفر: حوّل الـ counts لـ binary وقارن بالـ Multinomial. إمتى الـ Bernoulli يكسب؟
    تلميحp = ((X_c > 0).sum(0) + α) / (n_c + 2α). والـ score: X_bin @ log(p).T + (1 - X_bin) @ log(1 - p).T + log_prior. الجزء التاني ده هو «عقاب الغياب». غالبًا بيكسب في الـ documents القصيرة.
  4. NB ضد LR: درّب الاتنين من 100 لـ 10,000 عينة وارسم الـ accuracy. LR بيعدّي NB إمتى؟
    تلميحmake_text_data(n_samples=12000) وخلّي آخر 2000 test ثابت. استخدم sklearn.linear_model.LogisticRegression(max_iter=1000). توقع إن NB يبدأ أعلى وLR يلحقه ويعديه مع الداتا الكبيرة (أو يقربوا من بعض لو الداتا الصناعية قريبة من فرضية NB، لأن الكلمات هنا متولدة مستقلة فعلًا).
  5. Spam filter كامل: tokenize، vocabulary، bag-of-words، MultinomialNB، وقيّم بـ precision وrecall مش accuracy بس. ليه؟
    الإجابةلو 90% من الإيميلات مش spam، موديل بيقول «مش spam» دايمًا accuracy بتاعته 90% وهو عديم الفايدة. والغلطتين مش بنفس التمن: إيميل شغل مهم راح الـ spam (false positive) أوحش بكتير من spam عدّى. فبتبص على precision الـ spam بالذات (Day 31).
  6. إضافة مني · router رخيص قبل الـ LLM: اكتب ٣٠ رسالة دعم قصيرة بإيدك بـ ٣ labels (billing، bug، other). درّب TfidfVectorizer + MultinomialNB في Pipeline. لكل رسالة جديدة: لو أعلى احتمال (بعد CalibratedClassifierCV) فوق threshold، وجّهها للفريق مباشرة؛ لو أقل، ابعتها لـ LLM يصنّفها. احسب كام رسالة وفّرت عليها نداء LLM.
    تلميحمع ٣٠ رسالة بس استخدم cv=3 في الـ calibration. جرّب thresholds 0.6 و0.8 و0.9 وشوف الـ tradeoff بين التوفير والغلط. ده pattern حقيقي: موديل صغير سريع قدام موديل كبير غالي.

إضافة مني: اللي الدرس مقالوش صريح

الـ NB هو linear model متنكر

في حالة classين، القرار هو: هل log P(spam|x) − log P(ham|x) > 0؟ ده بيطلع Σ xᵢ · log(P(wᵢ|spam)/P(wᵢ|ham)) + log(prior ratio): مجموع موزون للـ counts + bias، يعني نفس شكل الـ logistic regression بالظبط. الفرق الوحيد إن الـ weights جاية من «عدّ» مش من optimization. علشان كده الجدول قال «الاتنين linear classifiers».

أخطاء بتحصل كتير

  • • GaussianNB على word counts: الـ counts مش bell curve (أغلبها أصفار). استخدم Multinomial.
  • • تستخدم predict_proba بتاع NB كأنه ثقة حقيقية وتحط عليه threshold من غير calibration.
  • • تبني الـ vocabulary على كل النصوص قبل التقسيم (leakage امبارح بالظبط). خلي CountVectorizer جوه الـ Pipeline.
  • • تنسى إن الـ Multinomial بيتجاهل الكلمات الغايبة، وتستغرب ليه الإيميل القصير «ملوش رأي».

بيظهر فين في الـ LLMs والـ Agents؟

  • • الـ log-probs: احتمال جملة كاملة من LLM = حاصل ضرب احتمالات الـ tokens، وفي الممارسة بيتحسب مجموع log-probs لنفس سبب المعمل ٢. لما API يرجعلك logprobs، ده هو.
  • • log-sum-exp اللي في predict_proba هو نفس الحيلة اللي جوه الـ softmax في كل Transformer.
  • • Smoothing: الـ n-gram language models القديمة كانت بتواجه نفس مشكلة «الكلمة اللي ما اتشافتش = صفر» وبتحلها بنفس فكرة الـ Laplace.
  • • Routers وguardrails: classifier صغير (NB أو LR على TF-IDF) قدام الـ LLM بيفلتر spam أو بيوجّه الطلب، بتكلفة شبه صفر (تمرين ٦).

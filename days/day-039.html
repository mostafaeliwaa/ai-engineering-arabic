ليه الـ accuracy بتفشل؟

لما 0.1% بس من المعاملات fraud، الموديل بيكتشف إن أرخص حل يقول «مش fraud» على طول. ده مش bug، ده التصرف «العقلاني» لو هدفك تقلل عدد الأخطاء. صح تقنيًا وملوش أي فايدة.

وده بيحصل في كل حتة الـ classification فيها مهم: تشخيص أمراض (حوالي 1% positive)، اختراق شبكات (0.01%)، عيوب تصنيع (0.5%)، spam (20%)، churn (5%). وكل ما الـ class أهم، غالبًا بتبقى أندر.

المشكلة إن الـ accuracy بتعامل كل إجابة صح زي التانية: إنك تقول على معاملة سليمة إنها سليمة، وإنك تلقط fraud، الاتنين بنقطة واحدة. بس لقط الـ fraud هو السبب الوحيد إن الموديل موجود.

مثال: 1000 عينة، 990 negative و10 positive، والموديل بيقول negative دايمًا:

Predicted +Predicted −
Actually +0 (TP)10 (FN)
Actually −0 (FP)990 (TN)
Accuracy = (0 + 990) / 1000 = 99.0% ← وهو ما لقطش ولا حالة

غيّر الداتا: Oversampling وUndersampling وSMOTE

أول عيلة من الحلول بتغيّر الداتا نفسها عشان الـ classes تبقى متوازنة قبل التدريب.

Random Oversampling

كرّر عينات الـ minority لحد ما عددها يساوي الـ majority. بسيط ومفيش معلومة ضاعت، بس الموديل بيشوف نفس النقطة بالظبط مرات كتير، فممكن يحفظها (overfitting)، والتدريب بيطول.

Random Undersampling

شيل عينات من الـ majority لحد ما عددها يساوي الـ minority. سريع وبسيط، بس بترمي داتا ممكن تكون مفيدة، والنتايج بتبقى أكتر تذبذبًا (variance أعلى).

SMOTE: نقط جديدة مش نسخ

الـ Synthetic Minority Oversampling Technique بيعمل نقط minority جديدة معقولة بدل ما ينسخ:

  1. لكل نقطة minority x، هات أقرب k جيران ليها من الـ minority بس.
  2. اختار جار منهم عشوائيًا.
  3. اعمل نقطة جديدة في مكان عشوائي على الخط اللي بينهم.
new_sample = x + random(0, 1) · (neighbor − x)

مثال من الدرس: x1 = (1.0, 2.0) وجارها x2 = (1.5, 2.5) وt = 0.4، فالنقطة الجديدة x1 + 0.4·(0.5, 0.5) = (1.2, 2.2). يعني بنملا المنطقة اللي الـ minority عايشة فيها بنقط جديدة من غير ما ننسخ.

عيوبه: ممكن يعمل نقط فيها noise جنب حدود القرار (لو جار الـ minority بعيد ووسطهم majority)، ومش بيبص على توزيع الـ majority خالص.

غيّر الموديل: Class Weights والـ Threshold والتكلفة

Class Weights

بدل ما تلعب في الداتا، غيّر تمن الغلطة. الغلط في الـ minority يتحسب أغلى. الوزن لكل class:

weight(class) = n_samples / (n_classes · n_class)

لو عندك 950 negative و50 positive: وزن الـ negative = 1000 / (2·950) = 0.526، ووزن الـ positive = 1000 / (2·50) = 10.0. يعني الـ positive واخد 19 ضعف، وغلطة واحدة فيه بتوجع زي 19 غلطة في الـ negative.

في الـ logistic regression، ده بيعدّل الـ loss:

weighted_loss = −Σ wᵢ · [ yᵢ·log(pᵢ) + (1−yᵢ)·log(1−pᵢ) ]

الـ class weights بتساوي الـ oversampling في المتوسط (in expectation)، بس من غير ما تعمل نقط جديدة، فهي أسرع ومفيهاش خطر الـ overfitting على نسخ مكررة.

Threshold Tuning

معظم الـ classifiers بتطلّع احتمال، والـ threshold الافتراضي 0.5. بس 0.5 رقم اعتباطي، ومع الـ imbalance الـ threshold الأحسن غالبًا أقل بكتير. الخطوات:

  1. درّب الموديل.
  2. هات الاحتمالات على الـ validation set (مش الـ test).
  3. جرّب thresholds من 0 لـ 1.
  4. احسب الـ F1 (أو المقياس اللي يهمك) عند كل واحد.
  5. اختار الأحسن واستخدمه في الـ production.

موديل ممكن يدّي معاملة fraud احتمال 0.15. عند 0.5 هتعدّي. عند 0.10 هتتمسك. المهم هو الترتيب أكتر من دقة الاحتمال نفسه: طالما الـ fraud واخد احتمالات أعلى من السليم، فيه threshold بيفصلهم.

Cost-Sensitive Learning

تعميم للـ class weights: بدل وزن واحد لكل class، حط تكلفة لكل نوع غلطة:

Predict +Predict −
Actually +0 (صح)C_FN = 100
Actually −C_FP = 10 (صح)

تفويت fraud أغلى 100 مرة من إنذار كداب، والموديل بيقلل التكلفة الكلية مش عدد الأخطاء. ده أكتر طريقة منطقية لو تقدر تقدّر التكاليف الحقيقية: تفويت تشخيص سرطان غير إنذار كداب بيودّي لعينة زيادة. لما تكتب التكاليف صريحة، القرار بيبقى صح.

import numpy as np

def make_imbalanced_data(n_majority=950, n_minority=50, seed=42):
    rng = np.random.RandomState(seed)
    X_maj = rng.randn(n_majority, 2) * 1.0 + np.array([0.0, 0.0])    # الأغلبية حوالين الصفر
    X_min = rng.randn(n_minority, 2) * 0.8 + np.array([2.5, 2.5])    # الأقلية حوالين (2.5, 2.5)
    X = np.vstack([X_maj, X_min])
    y = np.concatenate([np.zeros(n_majority), np.ones(n_minority)])
    shuffle_idx = rng.permutation(len(y))
    return X[shuffle_idx], y[shuffle_idx]

خطوة ٢: SMOTE من الصفر

def euclidean_distance(a, b):
    return np.sqrt(np.sum((a - b) ** 2))


def find_k_neighbors(X, idx, k):
    distances = []
    for i in range(len(X)):
        if i == idx:                     # النقطة مش جارة نفسها
            continue
        d = euclidean_distance(X[idx], X[i])
        distances.append((i, d))
    distances.sort(key=lambda x: x[1])
    return [d[0] for d in distances[:k]]


def smote(X_minority, k=5, n_synthetic=100, seed=42):
    rng = np.random.RandomState(seed)
    n_samples = len(X_minority)
    k = min(k, n_samples - 1)
    if k < 1:
        raise ValueError("SMOTE requires at least 2 minority samples")
    synthetic = []
    for _ in range(n_synthetic):
        idx = rng.randint(0, n_samples)                      # نقطة minority عشوائية
        neighbors = find_k_neighbors(X_minority, idx, k)     # جيرانها من الـ minority بس
        neighbor_idx = neighbors[rng.randint(0, len(neighbors))]
        t = rng.random()                                     # مكان عشوائي على الخط
        new_point = X_minority[idx] + t * (X_minority[neighbor_idx] - X_minority[idx])
        synthetic.append(new_point)
    return np.array(synthetic)

خطوة ٣: Random over/under sampling

def random_oversample(X, y, seed=42):
    rng = np.random.RandomState(seed)
    classes, counts = np.unique(y, return_counts=True)
    max_count = counts.max()
    X_resampled = list(X)
    y_resampled = list(y)
    for cls, count in zip(classes, counts):
        if count < max_count:
            cls_indices = np.where(y == cls)[0]
            n_needed = max_count - count
            chosen = rng.choice(cls_indices, size=n_needed, replace=True)   # نسخ مع تكرار
            X_resampled.extend(X[chosen])
            y_resampled.extend(y[chosen])
    X_out = np.array(X_resampled)
    y_out = np.array(y_resampled)
    shuffle = rng.permutation(len(y_out))
    return X_out[shuffle], y_out[shuffle]


def random_undersample(X, y, seed=42):
    rng = np.random.RandomState(seed)
    classes, counts = np.unique(y, return_counts=True)
    min_count = counts.min()
    X_resampled = []
    y_resampled = []
    for cls in classes:
        cls_indices = np.where(y == cls)[0]
        chosen = rng.choice(cls_indices, size=min_count, replace=False)   # خد min_count بس من كل class
        X_resampled.extend(X[chosen])
        y_resampled.extend(y[chosen])
    X_out = np.array(X_resampled)
    y_out = np.array(y_resampled)
    shuffle = rng.permutation(len(y_out))
    return X_out[shuffle], y_out[shuffle]

خطوة ٤: Logistic regression بأوزان

def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-np.clip(z, -500, 500)))


def logistic_regression_weighted(X, y, weights, lr=0.01, epochs=200):
    n_samples, n_features = X.shape
    w = np.zeros(n_features)
    b = 0.0
    for _ in range(epochs):
        z = X @ w + b
        pred = sigmoid(z)
        error = pred - y
        weighted_error = error * weights          # غلطة الـ minority بتتضرب في وزن أكبر
        gradient_w = (X.T @ weighted_error) / n_samples
        gradient_b = np.mean(weighted_error)
        w -= lr * gradient_w
        b -= lr * gradient_b
    return w, b


def compute_class_weights(y):
    classes, counts = np.unique(y, return_counts=True)
    n_samples = len(y)
    n_classes = len(classes)
    weight_map = {}
    for cls, count in zip(classes, counts):
        weight_map[cls] = n_samples / (n_classes * count)
    return np.array([weight_map[yi] for yi in y])    # وزن لكل عينة


def class_weighted_loss(y_true, y_pred_probs, weights):
    eps = 1e-15
    y_pred_probs = np.clip(y_pred_probs, eps, 1 - eps)     # عشان log(0)
    loss = -(y_true * np.log(y_pred_probs) + (1 - y_true) * np.log(1 - y_pred_probs))
    return np.mean(loss * weights)

خطوة ٥: Threshold tuning

def find_optimal_threshold(y_true, y_probs, metric="f1"):
    best_threshold = 0.5
    best_score = -1.0
    for threshold in np.arange(0.05, 0.96, 0.01):
        y_pred = (y_probs >= threshold).astype(int)
        tp = np.sum((y_pred == 1) & (y_true == 1))
        fp = np.sum((y_pred == 1) & (y_true == 0))
        fn = np.sum((y_pred == 0) & (y_true == 1))
        if metric == "f1":
            prec = tp / (tp + fp) if (tp + fp) > 0 else 0.0
            rec = tp / (tp + fn) if (tp + fn) > 0 else 0.0
            score = 2 * prec * rec / (prec + rec) if (prec + rec) > 0 else 0.0
        elif metric == "recall":
            score = tp / (tp + fn) if (tp + fn) > 0 else 0.0
        elif metric == "precision":
            score = tp / (tp + fp) if (tp + fp) > 0 else 0.0
        else:
            score = 0.0
        if score > best_score:
            best_score = score
            best_threshold = threshold
    return best_threshold, best_score

خطوة ٦: المقاييس

def confusion_matrix_values(y_true, y_pred):
    tp = np.sum((y_pred == 1) & (y_true == 1))
    tn = np.sum((y_pred == 0) & (y_true == 0))
    fp = np.sum((y_pred == 1) & (y_true == 0))
    fn = np.sum((y_pred == 0) & (y_true == 1))
    return tp, tn, fp, fn


def compute_metrics(y_true, y_pred):
    tp, tn, fp, fn = confusion_matrix_values(y_true, y_pred)
    accuracy = (tp + tn) / (tp + tn + fp + fn)
    precision = tp / (tp + fp) if (tp + fp) > 0 else 0.0
    recall = tp / (tp + fn) if (tp + fn) > 0 else 0.0
    f1 = 2 * precision * recall / (precision + recall) if (precision + recall) > 0 else 0.0
    denom = np.sqrt(float((tp + fp) * (tp + fn) * (tn + fp) * (tn + fn)))
    mcc = (tp * tn - fp * fn) / denom if denom > 0 else 0.0
    return {"accuracy": accuracy, "precision": precision,
            "recall": recall, "f1": f1, "mcc": mcc}

w_cw, b_cw = logistic_regression_weighted(
    X_train, y_train, sample_weights, lr=0.1, epochs=300)
probs_cw = sigmoid(X_test @ w_cw + b_cw)

# Threshold: اتظبط على validation من التدريب، مش على الـ test
val_split = int(0.75 * len(y_train))
X_tr, X_val = X_train[:val_split], X_train[val_split:]
y_tr, y_val = y_train[:val_split], y_train[val_split:]
w_val, b_val = logistic_regression_weighted(
    X_tr, y_tr, compute_class_weights(y_tr), lr=0.1, epochs=300)
best_thresh, best_f1 = find_optimal_threshold(
    y_val, sigmoid(X_val @ w_val + b_val), metric="f1")
preds_thresh = (probs_cw >= best_thresh).astype(int)

print(compute_metrics(y_test, preds_thresh))

الملف الأصلي بيعمل ٨ أقسام: always-majority، من غير علاج، oversampling، undersampling، SMOTE، class weights، class weights + threshold، ومقارنة الـ weighted loss. وفي الآخر جدول ملخص فيه Acc وPrec وRec وF1 وMCC لكل طريقة.

المفروض تشوف إيه؟

أول سطرين محسوبين من الكود نفسه:

Dataset: 1000 samples, 50 positive (5.0%), 950 negative (95.0%)
Train: 800 samples, Test: 200 samples

وبعد كده (ما شغلتش الملف هنا، فمش هكتب أرقام): «Always majority» هتلاقي الـ accuracy بتاعته عالية والـ Recall والـ F1 والـ MCC كلهم 0. وقارن بنفسك: الطرق اللي بتعالج الـ imbalance المفروض ترفع الـ recall والـ MCC حتى لو الـ accuracy نزلت شوية. ولاحظ إن وزن الـ positive في قسم ٦ قريب من 10 لأن نسبة الـ positive في التدريب حوالي 5%.

خطوة ٨: نفس الكلام بـ sklearn وimbalanced-learn

# pip install imbalanced-learn
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report
from sklearn.model_selection import train_test_split
from imblearn.over_sampling import SMOTE
from imblearn.pipeline import Pipeline

X_train, X_test, y_train, y_test = train_test_split(X, y, stratify=y)   # stratify = نفس النسبة في الاتنين

model_weighted = LogisticRegression(class_weight="balanced")
model_weighted.fit(X_train, y_train)
print(classification_report(y_test, model_weighted.predict(X_test)))

smote = SMOTE(random_state=42)
X_resampled, y_resampled = smote.fit_resample(X_train, y_train)   # على التدريب بس
model_smote = LogisticRegression()
model_smote.fit(X_resampled, y_resampled)
print(classification_report(y_test, model_smote.predict(X_test)))

# الـ Pipeline بتاع imblearn بيعمل الـ SMOTE وقت الـ fit بس، مش وقت الـ predict
pipeline = Pipeline([
    ("smote", SMOTE()),
    ("model", LogisticRegression(class_weight="balanced")),
])
pipeline.fit(X_train, y_train)
print(classification_report(y_test, pipeline.predict(X_test)))

مفيش سحر: الـ SMOTE هو k-NN interpolation على الـ minority، والـ class weights بتضرب الـ loss، والـ threshold tuning هو for-loop على قيم القطع.

التمارين

اعمل ٣ على الأقل.

  1. Borderline-SMOTE: عدّل الـ SMOTE يولّد بس من نقط الـ minority القريبة من حدود القرار (اللي من ضمن أقرب k جيران ليها في الداتا كلها فيه majority). قارنه بالـ SMOTE العادي على داتا الـ classes فيها متداخلة.
    تلميحلكل نقطة minority، هات أقرب k جيران من X_train كله. لو عدد الـ majority فيهم بين k/2 وk−1 تبقى «danger» وتولّد منها. لو كلهم majority غالبًا دي noise، سيبها. عشان تعمل تداخل قرّب المركزين، مثلًا minority عند (1.2, 1.2).
  2. Cost matrix: اعمل cost-sensitive learning والـ cost matrix parameter. دالة بتاخد الـ cost matrix وترجّع التوقعات اللي بتقلل التكلفة المتوقعة. جرّب نسب 1:10 و1:100 و1:1000 وارسم الـ precision-recall tradeoff بيتغير إزاي.
    تلميحلكل عينة: cost(predict +) = (1−p)·C_FP وcost(predict −) = p·C_FN. اختار الأقل. ده نفس الـ threshold C_FP/(C_FP+C_FN) اللي في المعمل ٣. كل ما النسبة تكبر، الـ recall يطلع والـ precision تنزل.
  3. Platt scaling: اعمل logistic regression على الـ outputs الخام للموديل عشان تطلع احتمالات calibrated. قارن منحنى الـ PR قبل وبعد، ووضّح إن الـ calibration مش بتغيّر الترتيب (الـ AUC ثابت) بس بتخلّي الاحتمالات ليها معنى.
    تلميحخد الـ logits z = X_val @ w + b، ودرّب logistic بـ feature واحدة z على y_val. الناتج sigmoid(a·z + c). لو a > 0 فالترتيب زي ما هو، فالـ AUC مش هيتغير. قارن متوسط الاحتمالات بنسبة الـ positive الحقيقية قبل وبعد.
  4. Balanced bagging: درّب كذا موديل، كل واحد على bootstrap متوازن (كل الـ minority + جزء عشوائي من الـ majority)، وخد متوسط توقعاتهم. قارنه بموديل واحد بالـ SMOTE، في الأداء وفي التذبذب بين التشغيلات.
    تلميحده undersampling بس من غير ما ترمي الداتا: كل موديل بيشوف majority مختلفة، فالغابة كلها شافت كل حاجة. نفس فكرة الـ bagging من Day 33. شغّل التجربة بـ 10 seeds واحسب الـ std بتاع الـ F1.
  5. تجربة نسبة الـ imbalance: خد داتا متوازنة وزوّد الـ imbalance تدريجيًا (50/50، 70/30، 90/10، 95/5، 99/1). عند كل نسبة درّب بالـ SMOTE ومن غيره، وارسم الـ F1 مقابل النسبة. من عند أي نسبة الـ SMOTE بيفرق فعلًا؟
    تلميحاستخدم make_imbalanced_data(n_majority, n_minority) وخلّي المجموع ثابت. خلّي الـ test بنفس النسبة الحقيقية (متعملش resample للـ test أبدًا). غالبًا الفرق مش هيبان في 70/30 وهيبان أكتر كل ما النسبة تتطرف.
  6. إضافة مني · classifier لـ prompt injection: عندك 5000 رسالة جاية لـ agent، منهم 2% بس prompt injection. المطلوب: الـ recall لازم يبقى على الأقل 95% (تفويت injection خطر)، وبعد كده عايز أعلى precision ممكنة عشان متضايقش اليوزرز العاديين. اعمل داتا صناعية بـ 2 features (score من كلمات مشبوهة + طول الرسالة)، ودرّب logistic بـ class weights، وهات الـ threshold اللي بيحقق الشرط على الـ validation، واحسب الـ precision عنده.
    تلميحرتّب الـ positives في الـ validation حسب الاحتمال، وخد الـ threshold = الاحتمال عند الـ 5th percentile بتاعهم (عشان 95% منهم فوقه). قيس الـ precision على الـ test مش على نفس الـ validation. ده اسمه «recall at fixed target» وهو أقرب لطريقة شغل فرق الـ safety من الـ F1.

إضافة مني: اللي الدرس مقالوش صريح

الحدس في جملة

كل الحلول بتعمل نفس الحاجة بطرق مختلفة: بتقول للموديل «الـ class دي أهم مما عددها بيوحي». الـ resampling بيقولها بالداتا، والـ weights بيقولها في الـ loss، والـ threshold بيقولها وقت القرار.

أخطاء بتحصل كتير

  • • SMOTE قبل الـ split: النقط الصناعية بتتعمل من نقط ممكن تقع في الـ test، فالموديل بيشوف «نسخ مشوهة» من الـ test وهو بيتدرب. ده leakage. اعمل resample على التدريب بس، وجوه كل fold في الـ CV (عشان كده الـ Pipeline بتاع imblearn موجود، زي Day 35).
  • • Resample للـ test: الـ test لازم يفضل بنفس نسبة الدنيا الحقيقية، وإلا الأرقام مش هتشبه الـ production.
  • • نسيان stratify=y: مع 50 positive بس، split عشوائي ممكن يحط في الـ test عدد قليل جدًا، والمقاييس تتهز جامد.
  • • الاحتمالات بعد الـ resampling مش calibrated: لو دربت على 50/50 والدنيا 5/95، الموديل هيدّي احتمالات أعلى من الحقيقة. لو بتستخدم الاحتمال نفسه (في التكلفة أو في الـ ranking مع موديلات تانية) اعمل calibration (تمرين ٣).
  • • SMOTE على features categorical: الـ interpolation بين one-hot بيطلّع قيم زي 0.4 ملهاش معنى. imbalanced-learn فيها SMOTENC للحالة دي.
  • • تظبيط الـ threshold على الـ test: كده الـ test بقى جزء من التدريب. الكود الأصلي بيعمل validation slice من التدريب عشان كده.

بيظهر فين في الـ LLMs والـ Agents؟

  • • Guardrails: classifiers للـ jailbreak والـ prompt injection والمحتوى الضار: الحالات الخطرة نادرة جدًا وسط الرسايل العادية، وفرق الـ safety غالبًا بتحدد recall مطلوب وتشوف الـ precision عنده.
  • • تقييم LLM-as-judge: لو عندك eval set فيه 3% إجابات فيها hallucination، «الـ judge دقيق 97%» ممكن يبقى معناها إنه بيقول «كويس» على طول. اطلب precision وrecall للـ class النادرة.
  • • Intent routing: agent بيوزّع الطلبات على tools، وفيه intents نادرة بس مهمة (إلغاء اشتراك، شكوى قانونية). نفس الحلول: class weights، أمثلة صناعية (ودلوقتي ممكن الـ LLM نفسه يولّدها، فكرة قريبة من SMOTE بس في مساحة النص)، وthreshold أقل للـ intents المهمة.
  • • Focal loss: في الـ object detection (موديل RetinaNet) ظهرت loss بتقلل وزن الأمثلة السهلة الكتير عشان الموديل يركز على الصعبة النادرة. نفس روح الـ class weights، ولو اشتغلت في الـ object detection هتقابلها.

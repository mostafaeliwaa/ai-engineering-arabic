الـ adapter: الواجهة الصغيرة اللي بتفصل الموديل عن الـ runner

class ModelAdapter:

@dataclass
class Generation:
    text: str                # رد الموديل كنص حر
    confidence: float = 0.5  # ثقة الموديل في الإجابة، في [0, 1]
    token_nll: float = 0.0   # اختياري: مجموع الـ NLL على الـ tokens المتولدة
    token_count: int = 0     # اختياري: عدد الـ tokens

دالة واحدة بس. أي موديل (mock، local، API) يقدر يلبس الواجهة دي. كل حاجة تانية (retries، caching، rate limits) مكانها جوه الـ adapter مش الـ runner.

الـ ٣ adapters الوهمية (mocks)

  • RuleBasedAdapter (rule_based): deterministic وشبه مثالي. بيرجّع الـ target نفسه، وللكود بيكتب الحل الصح لـ add و is_even. ثقته 0.92 دايمًا، و NLL لكل token = 0.8.
  • NoisyAdapter (noisy): بيجيب الإجابة الصح بنسبة ٢٥٪ بس، وغير كده «I do not know» أو «Answer: A» أو add بتطرح بدل ما تجمع. ثقته 0.85 دايمًا (يعني overconfident جدًا)، و NLL لكل token = 2.5.
  • BiasedAdapter (biased): ممتاز في فئة واحدة (arithmetic افتراضيًا) بثقة 0.9، وبيخمّن في الباقي بثقة 0.4. NLL لكل token = 1.0 في فئته و 3.0 في الباقي.

معمل ١: تتبّع task واحد في الـ pipeline

اختار adapter و task من الـ ١٠ tasks الحقيقية بتاعة fixture درس ٧٠، ودوس «تتبّع». هتشوف كل مرحلة بتحوّل إيه لإيه. الـ metrics هنا محاكاة مبسطة في المتصفح (للـ summaries بنعتبر التطابق الكامل 1 وغيره 0، وده بيطابق ردود الـ mocks دي). الـ noisy بيستخدم random generator من عندي، فدوس «زهر جديد» تشوف حالات تانية.

M1 · تحميل الموديولات الشقيقة

كل درس اسم الملف بتاعه main.py، فما ينفعش تعمل import main خمس مرات. الحل: importlib تحمّل كل ملف باسم موديول مختلف.

import importlib.util, json, os, random, sys, time
from concurrent.futures import ThreadPoolExecutor, as_completed
from dataclasses import dataclass

def _load_sibling(lesson_dir, module_name="main"):
    here = os.path.dirname(os.path.abspath(__file__))
    sibling = os.path.normpath(os.path.join(here, "..", "..", lesson_dir, "code", "main.py"))
    if not os.path.isfile(sibling):
        raise ImportError(f"sibling module not found: {sibling}")
    mod_name = f"_sibling_{lesson_dir.replace('-', '_')}"   # اسم فريد لكل درس
    spec = importlib.util.spec_from_file_location(mod_name, sibling)
    if spec is None or spec.loader is None:
        raise ImportError(f"could not build spec for {sibling}")
    module = importlib.util.module_from_spec(spec)
    sys.modules[mod_name] = module        # لازم قبل exec عشان الـ dataclasses تشتغل
    spec.loader.exec_module(module)
    return module

M3 · الـ scoring loop لـ task واحد

لكل task: (١) ارسم الـ prompt، (٢) نادي الـ adapter واحسب الوقت، (٣) اعمل post-process حسب قاعدة الـ task، (٤) وزّع على طبقة الـ metric، (٥) ابني نتيجة فيها الـ score والـ metadata، (٦) الثقة والصح بيروحوا لبافر الـ calibration بعدين.

def _correct_from_score(metric_name, score, threshold=0.5):
    if metric_name in ("exact_match", "accuracy", "code_exec"):
        return score >= 0.999999          # يا صح يا غلط: لازم 1.0
    return score >= threshold             # المتدرجة (f1, bleu, rouge): 0.5

def _score_one(adapter, task, timeout_s=3.0):
    rendered = spec_mod.render_prompt(task)
    t0 = time.time()
    gen = adapter.generate(rendered, task)
    elapsed = time.time() - t0
    processed = spec_mod.post_process(gen.text, task.post_process)
    if task.metric_name == "code_exec":   # الكود بيتشغّل في subprocess (درس 72)
        result = exec_mod.run_candidate(exec_mod.extract_code(processed) or processed,
                                        task.targets, timeout_s=timeout_s)
        score, detail = result.score, result.detail
    else:                                  # الباقي من درس 71
        score, detail = metrics_mod.score(task.metric_name, processed, task.targets), ""
    return TaskResult(
        model_id=adapter.model_id, task_id=task.task_id, category=task.category,
        metric_name=task.metric_name, score=float(score),
        correct=bool(_correct_from_score(task.metric_name, score)),
        confidence=float(min(1.0, max(0.0, gen.confidence))),   # clamp للأمان
        generation=gen.text, detail=detail, wall_seconds=float(elapsed))

الـ threshold جوه _correct_from_score والـ runner ما بيدّيش طريقة عامة تغيّره. Check: _correct_from_score("exact_match", 0.99) = False، و ("f1", 0.6) = True، و ("f1", 0.49) = False.

M4 · الـ run_eval مع parallel اختياري

الـ runner بيستخدم ThreadPoolExecutor. الـ threads كفاية لأن عنق الزجاجة في الموديلات الحقيقية هو الـ network I/O، ومسار الكود بيعمل subprocess لوحده والـ executor بس بيستنى. الدرس بيقول عدد الـ workers الافتراضي هو الأصغر بين ٨ وعدد الـ tasks، والكود بيعمل min(max_workers, len(work)) و max_workers=8. وفيه flag اسمه parallel: الـ tests بتقفله عشان الترتيب يبقى ثابت.

def run_eval(adapters, tasks, parallel=True, max_workers=8, code_exec_timeout_s=3.0):
    results = []
    model_ids = [a.model_id for a in adapters]
    if len(set(model_ids)) != len(model_ids):          # model_id لازم يبقى فريد
        raise ValueError("adapter.model_id values must be unique within a single eval run")
    calibration_buf = {mid: [] for mid in model_ids}
    if not tasks or not adapters:
        return results, calibration_buf
    work = [(a, t) for a in adapters for t in tasks]     # كل موديل × كل task
    if parallel and len(work) > 1:
        with ThreadPoolExecutor(max_workers=min(max_workers, len(work))) as ex:
            futures = {ex.submit(_score_one, a, t, code_exec_timeout_s): (a, t) for a, t in work}
            for fut in as_completed(futures):           # بترجع بترتيب الخلصان
                results.append(fut.result())
    else:
        for a, t in work:
            results.append(_score_one(a, t, code_exec_timeout_s))
    results.sort(key=lambda r: (r.model_id, r.task_id))   # نرجّع الترتيب ثابت
    for r in results:
        calibration_buf[r.model_id].append((r.confidence, 1.0 if r.correct else 0.0, r.score))
    return results, calibration_buf

Check: نفس الـ adapter مرة parallel=False ومرة parallel=True بيطلّعوا نفس الـ scores لكل task (ده الـ test test_parallel_sequential_match).

معمل ٢: parallel ضد sequential

٣٠ شغلانة (٣ adapters × ١٠ tasks). كل شغلانة ليها latency (محاكاة: نداء API بين 0.2 و 1.2 ثانية، ومهام الكود أطول عشان الـ subprocess). كل صف worker، وكل مستطيل شغلانة. الأرقام في المستطيلات = ترتيب الخلصان.

جرب: (١) workers = 1: ده الـ sequential، والوقت = مجموع كل الـ latencies. (٢) زوّد لـ 8 وشوف الوقت بيقل قد إيه. (٣) لاحظ ترتيب الخلصان بيتلخبط، وده سبب results.sort في الآخر.

M5 · التقرير: aggregate + calibration + perplexity

بعد ما كل task يخلص، الـ runner بيحوّل النتايج لـ EvalRun ويديها لـ aggregate و pairwise_diffs من درس ٧٤ (بـ b = 200، seed = 7)، وبيحسب CalibrationReport من درس ٧٣ لكل موديل بـ ١٠ صناديق. والـ perplexity لكل موديل من الـ token_stats اللي الـ adapter جمّعها، جنب الـ leaderboard مش جواه.

def build_eval_runs(results):
    return [board_mod.EvalRun(model_id=r.model_id, task_id=r.task_id,
                              metric_name=r.metric_name, score=r.score, category=r.category)
            for r in results]

def _calibration_blocks(buf):
    out = {}
    for model_id, entries in buf.items():
        if not entries:
            out[model_id] = {"ece": 0.0, "brier": 0.0, "populated_bins": 0, "n_samples": 0}
            continue
        report = calib_mod.CalibrationReport.from_predictions(
            [e[0] for e in entries], [e[1] for e in entries], bins=10)
        out[model_id] = {"ece": report.ece, "brier": report.brier,
                         "populated_bins": report.populated_bins, "n_samples": report.n_samples}
    return out

def _perplexity_blocks(adapters, buf, results, adapter_token_stats):
    out = {}
    for adapter in adapters:
        stats = adapter_token_stats.get(adapter.model_id, [])
        if not stats:
            out[adapter.model_id] = {"perplexity": float("nan"), "total_tokens": 0}
            continue
        result = calib_mod.PerplexityResult.from_token_nll([s[0] for s in stats], [s[1] for s in stats])
        out[adapter.model_id] = result.to_dict()
    return out

def render_report(adapters, tasks, results, calibration_buf, adapter_token_stats, wall_seconds):
    eval_runs = build_eval_runs(results)
    rows = board_mod.aggregate(eval_runs, b=200, alpha=0.05, seed=7)
    diffs = board_mod.pairwise_diffs(eval_runs, b=200, alpha=0.05, seed=7)
    return EvalReport(
        leaderboard=[r.to_dict() for r in rows],
        pairwise=[d.to_dict() for d in diffs],
        calibration=_calibration_blocks(calibration_buf),
        perplexity=_perplexity_blocks(adapters, calibration_buf, results, adapter_token_stats),
        summary={"tasks": len(tasks), "models": len(adapters),
                 "task_runs": len(results), "wall_seconds": float(wall_seconds)})

def render_markdown_block(report):
    lines = ["| Rank | Model | Mean | 95% CI | Win rate | Tasks | ECE | Brier |",
             "|------|-------|------|--------|----------|-------|-----|-------|"]
    for i, row in enumerate(report.leaderboard, start=1):
        cal = report.calibration.get(row["model_id"], {})
        ci = f"{row['mean_ci_lo']:.2f}-{row['mean_ci_hi']:.2f}"
        lines.append(f"| {i} | {row['model_id'][:20]} | {row['mean_score']:.2f} | {ci} | "
                     f"{row['win_rate']:.2f} | {row['tasks_completed']} | "
                     f"{cal.get('ece', float('nan')):.3f} | {cal.get('brier', float('nan')):.3f} |")
    return "\n".join(lines)

class RuleBasedAdapter(ModelAdapter):
    model_id = "rule_based"
    def __init__(self):
        self.token_stats = []                   # (nll, count) لكل نداء
    def generate(self, prompt, task):
        text = task.targets[0] if task.targets else ""
        if task.metric_name == "code_exec":
            if task.task_id == "code_001":
                text = "```python\ndef add(a, b):\n    return a + b\n```"
            elif task.task_id == "code_002":
                text = "```python\ndef is_even(n):\n    return n % 2 == 0\n```"
            else:
                text = "```python\npass\n```"
        if task.post_process == "extract_letter" and task.targets:
            text = f"Answer: {task.targets[0]}"
        token_count = max(1, len(text.split()))
        nll = token_count * 0.8
        self.token_stats.append((nll, token_count))
        return Generation(text=text, confidence=0.92, token_nll=nll, token_count=token_count)

class NoisyAdapter(ModelAdapter):
    model_id = "noisy"
    def __init__(self, seed=0):
        self.rng = random.Random(seed)
        self.token_stats = []
    def generate(self, prompt, task):
        if self.rng.random() < 0.25 and task.targets:
            text = task.targets[0]              # صح بنسبة 25%
        else:
            text = "I do not know"
            if task.post_process == "extract_letter":
                text = "Answer: A"
            if task.metric_name == "code_exec":
                text = "```python\ndef add(a, b):\n    return a - b\n```"
        token_count = max(1, len(text.split()))
        nll = token_count * 2.5
        self.token_stats.append((nll, token_count))
        return Generation(text=text, confidence=0.85, token_nll=nll, token_count=token_count)

class BiasedAdapter(ModelAdapter):
    model_id = "biased"
    def __init__(self, good_category="arithmetic"):
        self.good_category = good_category
        self.token_stats = []
    def generate(self, prompt, task):
        if task.category == self.good_category and task.targets:
            text, confidence, nll_per_token = task.targets[0], 0.9, 1.0
        else:
            text = "guess"
            if task.post_process == "extract_letter":
                text = "Answer: B"
            if task.metric_name == "code_exec":
                text = "```python\ndef add(a, b):\n    return None\n```"
            confidence, nll_per_token = 0.4, 3.0
        token_count = max(1, len(text.split()))
        nll = token_count * nll_per_token
        self.token_stats.append((nll, token_count))
        return Generation(text=text, confidence=confidence, token_nll=nll, token_count=token_count)

def _load_fixture_tasks():
    import tempfile
    good, _bad = spec_mod.load_fixtures(tempfile.mkdtemp(prefix="aie_l75_"))
    tasks, errors = spec_mod.validate_file(good)
    if errors:
        raise RuntimeError(f"fixture validation failed: {errors}")
    return tasks

def demo():
    tasks = _load_fixture_tasks()
    adapters = [RuleBasedAdapter(), NoisyAdapter(seed=1), BiasedAdapter(good_category="arithmetic")]
    t0 = time.time()
    results, buf = run_eval(adapters, tasks, parallel=True, max_workers=6, code_exec_timeout_s=2.0)
    wall = time.time() - t0
    stats = {a.model_id: list(getattr(a, "token_stats", [])) for a in adapters}
    report = render_report(adapters, tasks, results, buf, stats, wall)
    print(render_markdown_block(report))
    print()
    print(f"summary: {json.dumps(report.summary, indent=2)}")
    print()
    print("pairwise differences (paired bootstrap):")
    for d in report.pairwise:
        sig = "yes" if d["significant"] else "no"
        print(f"  {d['model_a']} vs {d['model_b']}: diff={d['diff_mean']:+.3f}  "
              f"ci=[{d['ci_lo']:+.3f},{d['ci_hi']:+.3f}]  significant={sig}")
    if not report.leaderboard:
        print("ERROR: empty leaderboard"); return 1
    top, bot = report.leaderboard[0]["model_id"], report.leaderboard[-1]["model_id"]
    if top != "rule_based":
        print(f"ERROR: expected rule_based at top, got {top}"); return 2
    if bot == "rule_based":
        print("ERROR: rule_based should not be at the bottom"); return 3
    return 0

if __name__ == "__main__":
    sys.exit(demo())

  • الـ rule_based في المركز الأول. (الـ docs بتقول «فوق الـ random adapter»، والكود بيطبّقها كده: الأول لازم rule_based، والأخير لازم ميكونش rule_based، وإلا exit 2 أو 3.)

الدرس بيقول الوقت الكلي المفروض يبقى أقل من ١٠ ثواني على الـ ١٠ tasks.

المتوقع لما تشغّل

جدول markdown بـ ٣ صفوف وأعمدة ECE و Brier، و rule_based في الأول. بعده summary فيه "tasks": 10 و "models": 3 و "task_runs": 30، وبعده ٣ سطور pairwise، و exit=0. حاجات تقدر تحسبها بإيدك قبل ما تشغّل (وتقارن):

  • rule_based ثقته 0.92 دايمًا. لو كل الـ ١٠ طلعوا صح، يبقى كلهم في صندوق واحد: ECE = |0.92 − 1| = 0.08 و Brier = 0.08² = 0.0064.
  • الـ perplexity بتاعة rule_based = e^0.8 ≈ 2.23 وبتاعة noisy = e^2.5 ≈ 12.18 بالظبط، مهما كان عدد الـ tokens، لأن الـ NLL لكل token ثابت عندهم. الـ biased بيخلط 1.0 و 3.0 فبيعتمد على أطوال ردوده.
  • أرقام الـ noisy بتعتمد على random.Random(seed=1)، فشغّل وشوف.

معمل ٣: ابني التقرير من المحاكاة

نفس محاكاة معمل ١، بس على الـ ٣٠ شغلانة كلها: mean و win-rate و ECE و Brier و perplexity لكل adapter. الـ rule_based والـ biased deterministic، والـ noisy بالـ random generator بتاعي (مش بتاع Python)، فما تتوقعش نفس أرقامه.

جرب: (١) لاحظ إن الـ noisy ثقته 0.85 وهو بيغلط أغلب الوقت: الـ ECE بتاعه هو الأعلى. (٢) غيّر الفئة اللي الـ biased شاطر فيها وشوف ترتيبه بيتغير. (٣) دوس «زهر جديد» كذا مرة: ممكن الـ noisy يعدّي الـ biased؟
03

الـ runner ده مش بيعمل إيه، وإيه اللي بعده

مش بينادي موديل حقيقي، ومفيهوش API keys ولا rate limits، ومفيهوش streaming (رد واحد لكل نداء)، ولا retries ولا caching. كل ده مكانه طبقة الـ adapter، والـ runner يفضل محايد للـ metric وللـ provider.

نظام eval حقيقي في production بيضيف (والدرس بيعدّهم):

  • results cache بمفتاح (task_id, model_id, model_version): ما تدفعش تاني على نفس السؤال.
  • cost ledger: دولارات و tokens لكل run.
  • retry layer بيعمل back-off على الـ rate limits.
  • sampling policy لـ tasks الـ pass@k.
  • streaming output للـ suites الطويلة.

كل واحدة منهم concern لوحده بيلف حوالين الـ runner من غير ما يغيّر طبقة الـ metric أو الـ aggregation. والفصل ده هو هدف العقد كله. والخطوة الطبيعية: بعد ما الـ mocks تشتغل، اكتب adapter لـ provider حقيقي عنده free tier (الدرس بيقول حوالي ٣٠ سطر glue)، وبعدين التاني، وسيب الـ harness يشتغل.

04

التمارين

الدرس ما فيهوش قايمة تمارين منفصلة، فدي مأخوذة من «Going further»، والأخير إضافة مني.

  1. Results cache: لفّ أي adapter في CachedAdapter بيحفظ الـ Generation بمفتاح (task_id, model_id, model_version).
    تلميحنفس الواجهة: model_id و generate. جوه generate دوّر في dict (أو ملف JSONL) الأول، ولو مش موجود نادي الـ adapter الداخلي واحفظ. خلي بالك إن الـ threads بتكتب في نفس الوقت، فاستخدم threading.Lock. اختبر إن الـ adapter الداخلي اتنادى مرة واحدة بس لما تشغّل الـ eval مرتين.
  2. Retry مع back-off: RetryingAdapter بيعيد المحاولة لما الـ adapter الداخلي يرمي exception.
    تلميحfor attempt in range(n): try: return inner.generate(...) except RateLimitError: time.sleep(base * 2**attempt + random.random()*jitter). في الآخر ارمي الـ exception. الـ runner نفسه ما يتغيرش، وده بالظبط معنى «concern بيلف حوالين الـ runner».
  3. Cost ledger: كل TaskResult يشيل tokens، والتقرير يطلّع "cost": {model_id: {"tokens":…, "usd":…}}.
    تلميحضيف token_count من الـ Generation للـ TaskResult، وخلي الـ adapter يعرّف price_per_1k_tokens. اجمع في render_report وضيف المفتاح للـ envelope. حدّث الـ test بتاع الـ envelope.
  4. Adapter لـ provider حقيقي (من «Going further»): اكتبه وشغّله جنب الـ mocks.
    تلميحالـ generate بتبعت prompt وترجّع Generation(text=…). لو الـ API بيدّي log-probabilities للـ tokens، اجمع −logprob في token_nll. لو مش بيدّي، سيب الثقة 0.5 (الافتراضي)، وده هيبان في الـ ECE. حط الـ key في environment variable مش في الكود.
  5. إضافة مني · eval gate في الـ CI: اعمل script بيشغّل الـ runner على suite صغير، ويفشل (exit ≠ 0) لو موديل الـ PR أسوأ significantly من الـ baseline، ويطبع الجدول عشان يتحط كتعليق.
    الحلشغّل run_eval([baseline, candidate], tasks) و render_report. دوّر في report.pairwise على الزوج ده. انتبه للاتجاه: model_a هو الأول أبجديًا، والفرق a − b. لو الـ candidate أسوأ والـ CI ما فيهوش الصفر، اطبع render_markdown_block(report) و sys.exit(1). لو الفرق مش significant، عدّي بس اطبع تحذير. ده شكل شائع جدًا لحماية الـ prompts والـ RAG pipelines من regressions.
05

إضافة مني: اللي الدرس ما قالوش

الحدس في سطر: الـ runner الكويس «ممل»: ما فيهوش أي ذكاء. كل الذكاء في الموديولات اللي بيركّبها. لو لقيت نفسك بتكتب حسابات جوه الـ runner، غالبًا مكانها درس تاني.

أخطاء شائعة

  • الـ token_stats بتتراكم: الـ mocks بتضيف لـ self.token_stats في كل نداء. لو شغّلت نفس الـ instance مرتين، الـ perplexity هتتحسب على الاتنين مع بعض. عشان كده الـ test بتاع parallel ضد sequential بيعمل adapter جديد لكل run.
  • model_id متكرر: لو عملت اتنين RuleBasedAdapter() في نفس الـ run، الـ runner بيرمي ValueError، لأن الـ calibration buffer والـ leaderboard مفتاحهم الـ model_id.
  • الـ correct threshold مخفي: ROUGE = 0.5 بيتعدّ «صح» في الـ calibration. ده قرار تصميم، مش حقيقة. لو الـ suite بتاعك كله summaries، فكّر فيه كويس.
  • الحظ بيبان صح: الـ biased خمّن «B» في mcq_001 وطلعت صح. في suite صغير، حالة زي دي بتأثر على الـ mean والـ calibration. وده سبب الـ CI.
  • الـ threads والـ GIL: الـ threads بتسرّع الـ I/O (نداءات API، انتظار subprocess)، بس لو الـ metric نفسه بيحسب حاجة تقيلة بـ Python، مش هتكسب كتير.

بيظهر فين في الـ LLMs والـ agents

ده بالظبط شكل أدوات الـ eval المفتوحة والداخلية في الشركات: ملف tasks، و adapters لكل provider، وطبقة metrics، وتقرير. في الـ agents بالذات، الـ adapter ممكن يكون الـ agent كله (بأدواته وخطواته)، والـ task بيبقى مهمة كاملة، والـ metric ممكن يكون «الـ tests عدّت؟» زي درس ٧٢. نفس الهيكل بيكبر معاك.

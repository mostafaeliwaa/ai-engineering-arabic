01

ليه ViT مهم؟ والقصة بتاعته

لمدة عشر سنين «رؤية بالكمبيوتر» كانت يعني convolution. الـ CNN عنده inductive biases قوية: locality (الجار يهم أكتر) وtranslation equivariance (القطة قطة في أي مكان). محدش كان متخيل إننا نقدر نستغنى عنهم. وبعدين Dosovitskiy وآخرون (2020) أثبتوا إن transformer عادي على patches مفرودة، من غير أي convolution (غير الـ patchify)، بيجاري أو بيغلب أحسن CNNs على نطاق كبير.

الـ «لكن»: ViT على ImageNet-1k لوحدها خسر قدام ResNet. أما ViT المتدرّب مسبقًا على ImageNet-21k أو JFT-300M ثم fine-tuned على ImageNet-1k فغلبه. الاستنتاج: الـ transformer مفيهوش priors مفيدة، بس بيتعلمها لو معاه داتا كفاية. بعدين DeiT وMAE وDINO أثبتوا إن بوصفة تدريب مظبوطة (augmentation قوي، self-supervised pretraining، distillation) الـ ViT بيتدرب كويس على داتا صغيرة.

تشبيه: الـ CNN طالب إدّوه كتاب قواعد جاهز (المكان والجيران). الـ ViT طالب إدّوه ورق فاضي: بياخد وقت أطول ويحتاج أمثلة أكتر، بس لما يتعلم ممكن يطلع قواعد أحسن من الكتاب.

في 2026 الـ CNN لسه منافس على الأجهزة الصغيرة (ConvNeXt أقواها)، لكن الـ transformers بتسيطر على الباقي: segmentation (Mask2Former, SegFormer)، detection (DETR, RT-DETR)، multimodal (CLIP, SigLIP)، فيديو (VideoMAE, VJEPA). شكل الـ ViT block هو اللي لازم تعرفه.

02

الـ pipeline: سبع خطوات

Patches ← tokens ← attention ← classifier. وكل variant (DeiT، Swin، ConvNeXt، MAE) بيغيّر خطوة أو اتنين ويسيب الباقي.

١) Patch embedding: الـ conv السري

Kernel حجمه 16 وstride 16، فصورة 224×224 بتتحول لـ grid 14×14 من patches كل واحدة 16×16، وكل واحدة بتتحول لـ embedding بحجم 768. الـ conv الواحد ده بيقطّع وبيعمل projection خطي في نفس الوقت.

Input: (3, 224, 224) Conv (3 → 768, k=16, s=16, بدون padding): (768, 14, 14) Flatten: (196, 768)

196 patch = 196 token. بُعد الـ token: 768 (ViT-B)، 1024 (ViT-L)، 1280 (ViT-H).

٢) Class token

vector واحد متعلَّم بيتحط في أول التسلسل: tokens = [CLS; patch₁; …; patch₁₉₆] فالشكل (197, 768). بعد N blocks، خرج الـ [CLS] بيمثل الصورة كلها، والـ classifier بيقرا الـ vector ده بس.

تشبيه: الـ CLS زي «المقرر» في اجتماع: الكل بيتكلم، وهو بيسمع الكل (لأن الـ attention بيخليه يشوف كل الـ tokens) وفي الآخر بيكتب الملخص.

٣) Positional embedding

الـ transformer مفيهوش إحساس بالمكان. فبنضيف vector متعلَّم لكل token: tokens = tokens + pos_embed (برضه (197, 768)). هو parameter في الموديل والـ training بيعلّمه بنية الصورة 2D. بدايل sinusoidal 2D موجودة لكن نادرًا ما بتتستخدم.

٤) الـ Encoder block

x = x + MSA(LN(x)) x = x + MLP(LN(x)) MLP = Linear(d→4d) → GELU → Linear(4d→d)

ViT-B/16 فيه 12 block، كل واحد 12 head، والمجموع 86 مليون بارامتر.

ليه Pre-LN؟

الـ transformers الأولى استخدمت post-LN (x = LN(x + sublayer(x))) وصعب تتدرب أعمق من 6–8 طبقات من غير warmup. الـ pre-LN (x = x + sublayer(LN(x))) بيدرّب شبكات أعمق بثبات من غير warmup. كل ViT وكل LLM حديث بيستخدم pre-LN.

لاحظ: في pre-LN الـ residual path «نضيف» (مفيهوش LN)، فالـ gradient بيعدي مباشرة. ده نفس فكرة identity اللي شفناها في Phase 1.
03

حجم الـ patch: السرعة ضد التفاصيل

  • 16×16 ← 196 token: المعيار.
  • 32×32 ← 49 token: أسرع بس تفاصيل أقل.
  • 8×8 ← 784 token: أدق لكن الـ attention تربيعي فالتكلفة بتنفجر.

SwinV2 بيستخدم patches 4×4 داخل نوافذ هرمية.

معمل ١: عدد الـ tokens وتكلفة الـ attention

غيّر حجم الصورة وحجم الـ patch. شوف عدد الـ tokens، وعدد أزواج الـ attention ((tokens+1)²، مع الـ CLS). لما الـ patch يتصغّر للنص، الـ tokens بتتضاعف 4 مرات والـ attention تقريبًا 16 مرة.

لاحظ: الـ image size لازم تقبل القسمة على patch size (الكود فيه assert). الأعمدة هنا بتتقارن على مقياس نسبي.
04

وصفة DeiT: ViT على ImageNet-1k لوحدها

الـ ViT الأصلي احتاج JFT-300M. DeiT (Touvron 2020) وصل بـ ViT-B لـ 81.8% top-1 على ImageNet-1k لوحدها بأربع تغييرات:

  1. Augmentation تقيل: RandAugment، Mixup، CutMix، Random Erasing.
  2. Stochastic depth: بنرمي blocks كاملة عشوائيًا في التدريب.
  3. Repeated augmentation: نفس الصورة 3 مرات في الـ batch.
  4. Distillation من CNN teacher (اختياري، بيرفع الدقة أكتر).

كل وصفة ViT حديثة نازلة من DeiT.

ConvNeXt أثبت إن الفجوة مش «attention ضد convolution» بل «وصفة تدريب حديثة + معمارية». في 2026 الاتنين (ConvNeXt-V2 وSwin-V2) جاهزين للإنتاج، والاختيار حسب الـ inference stack (ConvNeXt بيتcompile أحسن للـ edge) والـ pretraining corpus.

معمل ٢: ليه Swin أرخص؟

صورة 224×224 بـ patches 4×4 = 3136 token. attention كامل = حوالي 9.8 مليون زوج لكل طبقة. Swin بيحصره في نوافذ (عادةً 7×7 = 49 token) فبيبقى tokens × window² تقريبًا. غيّر حجم النافذة وشوف.

06

MAE: pretraining من غير labels

Masked Autoencoder (He 2022): خبّي 75% من الـ patches عشوائيًا، خلّي الـ encoder يشوف الـ 25% الباقيين بس، وخلّي decoder صغير يعيد بناء الـ patches المخبية من خرج الـ encoder. بعد الـ pretraining ارمي الـ decoder واعمل fine-tune للـ encoder.

MAE بيخلّي ViT قابل للتدريب على ImageNet-1k لوحدها، وبيوصل لـ SOTA، وهو دلوقتي الوصفة الافتراضية للـ self-supervised.

تشبيه: لعبة أحجية: بتشوف ربع القطع بس وبتتخيل الباقي. عشان تنجح لازم تفهم الصورة كلها مش بس تنسخ، وده اللي بيعلّم الـ encoder features مفيدة.

معمل ٣: خطوات الـ MAE

دوس «التالي» وشوف الـ 14×14 patches: الأصلية، بعد إخفاء 75%، اللي بيشوفه الـ encoder (ومحتاج حسبة أقل بكتير!)، وإعادة البناء.

لاحظ: الـ encoder بيشوف 49 token بس من 196، فالـ attention عنده تقريبًا 16× أرخص. ده سر كفاءة MAE في التدريب.

الخطوة ١: Patch embedding.

import torch
import torch.nn as nn

class PatchEmbedding(nn.Module):
    def __init__(self, in_channels=3, patch_size=16, dim=192, image_size=64):
        super().__init__()
        assert image_size % patch_size == 0              # لازم يقبل القسمة
        self.proj = nn.Conv2d(in_channels, dim, kernel_size=patch_size, stride=patch_size)
        self.num_patches = (image_size // patch_size) ** 2

    def forward(self, x):
        x = self.proj(x)                      # (N, dim, H/p, W/p)
        return x.flatten(2).transpose(1, 2)   # (N, num_patches, dim)

conv واحد + flatten + transpose = كل خطوة «صورة ← tokens».

الخطوة ٢: الـ block.

class Block(nn.Module):
    def __init__(self, dim, num_heads, mlp_ratio=4, dropout=0.0):
        super().__init__()
        self.ln1 = nn.LayerNorm(dim)
        self.attn = nn.MultiheadAttention(dim, num_heads, dropout=dropout, batch_first=True)
        self.ln2 = nn.LayerNorm(dim)
        self.mlp = nn.Sequential(
            nn.Linear(dim, dim * mlp_ratio),
            nn.GELU(),
            nn.Dropout(dropout),
            nn.Linear(dim * mlp_ratio, dim),
            nn.Dropout(dropout),
        )

    def forward(self, x):
        h = self.ln1(x)                                           # pre-LN
        a, _ = self.attn(h, h, h, need_weights=False)             # self-attention: Q=K=V=h
        x = x + a                                                 # residual
        x = x + self.mlp(self.ln2(x))                             # residual تاني
        return x

في الدرس الأصلي بيكتب self.ln1(x) تلات مرات في نداء الـ attention؛ تخزينها في h أنضف وبيدّي نفس النتيجة.

الخطوة ٣: الـ ViT.

class ViT(nn.Module):
    def __init__(self, image_size=64, patch_size=16, in_channels=3,
                 num_classes=10, dim=192, depth=6, num_heads=3, mlp_ratio=4):
        super().__init__()
        self.patch = PatchEmbedding(in_channels, patch_size, dim, image_size)
        num_patches = self.patch.num_patches
        self.cls_token = nn.Parameter(torch.zeros(1, 1, dim))
        self.pos_embed = nn.Parameter(torch.zeros(1, num_patches + 1, dim))
        self.blocks = nn.ModuleList([Block(dim, num_heads, mlp_ratio) for _ in range(depth)])
        self.ln = nn.LayerNorm(dim)
        self.head = nn.Linear(dim, num_classes)
        nn.init.trunc_normal_(self.pos_embed, std=0.02)
        nn.init.trunc_normal_(self.cls_token, std=0.02)

    def forward(self, x):
        x = self.patch(x)
        cls = self.cls_token.expand(x.size(0), -1, -1)    # نسخة من CLS لكل صورة
        x = torch.cat([cls, x], dim=1)                    # CLS في الأول
        x = x + self.pos_embed
        for blk in self.blocks:
            x = blk(x)
        x = self.ln(x[:, 0])                              # خرج CLS بس
        return self.head(x)

vit = ViT(image_size=64, patch_size=16, num_classes=10, dim=192, depth=6, num_heads=3)
x = torch.randn(2, 3, 64, 64)
print(f"output: {vit(x).shape}")
print(f"params: {sum(p.numel() for p in vit.parameters()):,}")

المتوقع: output: torch.Size([2, 10]) وحوالي 2.8 مليون بارامتر (ViT-B الحقيقي 86M بنفس الكلاس مع dim=768, depth=12, num_heads=12).

إضافة مني: أخطاء شائعة وفين بتظهر في الـ LLMs والـ agents

  • تغيير حجم الصورة بعد التدريب: الـ pos_embed متعلَّم لعدد patches ثابت. لو دخلت صورة بحجم مختلف هيحصل shape mismatch؛ الحل interpolate للـ positional embedding (أو إعادة التدريب). ده أشهر bug في porting (والـ skill بتاع الدرس بيفحصه).
  • نسيان الـ CLS: لو الـ pos_embed شكله (1, N, d) بدل (1, N+1, d) الـ cat هيفشل أو هتضيّع token.
  • Dropout والـ eval: لا تنسَ model.eval() وقت الاختبار.
  • في الـ LLMs متعددة الوسائط: LLaVA وCLIP وغيرهم بيحوّلوا الصورة لـ patch tokens بنفس الطريقة، وبيعدّوها للـ LLM كـ «كلمات»، فكل صورة بتاكل مئات الـ tokens من الـ context. patch size أكبر = tokens أقل = تكلفة أقل.
  • في الـ agents: agent بيقرا screenshots (computer use) بيعدّي الصورة على ViT encoder؛ دقة النص الصغير بتتأثر بحجم الـ patch.
  • نفس الكتلة: الـ block هنا (pre-LN + MSA + MLP) هو بالظبط block الـ GPT. الفرق في الـ masking (causal) والـ tokenisation.

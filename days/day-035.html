المشكلة: نوتبوك شغال… لحد ما يتشحن

عندك notebook بيحمّل الداتا، يملا الـ missing values بالـ median، يعمل scaling، يدرّب موديل ويطبع accuracy. شغال، وشحنته. بعد شهر حد عمل retrain وطلعت نتايج مختلفة. ليه؟ أربع حاجات حصلت مع بعض:

  1. الـ median اتحسب على الداتا كلها ومعاها الـ test (ده data leakage).
  2. بارامترات الـ scaling (المتوسط والانحراف) ما اتحفظتش، فوقت الـ inference اتحسبت بإحصائيات تانية.
  3. كود الـ feature engineering اتنسخ بين التدريب والـ serving، والنسختين بعدوا عن بعض مع الوقت.
  4. عمود categorical ظهرت فيه قيمة جديدة في الـ production الـ encoder عمره ما شافها.

دي مش أمثلة نظرية، دي أشهر أسباب فشل أنظمة الـ ML في الـ production. والحل لكلهم واحد: تحط كل خطوات التحويل في object واحد مرتب وقابل للتكرار.

يعني إيه Pipeline؟

تخيل مطبخ مطعم. الـ notebook زي شيف بيطبخ من دماغه كل مرة. الـ pipeline زي كارت الوصفة: نفس المقادير، نفس الترتيب، ونفس المعايير بالظبط كل مرة، سواء في المطبخ الرئيسي (التدريب) أو في الفرع (الـ production).

بالتعريف: سلسلة مرتبة من تحويلات الداتا وفي آخرها موديل. كل خطوة بتاخد ناتج اللي قبلها. الـ pipeline كله بيتعمله fit مرة واحدة على الـ training data، ووقت الـ inference نفس الـ pipeline المتدرّب بيحوّل الداتا الجديدة ويطلّع predictions.

Raw Data → Impute → Scale → Encode → Model → Prediction

الـ Pipeline بيضمنلك أربع حاجات:

  • • التحويلات بتتعمل fit على الـ training data بس (مفيش leakage).
  • • نفس التحويلات بالظبط بتتطبق وقت الـ inference.
  • • الـ object كله بيتحفظ (serialize) ويتشحن كـ artifact واحد.
  • • الـ cross-validation بتطبّق الـ pipeline جوه كل fold لوحده، فبتقفل أنواع leakage خفية.

الـ Data Leakage: القاتل الصامت

الـ leakage معناه إن معلومة من الـ test set (أو من المستقبل) دخلت في التدريب. زي طالب شاف ورقة الامتحان قبلها: درجته عالية، بس مش عشان فاهم.

scaler = StandardScaler()

مع الـ pipeline مش محتاج تفكر في ده خالص، هو بيعمله لوحده.

معمل ١: داتا عشوائية بـ accuracy «حلوة»

الداتا هنا noise صافي: الـ features عشوائية والـ labels عشوائية، يعني الحقيقة إن مفيش أي موديل يقدر يعدّي 50%. هنختار أحسن k features بالـ correlation مع الـ label، وبعدين نصنّف بـ nearest centroid. الفرق الوحيد: اخترنا الـ features بالنظر للداتا كلها (leaky) ولا للـ train بس (clean)؟

sklearn Pipeline: fit ولا transform؟

الـ Pipeline في sklearn بيربط transformers وفي الآخر estimator، ويديك .fit() و.predict() و.score() بيمشوا على الخطوات بالترتيب.

from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipe = Pipeline([
    ("scaler", StandardScaler()),
    ("model", LogisticRegression()),
])

pipe.fit(X_train, y_train)          # scaler: fit_transform ← model: fit
predictions = pipe.predict(X_test)  # scaler: transform بس ← model: predict
لما تناديكل transformer بيعملالموديل في الآخر بيعمل
pipe.fit(X_train, y_train)fit_transform: يتعلم الإحصائيات ويطبقهاfit على الداتا المتحوّلة
pipe.predict(X_test)transform بس: يطبق اللي اتعلمه، من غير ما يتعلم تانيpredict

تشبيه: fit = إنك تقيس مقاسات الزبون وتكتبها في كشكول. transform = إنك تفصّل بالمقاسات اللي في الكشكول. على الـ test انت بتفصّل بس، عمرك ما تقيس تاني. الـ scaler عمره ما بيشوف الـ test وقت الـ fit، وده كل الفكرة.

معمل ٢: شغّل الـ pipeline خطوة بخطوة

عندك ٦ صفوف train فيها age (فيه قيمة ناقصة)، income، وcity. دوس fit وشوف كل خطوة بتتعلم إيه وبتحفظه. بعدين اختار صف جديد ودوس predict: لاحظ إن كل خطوة بتستخدم المحفوظ، مش بتحسب من الصف الجديد.

جرّب: (١) دوس predict قبل fit. (٢) اختار مدينة جديدة seattle واقفل handle_unknown. (٣) اختار صف فيه age ناقص.

ColumnTransformer: كل نوع عمود ليه معاملة

  
الداتا الحقيقية فيها أعمدة رقمية (محتاجة imputation بالـ median وscaling) وأعمدة categorical (محتاجة imputation بالأكثر تكرارًا وone-hot encoding). الـ ColumnTransformer زي موظف فرز في مكتب بريد: كل جواب يروح للشباك بتاعه، وفي الآخر النتايج بتتلزق جنب بعض في مصفوفة واحدة.

  
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer

numeric_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale", StandardScaler()),
])

categorical_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="most_frequent")),
    ("encode", OneHotEncoder(handle_unknown="ignore")),   # مهم جدًا للـ production
])

preprocessor = ColumnTransformer([
    ("num", numeric_pipe, ["age", "income", "score"]),
    ("cat", categorical_pipe, ["city", "gender", "plan"]),
])

full_pipeline = Pipeline([
    ("preprocess", preprocessor),
    ("model", GradientBoostingClassifier()),
])

  
handle_unknown="ignore" هو اللي بيخلّي الـ encoder لما يشوف مدينة عمره ما شافها يطلّع vector كله أصفار بدل ما يعمل crash. جربتها في المعمل ٢.

  
من الكويز: الحلول المعتادة للقيمة الجديدة هي «bucket» اسمه unknown في الـ one-hot، أو في الـ target encoding ترجع للـ global mean. المهم إن الـ pipeline يكون متوقعها، مش إن السطر يتشال أو تعيد تدريب الموديل.

خطوة ١: داتا مختلطة فيها missing

  
٥٠٠ عميل: age وincome وscore رقمي، وcity وplan categorical. حوالي 5% من الـ age و3% من الـ income متشالين (NaN). الـ target بيعتمد على خليط منهم مع noise.

  
import numpy as np

def make_mixed_data(n_samples=500, seed=42):
    rng = np.random.RandomState(seed)
    age = rng.normal(35, 12, n_samples).clip(18, 80)
    income = rng.lognormal(10.5, 0.8, n_samples)
    score = rng.uniform(300, 850, n_samples)
    city = rng.choice(np.array(["new_york", "chicago", "la", "houston", "phoenix"]), n_samples)
    plan = rng.choice(np.array(["free", "basic", "premium"]), n_samples, p=[0.5, 0.3, 0.2])

    age_m = age.copy();    age_m[rng.random(n_samples) < 0.05] = np.nan     # 5% ناقص
    inc_m = income.copy(); inc_m[rng.random(n_samples) < 0.03] = np.nan     # 3% ناقص

    boundary = (0.01 * (age - 35) + 0.00001 * (income - 40000)
                + 0.002 * (score - 600)
                + 0.5 * (plan == "premium") - 0.3 * (plan == "free")
                + rng.normal(0, 0.5, n_samples))
    target = (boundary > 0).astype(int)
    return {"age": age_m, "income": inc_m, "score": score,
            "city": city, "plan": plan, "target": target}

  
الداتا راجعة كـ dict أعمدة (زي DataFrame بسيط). الأصل بيكتب الـ boundary بـ .astype(float) على شروط الـ plan؛ أنا اختصرتها، والمعنى واحد.


  
خطوة ٢: الـ transformers (كل واحد fit / transform)

  
class MedianImputer:
    def fit(self, X):
        self.medians = np.nanmedian(X, axis=0)     # اتعلم الـ median من غير الـ NaN
        return self
    def transform(self, X):
        X_out = X.copy()
        for col in range(X.shape[1]):
            mask = np.isnan(X_out[:, col])
            X_out[mask, col] = self.medians[col]   # املا بالمحفوظ
        return X_out
    def fit_transform(self, X):
        return self.fit(X).transform(X)

class StandardScaler:
    def fit(self, X):
        self.means = np.nanmean(X, axis=0)
        self.stds = np.nanstd(X, axis=0)
        self.stds[self.stds == 0] = 1.0            # متقسمش على صفر
        return self
    def transform(self, X):
        return (X - self.means) / self.stds
    def fit_transform(self, X):
        return self.fit(X).transform(X)

class OneHotEncoder:
    def __init__(self, handle_unknown="ignore"):
        self.handle_unknown = handle_unknown
    def fit(self, X):
        self.categories = [sorted(set(X[:, c])) for c in range(X.shape[1])]
        return self
    def transform(self, X):
        cols = []
        for c in range(X.shape[1]):
            for cat in self.categories[c]:           # بس الـ categories المحفوظة
                cols.append((X[:, c] == cat).astype(float))
        return np.column_stack(cols) if cols else np.zeros((X.shape[0], 0))
    def fit_transform(self, X):
        return self.fit(X).transform(X)

خطوة ٣: PipelineFromScratch

  
class PipelineFromScratch:
    def __init__(self, steps):
        self.steps = steps                           # [(name, step), ...] والآخر موديل

    def fit(self, X, y=None):
        X_current = X.copy() if isinstance(X, np.ndarray) else X
        for name, step in self.steps[:-1]:
            X_current = step.fit_transform(X_current)   # اتعلم وحوّل
        name, model = self.steps[-1]
        model.fit(X_current, y)
        return self

    def predict(self, X):
        X_current = X.copy() if isinstance(X, np.ndarray) else X
        for name, step in self.steps[:-1]:
            X_current = step.transform(X_current)       # حوّل بس
        name, model = self.steps[-1]
        return model.predict(X_current)

    def score(self, X, y):
        return np.mean(self.predict(X) == y)


  
خطوة ٤: ColumnTransformer و FullPipeline

  
class TransformerPipeline:                           # سلسلة transformers من غير موديل
    def __init__(self, steps):
        self.steps = steps
    def fit(self, X):
        for name, step in self.steps:
            X = step.fit_transform(X)
        return self
    def transform(self, X):
        for name, step in self.steps:
            X = step.transform(X)
        return X
    def fit_transform(self, X):
        return self.fit(X).transform(X)

class ColumnTransformerScratch:
    def __init__(self, transformers):
        self.transformers = transformers             # [(name, pipeline, columns), ...]
    def fit(self, data):
        for name, pipe, cols in self.transformers:
            pipe.fit(np.column_stack([data[c] for c in cols]))
        return self
    def transform(self, data):
        out = [pipe.transform(np.column_stack([data[c] for c in cols]))
               for name, pipe, cols in self.transformers]
        return np.hstack(out)                        # الزق النتايج جنب بعض
    def fit_transform(self, data):
        return self.fit(data).transform(data)

class FullPipeline:
    def __init__(self, model, numeric_cols, categorical_cols):
        self.model = model
        self.numeric_cols, self.categorical_cols = numeric_cols, categorical_cols
        self.num_pipeline = TransformerPipeline([
            ("impute", MedianImputer()), ("scale", StandardScaler())])
        self.cat_encoder = OneHotEncoder(handle_unknown="ignore")

    def _X(self, data, fit):
        X_num = np.column_stack([data[c] for c in self.numeric_cols])
        X_cat = np.column_stack([data[c] for c in self.categorical_cols])
        if fit:
            return np.hstack([self.num_pipeline.fit_transform(X_num),
                              self.cat_encoder.fit_transform(X_cat)])
        return np.hstack([self.num_pipeline.transform(X_num),
                          self.cat_encoder.transform(X_cat)])

    def fit(self, data):
        self.model.fit(self._X(data, fit=True), data["target"])
        return self
    def predict(self, data):
        return self.model.predict(self._X(data, fit=False))
    def score(self, data):
        return np.mean(self.predict(data) == data["target"])

  
الأصل كاتب fit وpredict في FullPipeline كل واحدة لوحدها بالتفصيل؛ أنا جمعت الجزء المشترك في _X عشان تشوف الفرق الوحيد: fit_transform ولا transform. الأصل فيه كمان LogisticRegressionSimple (gradient descent) وDecisionTreeSimple (Gini، thresholds من الـ percentiles) زي اللي بنيتهم في Day 25 وDay 26، وهما اللي بيتحطوا مكان model.


  
خطوة ٥: CV من غير leakage

  
def cross_validate_pipeline(pipeline_factory, data, n_folds=5, seed=42):
    rng = np.random.RandomState(seed)
    n = len(data["target"])
    idx = rng.permutation(n)
    fold_size = n // n_folds
    scores = []
    for fold in range(n_folds):
        val_start = fold * fold_size
        val_end = val_start + fold_size if fold < n_folds - 1 else n
        val_idx = idx[val_start:val_end]
        train_idx = np.concatenate([idx[:val_start], idx[val_end:]])
        train_data = {k: v[train_idx] for k, v in data.items()}
        val_data = {k: v[val_idx] for k, v in data.items()}

        pipe = pipeline_factory()          # pipeline جديد في كل fold!
        pipe.fit(train_data)               # الـ preprocessing بيتعلم من train الـ fold بس
        scores.append(pipe.score(val_data))
    return scores

  
ليه pipeline_factory مش pipeline جاهز؟ عشان كل fold يبدأ نضيف من غير إحصائيات fold قبله.

import pandas as pd
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.model_selection import cross_val_score

data = make_mixed_data(500)
df = pd.DataFrame({k: data[k] for k in ["age", "income", "score", "city", "plan"]})
y = data["target"]

pre = ColumnTransformer([
    ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                      ("scale", StandardScaler())]), ["age", "income", "score"]),
    ("cat", Pipeline([("impute", SimpleImputer(strategy="most_frequent")),
                      ("encode", OneHotEncoder(handle_unknown="ignore", sparse_output=False))]),
     ["city", "plan"]),
])
full_pipe = Pipeline([("preprocess", pre),
                      ("model", GradientBoostingClassifier(n_estimators=100, max_depth=3))])

scores = cross_val_score(full_pipe, df, y, cv=5, scoring="accuracy")
print(f"5-fold CV: {scores.mean():.3f} +/- {scores.std():.3f}")

import joblib                                     # احفظ الـ artifact كله
full_pipe.fit(df, y)
joblib.dump(full_pipe, "pipe.joblib")
same = joblib.load("pipe.joblib")
print((same.predict(df) == full_pipe.predict(df)).all())   # True

  
sparse_output اسمه كده في نسخ sklearn الحديثة (1.2 وبعدها)؛ في النسخ الأقدم كان اسمه sparse. لو طلعلك error في الاسم، ده السبب.

القاعدة الذهبية في سطر

  
أي حاجة بتتعلم رقم من الداتا (median، mean، vocabulary، الـ categories، اختيار features، target encoding) هي جزء من الموديل، ولازم تتعمل fit جوه التدريب بس. لو بتسأل «هل الخطوة دي محتاجة fit؟» والإجابة أيوه، يبقى مكانها جوه الـ pipeline.

  
أخطاء بتحصل كتير

  
    
    
  • • fit_transform على الـ test بالغلط بدل transform. الكود بيشتغل من غير أي error، وده اللي يخليها خطيرة.
    • 
    
  • • Target encoding محسوب على الداتا كلها قبل الـ CV: من أقوى أنواع الـ leakage لأنه بيستخدم الـ target نفسه.
    • 
    
  • • Feature من المستقبل: زي «عدد المرات اللي العميل اشتكى» محسوب لحد النهاردة وانت بتتوقع churn من شهر فات. ده leakage زمني، والـ pipeline لوحده مش هيلقطه (هنرجعله في Day 37).
    • 
    
  • • التقسيم بعد تكرار الصفوف: لو نفس العميل موجود في train وtest، الموديل «حافظه». قسّم بالـ GroupKFold على الـ user id.

  • • الـ tokenizer والـ chat template هما الـ «preprocessing» بتاع الـ LLM. لو عملت fine-tuning بـ template وعملت serving بـ template تاني، ده training/serving skew بالظبط، والموديل بيبوظ بهدوء.

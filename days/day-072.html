المشكلة: الـ labels غالية

ImageNet فيه حوالي 1.3 مليون صورة متعمل لها labels، وتكلفة ده اتقدّرت بحوالي 10 مليون دولار. والداتا الطبية والصناعية أصغر وأغلى. السؤال: ممكن نعمل pretraining على صور كتير من غير labels (فريمات يوتيوب، web crawl، كاميرات، أقمار صناعية) وبعدين نضبط على شوية صور معلّمة؟

ده اللي بيعمله الـ self-supervised learning. ViT متدرّب بالطريقة دي على داتا ضخمة بيوصل لدقة الـ supervised أو يتخطاها بعد الـ fine-tuning، وبينقل أحسن لمهام تانية (detection وsegmentation وdepth). وDINOv2 (Meta، 2023) وMAE (Meta، 2022) هما الاختيارات الافتراضية للـ features القابلة للنقل.

الفكرة الجوهرية: المهمة اللي بنتدرّب عليها (الـ pretext task) مش لازم تكون المهمة اللي عايزينها في الآخر. المهم إنها تجبر الموديل يتعلّم features مفيدة. أمثلة نجحت: تلوين صور رمادية، تصنيف زاوية دوران الصورة، إخفاء patches وإعادة بنائها. التلات اللي بتكبّر كويس هما contrastive وteacher-student وmasked reconstruction.
تشبيه: تخيّل طالب بيتعلّم لغة من غير مدرّس: بيشوف نص فيه كلمات ناقصة ويحاول يكمّلها. محدش قاله «ده معنى الكلمة»، بس عشان يكمّل صح لازم يفهم اللغة. ده الـ pretext task.

التلات عائلات

العائلةأمثلةالفكرة

١) Contrastive (SimCLR)

خد صورة واحدة، طبّق عليها augmentation عشوائي مرتين فتطلع view-ين. مرّرهم على نفس الـ encoder ومعاه projection head. الـ loss بيقول: «embedding الـ view-ين دول لازم يبقوا قريبين، وبعيدين عن embeddings كل الصور التانية في الـ batch».

L(i,j) = −log( exp(sim(zᵢ,zⱼ)/τ) / Σₖ≠ᵢ exp(sim(zᵢ,zₖ)/τ) ) sim = cosine similarity، τ = temperature (0.1 عادةً)

ده الـ InfoNCE. بيحتاج سلبيات كتير لكل positive، فحجم الـ batch بيفرق: SimCLR بيحتاج من 512 لـ 8192. وMoCo حلّها بـ queue من features الـ batches اللي فاتت بحيث عدد السلبيات ميعتمدش على حجم الـ batch.

تشبيه: تخيّل إن عليك تتعرّف على أخوك في زحمة. لو الزحمة 3 ناس بس، تختار صح بسهولة من غير ما تتعلّم أي ملامح مميزة. لو الزحمة ألف، لازم تتعلّم ملامح دقيقة بجد. كتر السلبيات هو اللي بيجبر الموديل يتعلّم.

٢) Teacher-student (DINO)

شبكتين بنفس البنية: student وteacher. الـ teacher هو EMA (متوسط متحرك أسّي) لأوزان الـ student. الاتنين بيشوفوا views مختلفة من الصورة، والـ student بيتدرّب إن مخرجه يطابق مخرج الـ teacher. مفيش سلبيات صريحة.

loss = CE( student(view₁), teacher(view₂) ) + CE( student(view₂), teacher(view₁) )
teacher = m · teacher + (1 − m) · student (m ≈ 0.996)

إزاي مبيتحوّلش لـ «توقّع ثابت دايمًا» (collapse)؟ بحيلتين على مخرج الـ teacher: centring (اطرح متوسط كل بُعد) فمفيش بُعد واحد يسيطر، وsharpening (اقسم على temperature صغيرة) فالمخرج مينزلقش لتوزيع منتظم. الاتنين مع بعض بيمنعوا الـ collapse. DINOv2 هو تكبير DINO على 142 مليون صورة منتقاة، وfeatures بتاعته دلوقتي أقوى حاجة في الـ retrieval والـ dense prediction.

٣) Masked reconstruction (MAE)

اخفي 75% من patches صورة الـ ViT. الـ encoder بيشوف الـ 25% الظاهرين بس. بعده decoder صغير بياخد مخرج الـ encoder ومعاه mask tokens في الأماكن المخفية، ويتدرّب يعيد بناء pixels الـ patches المخفية.

Encoder:  الـ 25% الظاهرين  ->  features
Decoder:  features + mask tokens في الأماكن المخفية  ->  pixels معاد بناؤها
Loss:     MSE بين المعاد بناؤه والأصلي، على الـ patches المخفية بس

تصميمات بتخلّي MAE شغّال:

  • نسبة إخفاء عالية 75%: لو أخفيت قليل، التنبؤ شبه تافه لأن البكسلات المتجاورة مرتبطة جدًا.
  • Encoder/decoder غير متماثلين: الـ encoder الكبير بيشوف الظاهر بس، والـ decoder صغير (8 طبقات، 512 بُعد). النتيجة pretraining أسرع حوالي 3 مرات من BEiT الساذج.
  • هدف في فضاء الـ pixels: أبسط من tokens بتاعة BEiT وبيشتغل أحسن على ViT.

بعد الـ pretraining بنرمي الـ decoder، والـ encoder هو الـ feature extractor.

ليه 75% وBERT بيخفي 15% بس؟

الفرق في كثافة المعلومات. اللغة فيها entropy عالي لكل token: حتى لو أخفيت 15%، كل مكان فيه احتمالات كتير. أما الـ patches فـ entropy منخفض: الجيران غالبًا بيحدّدوا الـ patch المخفي تقريبًا بالظبط. عشان التنبؤ يحتاج فهم دلالي لازم تخفي بشراسة. 75% كفاية إن الاستكمال المكاني البسيط ميحلش المهمة، والـ encoder لازم يمثّل محتوى الصورة.

معمل ١: InfoNCE والـ batch والـ temperature

جرّب بإيدك

المحور الأفقي = N (عدد الأزواج في الـ batch). المنحنى = قيمة الـ loss لو الـ positive له similarity s_pos وكل السلبيات similarity s_neg (تبسيط مني عشان نشوف الشكل). حرّك الـ temperature وشوف الـ loss.

اضبط s_pos = s_neg (يعني الموديل مبيفرقش): هتلاقي الـ loss بتتبع log(2N−1)، وده بالظبط الرقم اللي الكود هيطبعه لـ N=16: حوالي 3.43.

لاحظ: كل ما N يكبر، الـ loss للموديل «الأعمى» بيكبر (log(2N−1))، فبقى الـ loss بيحتاج الموديل يفرّق بين positive وسلبيات أكتر. وبعدها لو الـ positive أقرب فعلًا من السلبيات، المنحنى بيبقى أوطى.

معمل ٣: ليه DINO مبيعملش collapse؟

centring وsharpening

عندنا مخرج teacher من 8 أبعاد، والبُعد الأول (d1) فيه «ميل» ثابت (+3) بيظهر في كل الصور، فبيكسب دايمًا مهما كانت الصورة. الـ centring بيطرح المتوسط الجاري لكل بُعد، فالميل ده بيتشال وتفضل الإشارة الحقيقية. الأعمدة = احتمالات الـ teacher بعد الـ softmax.

  • اضبط centring = 0 وtemperature = 1: بُعد واحد بيسيطر (الـ collapse الأول).
  • زوّد centring: السيطرة بتروح، لأننا بنطرح المتوسط.
  • زوّد temperature لحد 3: المخرج بيقرب لتوزيع منتظم (collapse تاني: كل الأبعاد زي بعض ومفيش معلومة).
  • قلّل temperature لـ 0.2 مع centring كامل: مخرج حاد ومفيد.

خطوة ١: pipeline الـ two-view

import torch
import torchvision.transforms as T

two_view_train = lambda: T.Compose([
    T.RandomResizedCrop(96, scale=(0.2, 1.0)),   # قص عشوائي بين 20% و100% من الصورة
    T.RandomHorizontalFlip(),
    T.ColorJitter(0.4, 0.4, 0.4, 0.1),           # تغيير سطوع/تباين/تشبع/درجة اللون
    T.RandomGrayscale(p=0.2),
    T.ToTensor(),
])

class TwoViewDataset(torch.utils.data.Dataset):
    def __init__(self, base):
        self.base = base
        self.aug = two_view_train()

    def __len__(self):
        return len(self.base)

    def __getitem__(self, i):
        img, _ = self.base[i]                    # بنرمي الـ label، مش محتاجينه
        v1 = self.aug(img)                       # view أول
        v2 = self.aug(img)                       # view تاني من نفس الصورة
        return v1, v2

كل __getitem__ بيرجّع view-ين متغيّرين من نفس الصورة. الـ labels مش محتاجينها.

خطوة ٢: دالة InfoNCE

import torch.nn.functional as F

def info_nce(z1, z2, tau=0.1):
    """z1, z2: (N, D) embeddings متعملها L2-normalise، كل صف زوج views"""
    N, D = z1.shape
    z = torch.cat([z1, z2], dim=0)               # (2N, D) كل الـ views
    sim = z @ z.T / tau                          # (2N, 2N) cosine similarity / tau

    mask = torch.eye(2 * N, dtype=torch.bool, device=z.device)
    sim = sim.masked_fill(mask, float("-inf"))   # الصورة متقارنش بنفسها

    # شريك كل view: i (من الأول) شريكه i+N، والعكس
    targets = torch.cat([torch.arange(N, 2 * N), torch.arange(0, N)]).to(z.device)
    return F.cross_entropy(sim, targets)

لازم تعمل L2-normalise للـ embeddings قبل النداء. tau=0.1 هو الافتراضي في SimCLR، وقيمة أقل بتخلّي الـ loss أحدّ وبتحتاج سلبيات أكتر. الـ masked_fill بـ -inf بيمنع الـ view من مقارنة نفسه.

خطوة ٤: قناع على طريقة MAE

def random_mask_indices(num_patches, mask_ratio=0.75, seed=0):
    g = torch.Generator().manual_seed(seed)
    n_keep = int(num_patches * (1 - mask_ratio))     # 196 * 0.25 = 49 ظاهرين
    perm = torch.randperm(num_patches, generator=g)  # ترتيب عشوائي
    visible = perm[:n_keep]
    masked = perm[n_keep:]
    return visible.sort().values, masked.sort().values

num_patches = 196                                    # صورة 224 مقسومة patches 16x16 = 14x14
visible, masked = random_mask_indices(num_patches, mask_ratio=0.75)
print(f"visible: {len(visible)} / {num_patches}")
print(f"masked:  {len(masked)} / {num_patches}")

بسيط وسريع وثابت لنفس الـ seed. التطبيقات الحقيقية بتعمل ده على batch وبتحتفظ بقناع مختلف لكل عينة.

خطوة ٥: DINO head صغير (من main.py)

class DinoHead(torch.nn.Module):
    """نسخة صغيرة بتوضّح centring + sharpening"""
    def __init__(self, in_dim=64, out_dim=128, momentum=0.9):
        super().__init__()
        self.proj = torch.nn.Linear(in_dim, out_dim)
        self.register_buffer("centre", torch.zeros(out_dim))   # المتوسط الجاري للـ teacher
        self.momentum = momentum

    def student(self, x, temp=0.1):
        return F.log_softmax(self.proj(x) / temp, dim=-1)

    def teacher(self, x, temp=0.04):                          # temp صغيرة = sharpening
        out = self.proj(x)
        return F.softmax((out - self.centre) / temp, dim=-1).detach()   # centring

    @torch.no_grad()
    def update_centre(self, teacher_out):                     # EMA للمتوسط
        self.centre.mul_(self.momentum).add_(teacher_out.mean(dim=0), alpha=1 - self.momentum)

الـ register_buffer بيخزّن الـ centre جوه الموديل من غير ما يبقى parameter بيتدرّب. الـ teacher بيستخدم temperature أصغر (0.04) من الـ student (0.1): ده الـ sharpening.

إضافة مني: أخطاء وفين ده بيظهر في الـ LLMs

  • نسيان الـ L2-normalise: من غيره الـ dot product مش cosine similarity، والـ loss بتتأثر بطول المتجه بدل الاتجاه.
  • Augmentations ضعيفة: لو الـ view-ين شبه بعض جدًا، الموديل بيحل المهمة بحيلة (مثلًا يطابق الألوان) من غير ما يتعلّم حاجة مفيدة. الـ crop العشوائي مع الـ color jitter هما اللي بيمنعوا الحيل دي.
  • الـ collapse صعب يتلاحظ: الـ loss ممكن تنزل جامد والـ embedding كلها نفس المتجه. راقب الـ std للـ embeddings عبر الـ batch.
  • قياس الجودة: الـ loss بتاع الـ pretext مش مقياس جودة. استخدم linear probe على داتا معلّمة.
  • في الـ LLMs: النص بيعمل نفس الفكرة: next-token prediction وmasked language modeling (BERT) هما pretext tasks من غير labels. وCLIP (الدرس الجاي) هو InfoNCE بين صورة ونص. والـ MAE نسخة بصرية من BERT مع فرق نسبة الإخفاء.
  • في الـ agents: embeddings من DINOv2 أو CLIP بتتخزن في vector database لبحث بصري، يعني agent بيدوّر على صور شبه صورة معينة.

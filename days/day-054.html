المشكلة: فريمورك امبارح بطيء جدًا

الفريمورك بتاعك شغال، بس بيعالج sample واحدة في المرة بلوبات Python متداخلة. PyTorch بيبعت نفس العمليات لـ kernels مكتوبة بـ C++/CUDA وشغالة على الـ GPU. الدرس بيقول إنه حوالي ٥٠٠ مرة أسرع على نفس المسألة.

مثال من الدرس: على GPU واحد A100، PyTorch بيدرب ResNet-50 (25.6M parameter) على ImageNet (1.28M صورة) في حوالي ٦ ساعات. فريمورك امبارح كان هياخد حوالي ٣٠٠٠ ساعة، لو ماخلصتش منه الميموري الأول.

والسرعة مش الفرق الوحيد. فريمورك امبارح ناقصه: GPU، autodiff (انت كاتب backward لكل حاجة)، حفظ الموديل (serialization)، distributed training، mixed precision، وأي طريقة تعمل debug للـ gradients غير print.

الخبر الحلو: PyTorch بيحافظ على نفس الـ mental model اللي انت بنيته: Module, forward(), parameters(), backward(), optimizer.step(). المفاهيم بتنتقل واحد لواحد. الفرق إن ورا نفس الواجهة فيه عشر سنين من الـ systems engineering.

ليه PyTorch كسب؟

سنة ٢٠١٥ كان TensorFlow بيطلب منك تعرّف static graph الأول: تبني الجراف، تعمله compile، وبعدين تدخّل الداتا. الـ debug كان إنك تبحلق في رسومات الجراف، وأي تغيير في المعمارية يعني تبني الجراف من الأول.

PyTorch نزل ٢٠١٧ بفكرة تانية: eager execution. تكتب Python وهو يتنفذ فورًا. y = model(x) بتحسب y دلوقتي، مش «ضيف node هتحسب y بعدين». فـ print() اشتغل، وpdb اشتغل، وif/else جوه الـ forward اشتغلت.

التشبيه: الـ static graph زي إنك تكتب وصفة كاملة وتبعتها للمطبخ ومتعرفش غلطت فين غير لما الأكلة تطلع. الـ eager زي إنك واقف في المطبخ بنفسك، بتدوق كل خطوة.

حسب الدرس: نصيب PyTorch في أوراق البحث طلع من 7% (2017) لأكتر من 75% (2022)، وMeta و Google DeepMind و OpenAI و Anthropic و Hugging Face بيستخدموه كفريمورك أساسي. وTensorFlow 2.x نفسه اتحول لـ eager. الدرس: تجربة المطوّر بتتراكم. فريمورك أبطأ ١٠% بس الـ debug فيه أسرع ٥٠% بيكسب.

تغيير الشكل (Reshaping) تقريبًا ببلاش

الـ reshape بيغيّر الـ metadata (الشكل والـ strides)، مش الداتا نفسها في الميموري. يعني الأرقام فاضلة في نفس مكانها، والـ tensor بس بيقرأها بترتيب مختلف.

x = torch.randn(2, 3, 4)
x.view(2, 12)      # (2, 12) لازم الـ tensor يكون contiguous
x.reshape(6, 4)    # (6, 4) بتشتغل دايمًا
x.permute(2, 0, 1) # رتّب الأبعاد من جديد
x.unsqueeze(0)     # زوّد بُعد: (1, 2, 3, 4)
x.squeeze()        # شيل الأبعاد اللي حجمها 1

معمل ٠١: شوف الأرقام وهي بتتقري بترتيب جديد

عندك tensor شكله (2, 3, 4) فيه الأرقام من 0 لـ 23. الصف اللي تحت في الرسمة هو الميموري الحقيقية (storage)، وفوق هو اللي الـ tensor «بيشوفه».

جرّب: اعمل permute وبعدها view. هتلاقي error لأن الـ tensor بقى مش contiguous (الترتيب اللي بيقرأ بيه مش هو ترتيب الميموري). بعدها جرّب reshape: هتشتغل بس هتعمل نسخة جديدة.

لاحظ: view و reshape و unsqueeze على tensor contiguous مش بيغيروا ألوان صف الميموري خالص. ده معنى «constant-time».

Autograd: الـ backward بيكتب نفسه

في فريمورك امبارح كنت لازم تكتب backward() لكل module. PyTorch لأ. هو بيسجّل كل عملية بتحصل على الـ tensors في جراف موجّه من غير دواير (DAG، اسمه computational graph)، وبعدين يمشي فيه بالعكس ويحسب الـ gradients لوحده.

اسمها tape-based autodiff: تخيل شريط كاسيت بيسجّل كل عملية وانت ماشي في الـ forward. لما تنادي .backward() الشريط بيلف بالعكس، وكل عملية بتسلّم الـ gradient للي قبلها.

x = torch.randn(3, requires_grad=True)
y = x ** 2 + 3 * x
z = y.sum()
z.backward()
print(x.grad)  # dz/dx = 2x + 3

القواعد التلاتة

  1. الـ leaf tensors اللي عليها requires_grad=True بس هي اللي بتتجمع فيها gradients (يعني الحاجات اللي انت عملتها بإيدك زي الأوزان، مش النتايج الوسطانية).
  2. الـ gradients بتتجمع فوق بعض by default. عشان كده لازم optimizer.zero_grad() قبل كل backward.
  3. torch.no_grad() بيقفل تسجيل الجراف. استخدمه وقت التقييم.

معمل ٠٢: الشريط وهو بيلف بالعكس

حرّك قيم x. اضغط Forward وشوف القيم ماشية لقدام (أزرق). اضغط Backward وشوف الـ gradients راجعة (برتقالي) لحد ما توصل x.grad = 2x + 3.

بعدين اضغط «forward + backward تاني من غير zero_grad» وشوف الـ grad بيتضاعف. ده القاعدة رقم ٢ بعينك.

nn.Module: نفس اللي بنيته، بزيادات

nn.Module هو الكلاس الأساسي لأي حتة في الشبكة. انت بنيت نفس الفكرة امبارح. نسخة PyTorch بتزوّد: تسجيل الـ parameters أوتوماتيك، اكتشاف الـ modules اللي جوه بعض (recursive)، إدارة الـ device، وحفظ/تحميل بالـ state dict.

import torch.nn as nn

class MLP(nn.Module):
    def __init__(self, input_dim, hidden_dim, output_dim):
        super().__init__()                                # مهم جدًا: من غيره التسجيل مش هيشتغل
        self.layer1 = nn.Linear(input_dim, hidden_dim)    # اتسجلت لوحدها
        self.relu = nn.ReLU()
        self.layer2 = nn.Linear(hidden_dim, output_dim)

    def forward(self, x):
        x = self.layer1(x)
        x = self.relu(x)
        x = self.layer2(x)
        return x

أول ما تحط nn.Module أو nn.Parameter كـ attribute في __init__، PyTorch بيسجله. وmodel.parameters() بتلم كل الـ parameters من كل الطبقات. فمش هتجمع الأوزان بإيدك زي امبارح. تشبيه: زي شنطة سفر فيها شنط أصغر؛ لما تقول «طلّعلي كل الهدوم» بيفتح كل شنطة جوه التانية لوحده.

class MNISTDataset(Dataset):

        self.labels = labels

    def __len__(self):               # عندك كام sample
        return len(self.labels)

    def __getitem__(self, idx):      # هات sample رقم idx

    خطوة ١: نزّل MNIST وفك الملفات

    MNIST عبارة عن ٤ ملفات gzip: صور التدريب (60,000 × 28 × 28)، labels التدريب، صور الاختبار (10,000 × 28 × 28)، و labels الاختبار.

    import torch
import torch.nn as nn
import struct, gzip, urllib.request, os

def download_mnist(path="./mnist_data"):
    base_url = "https://storage.googleapis.com/cvdf-datasets/mnist/"
    files = ["train-images-idx3-ubyte.gz", "train-labels-idx1-ubyte.gz",
             "t10k-images-idx3-ubyte.gz", "t10k-labels-idx1-ubyte.gz"]
    os.makedirs(path, exist_ok=True)
    for f in files:
        filepath = os.path.join(path, f)
        if not os.path.exists(filepath):          # نزّل مرة واحدة بس
            urllib.request.urlretrieve(base_url + f, filepath)

def load_images(filepath):
    with gzip.open(filepath, "rb") as f:
        magic, num, rows, cols = struct.unpack(">IIII", f.read(16))  # header: ٤ أرقام 32-bit
        data = f.read()
        images = torch.frombuffer(bytearray(data), dtype=torch.uint8)
        images = images.reshape(num, rows * cols).float() / 255.0     # فرد الصورة لـ 784 وقيم من 0 لـ 1
    return images

def load_labels(filepath):
    with gzip.open(filepath, "rb") as f:
        magic, num = struct.unpack(">II", f.read(8))
        data = f.read()
        labels = torch.frombuffer(bytearray(data), dtype=torch.uint8).long()  # CrossEntropy عايزة long
    return labels

    class MNISTModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(

    def forward(self, x):

        loss.backward()
        optimizer.step()
        total_loss += loss.item() * images.size(0)   # .item() = رقم Python عادي
        _, predicted = outputs.max(1)                # أعلى logit = التوقع
        correct += predicted.eq(labels).sum().item()
        total += labels.size(0)
    return total_loss / total, correct / total

def evaluate(model, loader, criterion, device):
    model.eval()                                  # dropout مقفول
    total_loss, correct, total = 0, 0, 0
    with torch.no_grad():                         # مفيش جراف = ميموري أقل وأسرع
        for images, labels in loader:
            images, labels = images.to(device), labels.to(device)
            outputs = model(images)
            loss = criterion(outputs, labels)
            total_loss += loss.item() * images.size(0)
            _, predicted = outputs.max(1)
            correct += predicted.eq(labels).sum().item()
            total += labels.size(0)
    return total_loss / total, correct / total

    الحدس اللي يفضل معاك

    PyTorch مش سحر. هو بالظبط فريمورك امبارح + شريط تسجيل (autograd) + محرك سريع (C++/CUDA). لما حاجة تبوظ، اسأل نفسك: «لو كنت كاتبها في فريمورك امبارح، كانت هتبوظ فين؟» غالبًا هتلاقي الإجابة.

    في الـ LLMs والـ Agents: أي موديل PyTorch في Hugging Face transformers هو nn.Module عادي، وملفات الأوزان اللي بتنزلها هي state dict. الـ Transformer مبني من نفس القطع اللي في جدول محطة ٠٤: nn.Embedding و nn.LayerNorm و nn.GELU و nn.Linear. وتدريبه بيستخدم AdamW و bfloat16 و mixed precision. ولما تعمل fine-tuning لموديل أو تشغّل موديل محلي للـ agent بتاعك، نفس الخمس سطور ونفس no_grad و eval() هما اللي شغالين.

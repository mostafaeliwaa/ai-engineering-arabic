المشكلة: لعنة الأبعاد

كل ما تزوّد features، حجم الفضاء بيكبر بشكل أُسّي. النقط بتبقى متفرقة، والمسافات بين النقط بتقرّب من بعض (أقرب جار وأبعد جار تقريبًا نفس المسافة)، والموديل بيحتاج داتا أكتر بكتير عشان يلاقي أنماط حقيقية. الـ features اللي هي noise بتغرّق الـ features المفيدة، والـ overfitting بيبقى هو الطبيعي.

تخيّل بتدوّر على صاحبك في شارع (بُعد واحد): سهل. في ميدان (بُعدين): أصعب. في عمارة ١٠٠ دور (٣ أبعاد): أصعب كتير. ومع 500 بُعد، كل الناس «بعيدين» عن بعض بنفس الدرجة تقريبًا.

الـ feature selection هو العلاج: شيل الـ noise، شيل التكرار، وخلّي الـ features اللي فيها معلومة فعلًا عن الـ target. النتيجة: تدريب أسرع، generalization أحسن، وموديل تقدر تشرحه. الهدف مش إنك تستخدم كل المعلومات المتاحة، الهدف إنك تستخدم المعلومات الصح.

تشبيه: إنت بتختار لاعيبة لفريق. الـ Filter: تقيس سرعة كل لاعب لوحده بساعة. الـ Wrapper: تلعّب تشكيلات مختلفة ماتشات كاملة وتشوف مين بيكسب. الـ Embedded: المدرب بيختار وهو بيدرّب، اللي مش بيلعب بيقعد على الدكة لوحده.

Variance Threshold

أبسط filter. لو feature تقريبًا مش بتتغير بين العينات، يبقى مفيهاش معلومة. feature قيمتها 0.0 في 999 من 1000 عينة؟ الـ variance بتاعها قريبة من الصفر، ومفيش موديل هيقدر يفرّق بيها بين الـ classes. شيلها.

variance(x) = mean( (x − mean(x))² ) drop لو variance < threshold (مثلًا 0.01)

مش بتبص على الـ target خالص. استخدمها كخطوة preprocessing قبل أي حاجة: بتشيل الـ features الميتة ببلاش تقريبًا. بس خد بالك: feature ممكن الـ variance بتاعها عالية وهي noise صافي. يعني الـ variance threshold ضروري بس مش كفاية. (هتشوف ده في المعمل ٣.)

Mutual Information

بيقيس: لو عرفت قيمة الـ feature X، الشك بتاعك في الـ target Y هيقل قد إيه؟

I(X; Y) = Σₓ Σᵧ p(x, y) · log[ p(x, y) / (p(x) · p(y)) ]

لو X وY مستقلين، p(x,y) = p(x)·p(y)، فالـ log بيبقى صفر والـ MI = 0. وكل ما X بتقول عن Y أكتر، الـ MI بيكبر.

الميزة الكبيرة على الـ correlation: بيلقط العلاقات الـ nonlinear. feature ممكن الـ correlation بتاعها مع الـ target صفر، والـ MI عالي، لأن العلاقة تربيعية أو دورية. الـ correlation زي واحد بيدوّر على «خط مستقيم» بس. الـ MI بيسأل: «فيه أي نمط؟».

للـ features المتصلة، بنقسمها لـ bins الأول (histogram). عدد الـ bins بيأثر: قليل = بتضيّع معلومات، كتير = بتزوّد noise. اختيارات مشهورة: √n bins أو قاعدة Sturges (1 + log₂ n).

الخطوات: قسّم X لـ bins ← احسب الـ joint distribution p(x,y) ← احسب الـ MI ← رتّب الـ features ← خد أحسن K.

معمل ٢: الـ correlation عامي، والـ MI شايف

اختار شكل العلاقة بين X وY. الشمال scatter، واليمين نفس الداتا بعد ما اتقسمت لـ bins (كل مربع لونه = عدد النقط فيه، يعني p(x,y)). الـ Pearson r والـ MI بيتحسبوا live على 600 نقطة.

جرب: «linear»: الاتنين عاليين. «quadratic» و«periodic»: الـ r قريب من صفر والـ MI عالي. «noise»: الاتنين قريبين من صفر، بس زوّد الـ bins لـ 30 وشوف الـ MI بيطلع شوية من غير أي علاقة: ده الـ noise بتاع التقدير لما الـ bins تبقى كتير.

RFE وL1 وأهمية الشجر والـ Permutation

Recursive Feature Elimination (RFE)

Wrapper بيستخدم أهمية الـ features في الموديل نفسه عشان يقلّم تدريجيًا:

  1. درّب الموديل على كل الـ features.
  2. رتّبهم بالأهمية (الـ coefficients في الموديلات الـ linear، أو تقليل الـ impurity في الشجر).
  3. شيل الأضعف (واحدة أو أكتر).
  4. كرّر لحد ما يفضل العدد اللي عايزه.

الـ RFE بيشوف التفاعل بين الـ features لأن الموديل بيشوف الباقيين مع بعض. لما تشيل feature، أهمية الباقيين بتتغير (لو شلت واحدة من اتنين متشابهين، التانية أهميتها بتطلع). عشان كده هو أدق من الـ filter. التمن: بتدرّب N − target مرة. 500 feature وعايز 10 = 490 تدريب. تقدر تسرّعه بإنك تشيل أكتر من واحدة كل لفة (مثلًا أضعف 10%).

L1 (Lasso) Regularization

loss = prediction_error + α · Σ |wᵢ|

الـ α بيتحكم في قد إيه بنقلّم: α أكبر = أوزان أكتر بتبقى صفر بالظبط. ليه صفر بالظبط؟ قيد الـ L1 شكله معيّن (diamond) في فضاء الأوزان، والحل الأمثل غالبًا بيقع على ركن من أركانه، والأركان دي فيها وزن أو أكتر = صفر. أما الـ L2 (ridge) فقيده دايرة، الأوزان بتصغر بس نادرًا ما بتوصل صفر.

ده embedded selection: الموديل بيتعلم وهو بيتدرب يتجاهل أنهي features. مميزاته: تدريب واحد، ولو فيه features متشابهة بيختار واحدة ويصفّر الباقي، وموجود في معظم الموديلات الـ linear. عيبه: linear بس، مش بيشوف أهمية nonlinear.

في الكود هتلاقي الـ L1 متطبق بـ soft_threshold: بعد كل خطوة gradient، أي وزن أصغر من lr·α بيتصفّر، والأكبر بيتزق ناحية الصفر بالمقدار ده.

Tree-Based Importance

الشجر بيرتّب الـ features طبيعي: كل split بيقلل الـ impurity (Gini أو entropy للـ classification، variance للـ regression)، والـ features اللي بتعمل تقليل أكبر أهم.

importance(feature_j) = (1/T) · Σ_trees Σ_nodes splitting on j (n_samples · impurity_decrease)

بيلقط العلاقات الـ nonlinear والتفاعلات لوحده. تحذير: متحيّز للـ features اللي فيها قيم unique كتير (high cardinality). عمود ID عشوائي هيبان مهم لأنه بيقسم كل عينة لوحدها تمام. استخدم الـ permutation importance كـ sanity check.

Permutation Importance

  1. درّب الموديل وسجّل الأداء على validation.
  2. لكل feature: اخلط قيمها عشوائيًا (shuffle)، وقيس الأداء نزل قد إيه.
  3. النزول الأكبر = الـ feature أهم.

تشبيه: عايز تعرف لاعب مهم قد إيه؟ خلّيه يلعب وعينه مغمّضة وشوف الفريق اتأثر قد إيه. لو مفرقش، الفريق مش معتمد عليه. بيشتغل مع أي موديل ومش متحيز للـ cardinality، بس بطيء: تقييم كامل لكل feature، ومتكرر كذا مرة عشان الثبات.

import numpy as np

def make_feature_selection_data(n_samples=500, seed=42):
    rng = np.random.RandomState(seed)
    x1 = rng.randn(n_samples)
    x2 = rng.randn(n_samples)
    x3 = rng.randn(n_samples)
    x4 = x1 + 0.1 * rng.randn(n_samples)          # نسخة قريبة من x1
    x5 = x2 + 0.1 * rng.randn(n_samples)          # نسخة قريبة من x2
    informative = np.column_stack([x1, x2, x3, x4, x5])

    correlated = np.column_stack([                # مخلوطين من الـ info + noise
        x1 * 0.9 + 0.1 * rng.randn(n_samples),
        x2 * 0.8 + 0.2 * rng.randn(n_samples),
        x3 * 0.7 + 0.3 * rng.randn(n_samples),
        x1 * 0.5 + x2 * 0.5 + 0.1 * rng.randn(n_samples),
        x2 * 0.6 + x3 * 0.4 + 0.1 * rng.randn(n_samples),
    ])

    noise = rng.randn(n_samples, 10) * 0.5        # 10 features ملهاش أي علاقة

    X = np.hstack([informative, correlated, noise])
    # الـ target معمول من x1 وx2 وx3 بس
    y = (2 * x1 - 1.5 * x2 + x3 + 0.5 * rng.randn(n_samples) > 0).astype(int)

    feature_names = (
        [f"info_{i}" for i in range(5)]
        + [f"corr_{i}" for i in range(5)]
        + [f"noise_{i}" for i in range(10)]
    )
    return X, y, feature_names

def variance_threshold(X, threshold=0.01):
    variances = np.var(X, axis=0)
    mask = variances > threshold      # True = الـ feature فضلت
    return mask, variances

خطوة ٣: Mutual information بالـ bins

def discretize(x, n_bins=10):
    min_val, max_val = x.min(), x.max()
    if max_val == min_val:
        return np.zeros_like(x, dtype=int)
    bin_edges = np.linspace(min_val, max_val, n_bins + 1)
    binned = np.digitize(x, bin_edges[1:-1])     # رقم الـ bin لكل قيمة
    return binned


def mutual_information(X, y, n_bins=10):
    n_samples, n_features = X.shape
    mi_scores = np.zeros(n_features)
    y_vals, y_counts = np.unique(y, return_counts=True)
    p_y = y_counts / n_samples                     # p(y)
    for f in range(n_features):
        x_binned = discretize(X[:, f], n_bins)
        x_vals, x_counts = np.unique(x_binned, return_counts=True)
        p_x = dict(zip(x_vals, x_counts / n_samples))   # p(x)
        mi = 0.0
        for xv in x_vals:
            for yi, yv in enumerate(y_vals):
                joint_mask = (x_binned == xv) & (y == yv)
                p_xy = np.sum(joint_mask) / n_samples   # p(x, y)
                if p_xy > 0:
                    mi += p_xy * np.log(p_xy / (p_x[xv] * p_y[yi]))
        mi_scores[f] = mi
    return mi_scores

خطوة ٤: RFE

def simple_logistic_importance(X, y, lr=0.1, epochs=100):
    n_samples, n_features = X.shape
    w = np.zeros(n_features)
    b = 0.0
    for _ in range(epochs):
        z = X @ w + b
        pred = 1.0 / (1.0 + np.exp(-np.clip(z, -500, 500)))
        error = pred - y
        w -= lr * (X.T @ error) / n_samples
        b -= lr * np.mean(error)
    return w, b


def rfe(X, y, n_features_to_select=5, lr=0.1, epochs=100):
    n_total = X.shape[1]
    remaining = list(range(n_total))
    rankings = np.ones(n_total, dtype=int)
    rank = n_total
    while len(remaining) > n_features_to_select:
        X_subset = X[:, remaining]
        w, _ = simple_logistic_importance(X_subset, y, lr, epochs)   # درّب على اللي فاضل
        importances = np.abs(w)
        least_idx = np.argmin(importances)                           # الأضعف
        original_idx = remaining[least_idx]
        rankings[original_idx] = rank          # اللي بيتشال الأول بياخد أسوأ rank
        rank -= 1
        remaining.pop(least_idx)
    for idx in remaining:
        rankings[idx] = 1
    selected_mask = rankings == 1
    return selected_mask, rankings

ملحوظة: الـ |w| كمقياس أهمية بيبقى له معنى بس لو الـ features متعملها scaling، وعشان كده الملف بيعمل standardization قبل الـ RFE والـ L1.

خطوة ٥: L1 بالـ soft-thresholding

def soft_threshold(w, alpha):
    # زقّ ناحية الصفر بمقدار alpha، واللي أصغر منه يبقى صفر بالظبط
    return np.sign(w) * np.maximum(np.abs(w) - alpha, 0)


def l1_feature_selection(X, y, alpha=0.1, lr=0.01, epochs=500):
    n_samples, n_features = X.shape
    w = np.zeros(n_features)
    b = 0.0
    for _ in range(epochs):
        z = X @ w + b
        pred = 1.0 / (1.0 + np.exp(-np.clip(z, -500, 500)))
        error = pred - y
        gradient_w = (X.T @ error) / n_samples
        gradient_b = np.mean(error)
        w -= lr * gradient_w                 # خطوة gradient عادية
        w = soft_threshold(w, lr * alpha)    # وبعدين عقوبة الـ L1
        b -= lr * gradient_b                 # الـ bias مش بيتعاقب
    selected_mask = np.abs(w) > 1e-6
    return selected_mask, w

خطوة ٦: أهمية الشجر

def gini_impurity(y):
    if len(y) == 0:
        return 0.0
    classes, counts = np.unique(y, return_counts=True)
    probs = counts / len(y)
    return 1.0 - np.sum(probs ** 2)


def best_split(X, y, feature_idx):
    values = np.unique(X[:, feature_idx])
    if len(values) <= 1:
        return None, -1.0
    best_threshold = None
    best_gain = -1.0
    parent_gini = gini_impurity(y)
    n = len(y)
    for i in range(len(values) - 1):
        threshold = (values[i] + values[i + 1]) / 2.0
        left_mask = X[:, feature_idx] <= threshold
        right_mask = ~left_mask
        n_left = np.sum(left_mask)
        n_right = np.sum(right_mask)
        if n_left == 0 or n_right == 0:
            continue
        gain = (parent_gini
                - (n_left / n) * gini_impurity(y[left_mask])
                - (n_right / n) * gini_impurity(y[right_mask]))
        if gain > best_gain:
            best_gain = gain
            best_threshold = threshold
    return best_threshold, best_gain


def _build_tree_importance(X, y, feature_subset, max_depth, depth=0):
    n_features = X.shape[1]
    importances = np.zeros(n_features)
    if depth >= max_depth or len(np.unique(y)) <= 1 or len(y) < 4:
        return importances
    best_feature, best_threshold, best_gain = None, None, -1.0
    for f in feature_subset:
        threshold, gain = best_split(X, y, f)
        if gain > best_gain:
            best_gain, best_feature, best_threshold = gain, f, threshold
    if best_feature is None or best_gain <= 0:
        return importances
    importances[best_feature] += best_gain * len(y)       # gain × عدد العينات
    left_mask = X[:, best_feature] <= best_threshold
    right_mask = ~left_mask
    importances += _build_tree_importance(X[left_mask], y[left_mask], feature_subset, max_depth, depth + 1)
    importances += _build_tree_importance(X[right_mask], y[right_mask], feature_subset, max_depth, depth + 1)
    return importances


def tree_importance(X, y, n_trees=50, max_depth=5, seed=42):
    rng = np.random.RandomState(seed)
    n_samples, n_features = X.shape
    importances = np.zeros(n_features)
    for _ in range(n_trees):
        sample_idx = rng.choice(n_samples, size=n_samples, replace=True)    # bootstrap
        feature_subset = rng.choice(n_features, size=max(1, int(np.sqrt(n_features))), replace=False)
        importances += _build_tree_importance(X[sample_idx], y[sample_idx], feature_subset, max_depth)
    total = importances.sum()
    if total > 0:
        importances /= total             # مجموعهم = 1
    return importances

def evaluate_accuracy(X, y, selected_mask, lr=0.1, epochs=200):
    X_selected = X[:, selected_mask]
    split = int(0.8 * len(y))
    X_train, X_test = X_selected[:split], X_selected[split:]
    y_train, y_test = y[:split], y[split:]

    preds = (1.0 / (1.0 + np.exp(-np.clip(z, -500, 500))) >= 0.5).astype(int)

التمارين

اعمل ٣ على الأقل.

  1. Forward selection: عكس الـ RFE. ابدأ من صفر features، وكل خطوة ضيف الـ feature اللي بتحسّن الأداء أكتر حاجة، ووقف لما الإضافة متفرقش. قارن باللي اختاره الـ RFE. مين أسرع؟ ومين أحسن؟
    تلميحloop خارجي على عدد الخطوات، وجوه loop على كل feature مش مختارة: درّب بالمختارين + هي وقيس على validation. خد الأحسن. وقف لو التحسن أقل من 0.005 مثلًا. هنا محتاج تدريبات كتير في الأول وقليلة في الآخر لو هتختار عدد صغير، فغالبًا أسرع من RFE لما الـ target صغير.
  2. Stability selection: شغّل L1 خمسين مرة، كل مرة على 80% عشوائية من الداتا وبـ α مختلفة شوية. عدّ كل feature اتختارت كام مرة. اللي اتختار في أكتر من 80% من المرات «stable». قارن بتشغيل L1 مرة واحدة. أنهي أوثق؟
    تلميحalpha = 0.05 * rng.uniform(0.5, 1.5) وidx = rng.choice(n, int(0.8*n), replace=False). خزّن counts += mask. غالبًا الـ noise اللي اتختار بالصدفة في تشغيلة واحدة هيختفي، والـ features المتشابهة هتبان بنسب متوسطة (مرة دي ومرة دي).
  3. Multicollinearity: احسب الـ correlation matrix. اعمل دالة تاخد threshold (مثلًا 0.9) وتشيل واحدة من كل زوج correlation بتاعه عالي، وتسيب اللي الـ MI بتاعها مع الـ target أعلى. جرّبها واتأكد إنها بتشيل المكرر.
    تلميحC = np.corrcoef(X, rowvar=False). لف على i < j ولو |C[i,j]| > 0.9 شيل اللي الـ MI بتاعه أقل. المفروض info_3/info_0 وinfo_4/info_1 يطلعوا، وغالبًا corr_0 مع info_0.
  4. Pipeline: اربط variance threshold ← خلّي أعلى 50% بالـ MI ← RFE على اللي فضلوا. قارن بالـ RFE لوحده على كل الـ features. أسرع؟ نفس الدقة؟
    تلميحبعد الـ variance (20) والـ MI (10)، الـ RFE هيعمل 5 تدريبات بدل 15. قيس بـ time.perf_counter(). لو الـ MI شال feature مهمة بس تفاعلها مع غيرها هو المهم، الـ pipeline ممكن يخسر شوية دقة.
  5. Permutation importance من الصفر: لكل feature، اخلطها 10 مرات وقيس متوسط النزول في الـ F1. قارن الترتيب بأهمية الشجر. لاقي حالات بيختلفوا فيها واشرح ليه (تلميح الدرس: الـ features المتشابهة).
    تلميحاخلط عمود واحد في نسخة من الـ validation: Xp[:, j] = rng.permutation(Xp[:, j]). الـ features المتشابهة: لو خلطت info_0 والموديل عنده info_3، النزول بيبقى صغير، فالاتنين يبانوا «مش مهمين». الشجر ممكن يقسم الأهمية بينهم بس يديهم الاتنين أهمية. شفت ده في المعمل ٣.
  6. إضافة مني · features لـ LLM router: عندك نظام بيقرر لكل request يبعته لموديل رخيص ولا غالي. سجّلت 40 feature لكل request (طول الـ prompt، فيه code ولا لأ، عدد الأسئلة، لغة، عدد الـ tools المطلوبة، و30 feature تانية أغلبها noise)، والـ label هو «الموديل الرخيص كان كفاية؟». اعمل داتا صناعية بالشكل ده، وطبّق variance ← MI ← L1، وقارن الدقة بـ 40 feature وبالمختارين. وفكّر: كل feature ليها تمن حساب وقت الـ request، فأنهي features تستاهل؟
    تلميحخلّي الـ label معتمد على 4 features بس (مثلًا طول + فيه code + عدد tools + تفاعل بين الطول والـ code). الـ L1 مش هيشوف التفاعل لو مضفتهوش كـ feature، بس الـ MI أو الشجر ممكن. الحساب في الـ production جزء من القرار: feature بتحتاج call لموديل تاني عشان تتحسب غالية حتى لو مفيدة شوية.

إضافة مني: اللي الدرس مقالوش صريح

الحدس في جملة

كل feature زيادة هي «فرصة» للموديل يلاقي نمط بالصدفة في داتا التدريب. مع 10 features noise، احتمال إن واحدة منهم «تبان» مفيدة في 400 عينة مش صغير. الـ feature selection بيقلل الفرص دي.

أخطاء بتحصل كتير

  • • Selection على الداتا كلها قبل الـ CV: مع features كتير noise، هتلاقي features «بتتنبأ» بالـ test بالصدفة، والـ CV score هيطلع متفائل جدًا. حط الـ selection جوه الـ Pipeline (Day 35) عشان يتعمل جوه كل fold.
  • • مقارنة |w| من غير scaling: feature بالآلاف هياخد وزن صغير حتى لو مهم. اعمل standardization الأول (الملف بيعمل كده).
  • • «الـ feature وزنها صفر في الـ L1، يبقى ملهاش علاقة»: مش لازم. ممكن تكون مرتبطة بـ feature تانية خدت الوزن مكانها. نفس الكلام في الـ permutation importance.
  • • الثقة في أهمية الشجر لعمود ID أو timestamp: high cardinality = أهمية مزيفة. ومن Day 37: الـ timestamp كمان ممكن يبقى leakage.
  • • الـ MI بـ bins كتير على داتا قليلة: بيدّي قيم موجبة للـ noise (شفته في المعمل ٢). قارن دايمًا بـ baseline: الـ MI بتاع نفس الـ feature بعد ما تخلط الـ target.

بيظهر فين في الـ LLMs والـ Agents؟

  • • اختيار الـ context: في الـ RAG، حشو الـ prompt بـ chunks كتير مش مرتبطة ممكن يشتّت الموديل زي ما الـ noise features بتشتّت الـ classifier. ترتيب الـ chunks واختيار أحسن k (reranking) فكرته قريبة من الـ filter methods.
  • • اختيار الـ tools للـ agent: agent عنده 100 tool في الـ prompt بيصرف tokens ويحتار أكتر. أنظمة كتير بتعمل «tool retrieval» تختار الأقرب للطلب بس قبل ما تبعت للموديل.
  • • تقليل الأبعاد في الـ embeddings: المسافات في الأبعاد العالية (المعمل ١) سبب إن البحث بالـ embeddings بيستخدم cosine similarity وطرق ANN مخصوصة بدل المسافة العادية بس. هنشوف ده في الـ RAG.
  • • الـ L1 والـ sparsity: نفس فكرة «عقوبة تخلّي أغلب الأرقام صفر» بتتستخدم في الـ interpretability لما الباحثين بيحاولوا يلاقوا features قليلة جوه الـ activations بتاعة الموديل.

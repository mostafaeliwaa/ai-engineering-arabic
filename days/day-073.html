الجزء ١ · CLIP: المشكلة وفكرة البرج المزدوج

الـ classifier العادي closed-vocabulary: موديل ImageNet بـ 1000 class مش هيقول غير واحدة من الـ 1000 دي. أي فئة جديدة = داتا جديدة وتدريب جديد.

CLIP (OpenAI، 2021) اتدرّب على 400 مليون زوج (صورة، caption) من الويب، وبقى يصنّف لأي مجموعة فئات بتوصفها بجملة وقت الاستخدام. ده الـ zero-shot transfer. وعشان كده كل نظام رؤية حديث بيبدأ بـ checkpoint من عيلة CLIP: الـ detection (Grounding DINO، OWL-ViT)، والـ segmentation (CLIPSeg)، والـ retrieval، والـ moderation، والـ VLMs، وتوليد الصور.

برجين (two towers)

encoder للصور (مثلًا ViT-L/14) وencoder للنص (transformer). كل واحد بيخلّص بـ linear projection لنفس البُعد (512 لـ CLIP-B/32، و1024 لـ CLIP-L/14). بنعمل L2-normalise ونحسب cosine similarity.

تشبيه: تخيّل مكتبة فيها مترجمين: واحد بيحوّل أي صورة لإحداثيات على خريطة، وواحد بيحوّل أي جملة لإحداثيات على نفس الخريطة. التدريب بيخلّي «صورة كلب» و«a photo of a dog» يقعوا على نفس النقطة. بعدها أي مهمة صورة+نص بقت مسألة قياس مسافة.

الـ objective

لباتش من N زوج، نبني مصفوفة تشابه N×N. القطر = الأزواج الصح (عايزينه عالي)، وخارج القطر = أزواج غلط (عايزينه واطي).

sim = image_emb @ text_emb.T / τ
loss_i2t = CE(sim, arange(N)) loss_t2i = CE(simᵀ, arange(N)) loss = (loss_i2t + loss_t2i) / 2

الـ loss متماثل لأننا عايزين الاتجاهين يشتغلوا: بحث بالنص عن صورة وبحث بالصورة عن نص. الـ τ (temperature) متعلَّمة كـ scalar وبتبدأ من 0.07.

SigLIP: loss أحسن

SigLIP (Zhai et al., 2023) بدّل الـ softmax بـ sigmoid لكل زوج:

loss = mean over pairs of log(1 + exp(−yᵢⱼ · simᵢⱼ)) y = +1 للزوج الصح، −1 لغيره

الـ loss لكل زوج لوحده بيشيل التطبيع على مستوى الـ batch اللي CLIP محتاجه، فـ SigLIP بيتدرّب كويس على batches أصغر وبيساوي CLIP أو بيتفوق عليه بنفس الداتا.

02

معمل ١: مصفوفة التشابه والـ loss

شوف القطر وهو بيظهر

الخريطة = احتمال كل صورة (صف) تتطابق مع كل نص (عمود) بعد الـ softmax على الصف. حرّك «جودة التدريب» من 0 لـ 1 وشوف القطر بيسيطر. وحرّك الـ logit_scale وشوف القيم بتحدّ.

على جودة 0 الـ loss قريبة من log(N) = log(6) ≈ 1.79، ده نفس منطق «الـ loss لموديل عشوائي ≈ log(N)» في الكود (log(8) = 2.08 للباتش 8). الأرقام هنا توضيحية (تشابه مصطنع).

لاحظ: الـ loss صغير لما القطر عالي، لكن لو الـ scale كبير جدًا والجودة ضعيفة، الموديل بيبقى «واثق وغلطان»، ولذلك التدريب بيبقى حساس.
03

Zero-shot classification: خمس خطوات

  1. اكتب prompt لكل class: "a photo of a {class}".
  2. شفّر كل الـ prompts بالـ text encoder: T شكلها (C, d).
  3. شفّر الصورة: I شكلها (1, d).
  4. التشابه = I @ Tᵀ شكلها (1, C).
  5. الـ argmax = الـ class المتوقع.

الـ prompt engineering مهم: OpenAI نشرت 80 template لـ ImageNet ("a photo of a {}"، "a blurry photo of a {}"، "a sketch of a {}"...). متوسط embeddings كل الـ templates لكل class بيدّي 1-3% زيادة في top-1، لأن كل template بيضيء جانب مختلف، والمتوسط بيدّيك «مركز» أنعم وأقوى للمفهوم.

معمل ٢: من التشابه للاحتمال

أربع classes وتشابه الصورة مع كل prompt (أرقام توضيحية). الصورة أقرب لـ dog. غيّر الـ logit_scale وشوف الـ softmax بيحوّل فروق صغيرة في cosine لاحتمالات. وغيّر «تشابه cat» وشوف الإجابة بتتغير لما الفرق يصغر.

ملاحظة: في الكود الحقيقي الـ scale = 100 (100.0 * image_features @ text_features.T). من غيره، فروق cosine الصغيرة (مثلًا 0.30 مقابل 0.25) هتدّيك احتمالات متقاربة جدًا.
04

CLIP بيظهر فين في ٢٠٢٦

  • Zero-shot classification: استخدام مباشر.
  • Image retrieval: شفّر كل الصور مرة واحدة، وشفّر الـ query وقت الطلب.
  • Text-conditioned detection: Grounding DINO وOWL-ViT بيلفّوا text tower حوالين detector.
  • Text-conditioned segmentation: CLIPSeg.
  • VLMs: LLaVA وQwen-VL وInternVL بيوصّلوا vision encoder من عيلة CLIP بـ LLM.
  • Text-to-image: Stable Diffusion وDALL-E 3 بيشتغلوا على CLIP text embeddings.

الفرق بين الأسماء: CLIP = الأصل (OpenAI). OpenCLIP = إعادة تدريب مجتمعية على LAION، الافتراضي للـ open source. SigLIP = نفس الفكرة بـ sigmoid loss، مفضّل للشغل الجديد (google/siglip-base-patch16-224 على Hugging Face). VLM (LLaVA وأخواتها) = encoder من عيلة CLIP + LLM بيجاوب أسئلة عن الصورة.

ليه VLMs بتستخدم CLIP مش ResNet اتدرّب على ImageNet؟ لأن features CLIP اتدرّبت قصاد نص، فمخرجاتها في فضاء الـ LLM يقدر يستهلكه بتكييف قليل (projection صغير). أما ResNet الـ supervised فمعندوش أي علاقة بتركيب اللغة ومحتاج طبقات ربط تقيلة.

خطوة ١: برجين صغيرين

CLIP الحقيقي هو ViT + transformer. هنا الأبراج MLPs صغيرة فوق features جاهزة عشان إشارة التدريب تبان على CPU:

import torch
import torch.nn as nn
import torch.nn.functional as F

class TwoTower(nn.Module):
    def __init__(self, img_in=128, txt_in=64, emb=64):
        super().__init__()
        self.image_proj = nn.Sequential(nn.Linear(img_in, 128), nn.ReLU(), nn.Linear(128, emb))
        self.text_proj = nn.Sequential(nn.Linear(txt_in, 128), nn.ReLU(), nn.Linear(128, emb))
        self.logit_scale = nn.Parameter(torch.ones([]) * 2.6592)   # ln(1/0.07)، بتتعلّم

    def forward(self, img_feats, txt_feats):
        i = F.normalize(self.image_proj(img_feats), dim=-1)        # L2-normalise
        t = F.normalize(self.text_proj(txt_feats), dim=-1)
        return i, t, self.logit_scale.exp()                        # exp عشان تبقى موجبة

خطوة ٢: الـ contrastive loss

def clip_loss(image_emb, text_emb, logit_scale):
    N = image_emb.size(0)
    sim = logit_scale * image_emb @ text_emb.T       # مصفوفة N x N
    targets = torch.arange(N, device=sim.device)     # القطر = الأزواج الصح
    l_i = F.cross_entropy(sim, targets)              # صورة -> نص
    l_t = F.cross_entropy(sim.T, targets)            # نص -> صورة
    return (l_i + l_t) / 2

logit_scale أكبر = softmax أحدّ، يعني ثقة أعلى لكن خطر عدم استقرار.

خطوة ٣: الـ zero-shot classifier

@torch.no_grad()
def zero_shot_classify(model, image_feats, class_text_feats, class_names):
    """image_feats: (N, img_in)   class_text_feats: (C, txt_in) واحد لكل class"""
    i = F.normalize(model.image_proj(image_feats), dim=-1)
    t = F.normalize(model.text_proj(class_text_feats), dim=-1)
    sim = i @ t.T                                    # (N, C)
    pred = sim.argmax(dim=-1)                        # أقرب class لكل صورة
    return [class_names[p] for p in pred.tolist()]

ده نفس الإجراء بالظبط مع checkpoint حقيقي.

import open_clip
import torch
from PIL import Image

model, _, preprocess = open_clip.create_model_and_transforms("ViT-B-32", pretrained="laion2b_s34b_b79k")
tokenizer = open_clip.get_tokenizer("ViT-B-32")

    text_features = model.encode_text(text)
    image_features = image_features / image_features.norm(dim=-1, keepdim=True)

print(probs)

الجزء ٢ · OCR وفهم المستندات: التلات طبقات

صور فيها نص في كل مكان: فواتير، هويات، كتب ممسوحة، فورمات، سبورات، لوحات، لقطات شاشة. استخراج بيانات منظّمة منها (مش بس الحروف، لكن «ده الإجمالي») من أعلى المشاكل قيمة في الـ vision التطبيقي. والمجال بيتقسم لتلات طبقات:

الطبقةبتعمل إيهمثال
١. OCRبكسلات ← نص"Total 42.50"
٢. Layout parsingتجميع النص في مناطق (عنوان، فقرة، جدول، هامش)Title / Table / Footnote
٣. Document understandingاستخراج حقول منظّمةinvoice_total = $42.50

لكل طبقة طرق كلاسيكية وحديثة، والفجوة بين «عايز النص من الصورة» و«عايز إجمالي الفاتورة» أكبر مما أغلب الفرق بتتوقع.

الـ pipeline الكلاسيكي

  • Text detection (DB، EAST، CRAFT): مضلعات لكل سطر أو كلمة.
  • Recognition: قص كل منطقة لارتفاع ثابت، وشغّل CNN + BiLSTM + CTC فيطلع تسلسل حروف.
  • Layout: إعادة ترتيب القراءة (فوق لتحت ويسار ليمين في اللاتيني، مختلف في العربي والياباني).

والتفاصيل: الـ detector بيطلّع box لكل سطر، بعدين crop لكل منطقة وبعدين الـ recognizer يطلّع نص، وأخيرًا ترتيب القراءة.

CTC في فقرة

الـ recognition بيطلّع تسلسل متغيّر الطول من feature map ثابتة الطول. CTC (Graves et al., 2006) بيخليك تدرّب من غير ما تعرف أنهي عمود ينتمي لأنهي حرف. الموديل بيطلّع توزيع على (vocab + blank) في كل خطوة زمنية، والـ CTC loss بيجمع على كل المحاذاات اللي بتتحوّل للنص الهدف بعد دمج المتكرر وشيل الـ blank.

raw output:  h h h _ _ e e l l _ l l o _ _
بعد الدمج وشيل الـ blank:  hello

الـ blank هو اللي بيخلّي الحروف المزدوجة تتكتب: الـ «ll» في hello لازم يبقى بينهم blank (l _ l)، وإلا الدمج هيحوّلهم لـ «l» واحد. وبسبب CTC اشتغل CRNN في 2015 وما زال بيدرّب أغلب موديلات OCR الإنتاجية.

معمل ٣: ألعب بالـ CTC

ادمج المتكرر وشيل الـ blank

اكتب تسلسل خام (الحروف بينها مسافات و_ هو الـ blank) وشوف الـ decoder بيعمل إيه خطوة خطوة. جرّب preset «hello من غير blank» وشوف إزاي الـ «ll» بتتحوّل لـ «l» واحد، وده سبب وجود الـ blank.

لاحظ: التسلسل الخام أطول من النص. كل حرف بياخد غالبًا أكتر من عمود، والـ blank بيفصل بين الحروف المتكررة.

الموديلات الحديثة، والـ layout، والمقاييس

  • Donut (Kim et al., 2022): ViT encoder + text decoder؛ بيقرا الصورة ويطلّع JSON مباشرة. من غير text detector ولا layout module.
  • TrOCR: ViT + transformer decoder لـ OCR على مستوى السطر.
  • Qwen-VL-OCR / InternVL: vision-language models متظبّطة لـ OCR، الأدق في 2026 على المستندات المعقدة.
  • PaddleOCR: pipeline كلاسيكي (DB + CRNN) في حزمة ناضجة، حصان الشغل في الـ open source.

الموديلات end-to-end بتحتاج داتا وحوسبة أكتر، لكنها بتتخطّى تراكم الأخطاء في pipeline متعدد المراحل.

خطوة ١: CTC loss وgreedy decoder

import torch
import torch.nn.functional as F

def ctc_loss(log_probs, targets, input_lengths, target_lengths, blank=0):
    """log_probs: (T, N, C) log-softmax، الـ blank على index 0"""
    return F.ctc_loss(log_probs, targets, input_lengths, target_lengths,
                      blank=blank, reduction="mean", zero_infinity=True)

def greedy_ctc_decode(log_probs, blank=0):
    preds = log_probs.argmax(dim=-1).transpose(0, 1).cpu().tolist()   # أعلى class في كل خطوة
    out = []
    for seq in preds:
        decoded, prev = [], None
        for idx in seq:
            if idx != prev and idx != blank:      # ادمج المتكرر وشيل الـ blank
                decoded.append(idx)
            prev = idx
        out.append(decoded)
    return out

الـ F.ctc_loss بيستخدم CuDNN لو متاح. الـ greedy decoder أبسط من beam search وغالبًا في حدود 1% CER منه.

خطوة ٢: TinyCRNN

import torch.nn as nn

class TinyCRNN(nn.Module):
    def __init__(self, vocab_size=40, hidden=128, feat=32):
        super().__init__()
        self.cnn = nn.Sequential(
            nn.Conv2d(1, feat, 3, 1, 1), nn.BatchNorm2d(feat), nn.ReLU(inplace=True),
            nn.MaxPool2d(2),
            nn.Conv2d(feat, feat * 2, 3, 1, 1), nn.BatchNorm2d(feat * 2), nn.ReLU(inplace=True),
            nn.MaxPool2d(2),
            nn.Conv2d(feat * 2, feat * 4, 3, 1, 1), nn.BatchNorm2d(feat * 4), nn.ReLU(inplace=True),
            nn.MaxPool2d((2, 1)),                 # بنصغّر الارتفاع بس، العرض = الزمن
            nn.Conv2d(feat * 4, feat * 4, 3, 1, 1), nn.BatchNorm2d(feat * 4), nn.ReLU(inplace=True),
            nn.MaxPool2d((2, 1)),
        )
        self.rnn = nn.LSTM(feat * 4, hidden, bidirectional=True, batch_first=True)
        self.head = nn.Linear(hidden * 2, vocab_size)

    def forward(self, x):                         # x: (N, 1, H, W)
        f = self.cnn(x)                           # (N, C, H', W')
        f = f.mean(dim=2).transpose(1, 2)         # (N, W', C) الارتفاع اتلخّص
        h, _ = self.rnn(f)
        return F.log_softmax(self.head(h).transpose(0, 1), dim=-1)   # (W', N, vocab)

الإدخال بارتفاع ثابت (الـ CNN بيصغّر الارتفاع لـ 1) والعرض هو بُعد الزمن للـ CTC.

كل حرف عمود من 6 خطوط بتكتب رقم الحرف بالـ binary. ليه؟ لو كل الحروف صندوق فاضي نفس الشكل، الموديل مش هيعرف يفرّق a من x، والـ loss هتفضل واقفة.

import numpy as np

GLYPHS = "0123456789abcdefghijklmnopqrstuvwxyz"

def synthetic_line(text, height=32, char_width=16):
    W = char_width * len(text)
    img = np.ones((height, W), dtype=np.float32)       # خلفية بيضا
    for i, c in enumerate(text):
        x = i * char_width
        code = GLYPHS.find(c) + 1                      # رقم الحرف
        for bit in range(6):                           # الحرف = 6 خطوط (binary)
            if code >> bit & 1:
                y = 4 + 4 * bit
                img[y:y + 3, x + 2:x + char_width - 2] = 0.0
    return img

def build_batch(strings, vocab):
    H = 32
    W = 16 * max(len(s) for s in strings)
    imgs = np.ones((len(strings), 1, H, W), dtype=np.float32)
    target_lengths, targets = [], []
    for i, s in enumerate(strings):
        imgs[i, 0, :, :16 * len(s)] = synthetic_line(s)
        ids = [vocab.index(c) for c in s]
        targets.extend(ids)
        target_lengths.append(len(ids))
    return torch.from_numpy(imgs), torch.tensor(targets), torch.tensor(target_lengths)

vocab = ["_"] + list("0123456789abcdefghijklmnopqrstuvwxyz")   # الـ blank أول واحد
imgs, targets, lengths = build_batch(["hello", "world"], vocab)
print(f"images: {imgs.shape}   targets: {targets.shape}   lengths: {lengths.tolist()}")

داتا OCR حقيقية بتضيف خطوط وضوضاء ودوران وblur وألوان، والـ pipeline هو هو.

خطوة ٤: تدريب (مخطّط)

model = TinyCRNN(vocab_size=len(vocab))
opt = torch.optim.Adam(model.parameters(), lr=1e-3)

for step in range(400):
    strings = ["abc" + str(step % 10)] * 4 + ["xyz" + str((step + 1) % 10)] * 4
    imgs, targets, target_lens = build_batch(strings, vocab)
    log_probs = model(imgs)                                           # (W', 8, vocab)
    input_lens = torch.full((8,), log_probs.size(0), dtype=torch.long)
    loss = ctc_loss(log_probs, targets, input_lens, target_lens, blank=0)
    opt.zero_grad(); loss.backward(); opt.step()

الـ loss المفروض تنزل من خانتين عشرية لحوالي 0.3 خلال 400 خطوة على الداتا التافهة دي. ملف main.py بيشغّل نفس الـ loop على مجموعة strings بتاعته.

التمارين

CLIP

  1. (سهل) استخدم OpenCLIP ViT-B/32 على CIFAR-10 بـ zero-shot مع مجموعة الـ 80 template. سجّل top-1: المفروض حوالي 85-90%.
    تلميححمّل CIFAR-10 بـ torchvision، شفّر الصور بـ encode_image، وكل class بمتوسط embeddings الـ templates (طبّع كل واحد قبل المتوسط وبعده)، وخد argmax للـ similarity.
  2. (متوسط) قارن template واحد ("a photo of a {}") بمتوسط الـ 80 على نفس المهمة. قدّر الفرق واشرح ليه الـ templates بتساعد.
    تلميحنفس الكود مرتين. الفرق المتوقع نقطة أو اتنين أو تلاتة. التفسير: كل template بيضيء جانب مختلف من النص ("blurry"، "sketch")، والمتوسط بيدّي centroid أنعم وأقل حساسية لصياغة واحدة.
  3. (صعب) ابنِ index للـ retrieval: شفّر 1000 صورة بـ CLIP، ابني FAISS index، واستعلم بوصف نصي. سجّل recall@5 لـ 20 استعلام كتبتهم بإيدك.
    تلميحطبّع الـ embeddings واستخدم faiss.IndexFlatIP (inner product = cosine بعد التطبيع). لكل query: شفّر النص، index.search(q, 5)، وسجّل لو الصورة الصح (اللي حددتها يدويًا) ضمن الـ 5.

OCR

  1. (سهل) درّب TinyCRNN على أرقام عشوائية من 5 خانات لـ 500 خطوة. سجّل CER على مجموعة اختبار.
    تلميحولّد strings رقمية عشوائية بـ random.choices("0123456789", k=5) في كل خطوة، وبعد التدريب فك الـ greedy وقارن بالمرجع بدالة CER (زي المعمل ٤).
  2. (متوسط) بدّل greedy بـ beam search (beam_width=5). سجّل فرق الـ CER. على أي مدخلات بيكسب beam؟
    تلميح وإجابةbeam بيكسب لما argmax كل خطوة مش موثوق: حروف غامضة، حروف متداخلة، مسح رديء. على الخط النضيف المطبوع الموديل واثق في كل خطوة فـ greedy قريب جدًا (في حدود 1% CER) وbeam بيضيف latency من غير مكسب.
  3. (صعب) استخدم PaddleOCR على 20 إيصال، استخرج بنود الأصناف، واحسب F1 مقابل ground truth معلّم بإيدك لأزواج {item_name, price}.
    تلميحعلّم الأزواج الصح بإيدك في JSON. من مخرج PaddleOCR (boxes + text) رتّب النص حسب y ثم x لتجمّع أسطر. لكل سطر استخرج السعر بـ regex والباقي اسم. F1 = تطابق الزوج كله (اسم وسعر) بين المتوقع والمعلّم.

إضافة مني

  1. CLIP كـ retrieval ثنائي الاتجاه: اكتب دالتين text_to_image(query) وimage_to_text(image) فوق نفس الـ embeddings. ليه الاتنين بيشتغلوا من تدريب واحد؟
    الإجابةلأن الـ loss متماثل (i2t + t2i) فالفضاء المشترك بيعمل الاتجاهين. كل اللي بتغيّره هو أنهي جانب هو الـ query وأنهي هو الـ gallery. الدالتين هما نفس query_emb @ gallery_emb.T ثم top-k.
  2. CTC بالإيد: اكتب decoder من 4 أسطر على القوائم لتسلسل [1,1,0,2,2,0,2] (0 = blank). إيه الناتج؟
    الإجابةدمج المتكرر يدّي [1,0,2,0,2]، وشيل الـ blank يدّي [1,2,2]. لاحظ إن الـ blank اللي في النص هو اللي حفظ الحرفين المتكررين (2) منفصلين.

إضافة مني: أخطاء شائعة وفين ده بيظهر في الـ LLMs والـ agents

  • CLIP: نسيان الـ L2-normalise قبل الـ cosine. الـ logit_scale بيتخزّن كـ log وتستخدمه بـ .exp().
  • CLIP: الـ zero-shot حساس لصياغة الـ prompt وأسماء الـ classes. الاسم الغامض ("crane": طائر ولا ونش؟) بيبوّظ الدقة. اكتب prompt بيحدّد السياق.
  • CLIP: «احتمالات» الـ softmax نسبية بين الـ classes اللي انت كتبتها. لو الصورة مش من أي منهم، هيختار واحد برضه بثقة.
  • OCR: نسيان إن الـ blank على index 0 في كل من الـ vocab والـ loss والـ decoder. عدم تطابق ده بيخلّي الـ CTC تطلّع نتايج غريبة.
  • OCR: طول التسلسل الزمني (W') لازم يكون على الأقل طول النص، ولازم يزيد لو فيه حروف متكررة (محتاجة blank بينها). ولذلك zero_infinity=True موجود.
  • Document understanding: OCR نضيف مش كفاية لو ترتيب القراءة غلط (جداول وأعمدة).
  • في الـ LLMs والـ agents: CLIP-family هو العين للـ VLMs. وagent بيقرا لقطة شاشة أو فاتورة بيعتمد على VLM-OCR (وبيحتاج contract زي Pydantic على الـ JSON اللي بيطلع، زي امبارح). والـ InfoNCE في CLIP هو نفس الفكرة بتاعة الـ embedding models اللي بتشغّل الـ RAG.

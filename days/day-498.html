ليه نقفل الـ spec؟

أي codebase بحثي بيتراكم فيه سكريبتات eval أسرع بكتير من الـ tests. بعد ست شهور: كل notebook ليه شكل JSON خاص بيه، وكل metric متكتبة مرتين بطريقتين، ومفيش أي run تقدر تقارنه بالتاني. الحل ممل جدًا ومهم جدًا: اختار schema، اكتب validator، وارفض أي حاجة تانية.

تشبيه: فكّر في الـ spec زي مقاس الفيشة والبريزة في البيت. أي جهاز (موديل) وأي بريزة (metric) شغالين مع بعض لأن المقاس ثابت. لو كل واحد عمل فيشة على مزاجه، هتحتاج adapter لكل جهاز. الـ validator هنا هو اللي بيرفض الفيشة اللي مقاسها غلط قبل ما تحرق البيت.

الشكل مستوحى من أفكار BIG-bench وHELM وharnesses على طريقة lm-eval، بس أسماء الحقول بتاعتنا. والقاعدة الذهبية: كل حقل ليه صاحب واحد.

مينبيقرا إيه
الـ runnerبيقرا التاسك (الـ prompt والـ few-shot) ويكلّم الموديل
الـ post-processبينضّف الـ generation حسب القاعدة المكتوبة في التاسك
الـ metricبيقرا الـ targets ويقارن

ومفيش حقل بيتعدّل في نص الـ pipeline. التاسك بيدخل زي ما هو ويخرج زي ما هو.

02

شكل الـ record

التاسك = JSON object على سطر واحد. الـ harness بيقرا tasks.jsonl ويـ validate كل سطر لوحده. السطر البايظ بيتلغي هو بس، مش الـ run كله.

{
  "task_id": "arith_001",
  "category": "arithmetic",
  "prompt": "Compute the result. Question: 17 + 24\nAnswer:",
  "targets": ["41"],
  "metric_name": "exact_match",
  "few_shot_examples": [
    {"prompt": "Question: 2 + 2\nAnswer:", "completion": "4"}
  ],
  "post_process": "strip_whitespace",
  "metadata": {"difficulty": "easy"}
}

الحقول الإجبارية (٦): task_id، category، prompt، targets، metric_name، post_process. الاختيارية (٢): few_shot_examples وmetadata. وأي حقل تالت برا دول = رفض.

قواعد كل حقل

الحقلالقاعدة
task_idstring من غير مسافات (في الكود: [A-Za-z0-9_-]+)، وفريد على مستوى الملف كله.
categoryواحدة من: arithmetic, mcq, code_exec, classification, summary. والـ category بتحدد أنهي metric مسموح.
promptstring مش فاضي، ممنوع trailing whitespace في آخره، وممنوع يكون جواه few-shot block مكتوب بإيد الكاتب. الـ few-shot بيتركّب في الـ runner.
targetslist مش فاضية من strings. في exact_match أي واحد يطابق يكفي. في f1 وrouge_l بناخد أعلى score. في الـ mcq لازم عنصر واحد بس، حرف من A لـ E.
metric_nameقايمة مقفولة: exact_match, f1, bleu_4, rouge_l, accuracy, code_exec. metric جديد = درس جديد وسطر جديد هنا.
few_shot_exampleslist من {prompt, completion}، أقصى حاجة ٨ عشان الـ prompt ميتنفخش.
post_processواحدة بس من: none, strip_whitespace, lower, extract_letter, extract_code_block, extract_first_line. ممنوع تجمع قاعدتين.
metadataobject حر (صعوبة، موضوع، لغة...)، الـ validator بيتأكد بس إنه dict.
ليه الـ few-shot جوه التاسك ومش في الـ runner؟ لأن اختيار الأمثلة جزء من تعريف الـ eval نفسه، مش من طريقة كلام الموديل. لما الأمثلة تبقى مربوطة بالتاسك، كل موديل بيشوف نفس الـ prompt بالحرف، فالفرق الوحيد في النتيجة بيبقى الموديل نفسه.
03

الـ Validator: بوابة على كل سطر

الـ validator بيمشي على كل سطر بالترتيب ده، وأول قاعدة تقع بيسجّل error ويكمّل على السطر اللي بعده:

parse JSON → required fields → unknown fields → types/values → category-metric pair → embedded few-shot → task_id unique

وبيرجّع حاجتين: list بالتاسكات السليمة، وlist بالـ errors (رقم السطر، الـ task_id، القاعدة اللي اتكسرت، والحقل الغلطان). الـ runner بيرفض يبدأ لو فيه أي error، إلا لو حطيت flag صريح --allow-bad-tasks.

معمل ١: جرّب الـ validator بنفسك

ده نفس منطق validate_task متحوّل لـ JavaScript. اختار حالة جاهزة أو عدّل الـ JSON بإيدك، وشوف أنهي مرحلة في البوابة وقفته.

لاحظ: الـ validator بيقف عند أول مشكلة في السطر. سطر فيه ٣ غلطات هيطلعلك error واحد بس. صلّحه وشغّل تاني هتلاقي اللي بعده.

import json, os, re, sys
from dataclasses import dataclass, field

# الحقول: ٦ إجباري + ٢ اختياري، وغيرهم مرفوض
REQUIRED_FIELDS = ("task_id", "category", "prompt", "targets", "metric_name", "post_process")
OPTIONAL_FIELDS = ("few_shot_examples", "metadata")
ALLOWED_FIELDS = set(REQUIRED_FIELDS) | set(OPTIONAL_FIELDS)

# القوايم المقفولة
CATEGORIES = ("arithmetic", "mcq", "code_exec", "classification", "summary")
METRICS = ("exact_match", "f1", "bleu_4", "rouge_l", "accuracy", "code_exec")
POST_PROCESS = ("none", "strip_whitespace", "lower",
                "extract_letter", "extract_code_block", "extract_first_line")

# مين يمشي مع مين
LEGAL_CATEGORY_METRIC = {
    "arithmetic": {"exact_match", "f1"},
    "mcq": {"exact_match", "accuracy"},
    "code_exec": {"code_exec"},
    "classification": {"exact_match", "accuracy", "f1"},
    "summary": {"exact_match", "f1", "bleu_4", "rouge_l"},
}

FEW_SHOT_MAX = 8
TASK_ID_RE = re.compile(r"^[A-Za-z0-9_\-]+$")
MCQ_TARGET_RE = re.compile(r"^[A-E]$")


  
خطوة ٢: شكل الـ error والـ TaskSpec

  
@dataclass
class ValidationError:
    line_number: int
    task_id: str
    rule: str          # اسم القاعدة اللي اتكسرت
    field_name: str    # الحقل الغلطان
    detail: str

    def to_dict(self):
        return {"line_number": self.line_number, "task_id": self.task_id,
                "rule": self.rule, "field": self.field_name, "detail": self.detail}

@dataclass
class TaskSpec:
    task_id: str
    category: str
    prompt: str
    targets: list
    metric_name: str
    post_process: str
    few_shot_examples: list = field(default_factory=list)
    metadata: dict = field(default_factory=dict)


  
خطوة ٣: الفحوصات واحدة واحدة

  
def _check_required(record):
    for f in REQUIRED_FIELDS:
        if f not in record:
            return ("missing_required", f)
    return None

def _check_unknown_fields(record):
    for k in record.keys():
        if k not in ALLOWED_FIELDS:
            return ("unknown_field", k)
    return None

def _check_types(record):
    if not isinstance(record["task_id"], str):
        return ("bad_type", "task_id", "must be string")
    if not TASK_ID_RE.match(record["task_id"]):
        return ("bad_value", "task_id", "must match [A-Za-z0-9_-]+")
    if record["category"] not in CATEGORIES:
        return ("bad_value", "category", f"must be one of {sorted(CATEGORIES)}")
    if not isinstance(record["prompt"], str) or not record["prompt"]:
        return ("bad_type", "prompt", "must be non-empty string")
    if record["prompt"] != record["prompt"].rstrip():   # مسافة في الآخر؟ مرفوض
        return ("bad_value", "prompt", "trailing whitespace not allowed")
    if not isinstance(record["targets"], list) or not record["targets"]:
        return ("bad_type", "targets", "must be non-empty list")
    for t in record["targets"]:
        if not isinstance(t, str):
            return ("bad_type", "targets", "all elements must be strings")
    if record["metric_name"] not in METRICS:
        return ("bad_value", "metric_name", f"must be one of {sorted(METRICS)}")
    if record["post_process"] not in POST_PROCESS:
        return ("bad_value", "post_process", f"must be one of {sorted(POST_PROCESS)}")
    if "few_shot_examples" in record:
        fs = record["few_shot_examples"]
        if not isinstance(fs, list):
            return ("bad_type", "few_shot_examples", "must be list")
        if len(fs) > FEW_SHOT_MAX:
            return ("bad_value", "few_shot_examples", f"max {FEW_SHOT_MAX} entries")
        for ex in fs:
            if not isinstance(ex, dict):
                return ("bad_type", "few_shot_examples", "entries must be objects")
            if "prompt" not in ex or "completion" not in ex:
                return ("bad_type", "few_shot_examples", "needs prompt and completion")
            if not isinstance(ex["prompt"], str) or not isinstance(ex["completion"], str):
                return ("bad_type", "few_shot_examples", "prompt/completion must be strings")
    if "metadata" in record and not isinstance(record["metadata"], dict):
        return ("bad_type", "metadata", "must be object")
    return None

def _check_category_metric(record):
    cat, metric = record["category"], record["metric_name"]
    if metric not in LEGAL_CATEGORY_METRIC[cat]:
        return ("illegal_pair", "metric_name", f"{metric} not allowed for category {cat}")
    if cat == "mcq":                              # الـ mcq: target واحد وحرف A-E
        if len(record["targets"]) != 1:
            return ("bad_value", "targets", "mcq needs exactly one target")
        if not MCQ_TARGET_RE.match(record["targets"][0]):
            return ("bad_value", "targets", "mcq target must be a letter A-E")
    return None

def _embedded_few_shot(prompt):
    # لو لقينا أكتر من علامة سؤال/مثال، غالبًا الكاتب حط few-shot جوه الـ prompt
    lowered = prompt.lower()
    hits = sum(lowered.count(m) for m in ("question:", "q:", "example:"))
    return hits > 1


  
خطوة ٤: validate_task (أول مشكلة توقف السطر)

  
def validate_task(record, line_number=0):
    errors = []
    if not isinstance(record, dict):
        return [ValidationError(line_number, "?", "bad_type", "_root", "not an object")]
    tid = str(record.get("task_id", "?"))
    m = _check_required(record)
    if m:
        return [ValidationError(line_number, tid, m[0], m[1], "required field")]
    u = _check_unknown_fields(record)
    if u:
        return [ValidationError(line_number, tid, u[0], u[1], "not in allowed fields")]
    t = _check_types(record)
    if t:
        return [ValidationError(line_number, tid, t[0], t[1], t[2])]
    p = _check_category_metric(record)
    if p:
        return [ValidationError(line_number, tid, p[0], p[1], p[2])]
    if _embedded_few_shot(record["prompt"]) and not record.get("few_shot_examples"):
        errors.append(ValidationError(line_number, tid, "embedded_few_shot", "prompt",
                      "few-shot in prompt body without few_shot_examples list"))
    return errors


  
خطوة ٥: validate_file (سطر سطر + التكرار)

  
def validate_file(path):
    validated, errors, seen_ids = [], [], set()
    with open(path, "r", encoding="utf-8") as fp:
        for i, raw in enumerate(fp, start=1):
            line = raw.strip()
            if not line:
                continue                          # السطور الفاضية بنتجاهلها
            try:
                record = json.loads(line)
            except json.JSONDecodeError as exc:   # JSON بايظ: سجّل وكمّل
                errors.append(ValidationError(i, "?", "bad_json", "_line", str(exc)))
                continue
            line_errors = validate_task(record, line_number=i)
            if line_errors:
                errors.extend(line_errors)
                continue
            tid = record["task_id"]
            if tid in seen_ids:                   # الـ uniqueness على الملف كله
                errors.append(ValidationError(i, tid, "duplicate_task_id", "task_id", "already seen"))
                continue
            seen_ids.add(tid)
            validated.append(TaskSpec(
                task_id=tid, category=record["category"], prompt=record["prompt"],
                targets=list(record["targets"]), metric_name=record["metric_name"],
                post_process=record["post_process"],
                few_shot_examples=list(record.get("few_shot_examples", [])),
                metadata=dict(record.get("metadata", {}))))
    return validated, errors

def render_prompt(task):
    parts = [f"{ex['prompt']} {ex['completion']}" for ex in task.few_shot_examples]
    parts.append(task.prompt)
    return "\n\n".join(parts)                     # سطر فاضي بين كل مثال

CODE_BLOCK_RE = re.compile(r"```(?:[a-zA-Z0-9_]*)\n(.*?)```", re.DOTALL)
LETTER_RE = re.compile(r"(?:^|[^A-Za-z])([A-E])(?:[^A-Za-z]|$)")  # حرف لوحده
LETTER_FALLBACK_RE = re.compile(r"[A-E]")                          # أي حرف كبير A-E

def post_process(text, rule):
    if rule == "none":
        return text
    if rule == "strip_whitespace":
        return text.strip()
    if rule == "lower":
        return text.lower()
    if rule == "extract_letter":
        m = LETTER_RE.search(text)
        if m:
            return m.group(1)
        m2 = LETTER_FALLBACK_RE.search(text)
        return m2.group(0) if m2 else ""
    if rule == "extract_code_block":
        m = CODE_BLOCK_RE.search(text)
        return m.group(1) if m else text          # مفيش block؟ رجّع النص كله
    if rule == "extract_first_line":
        for line in text.splitlines():
            if line.strip():
                return line.strip()
        return ""
    raise ValueError(f"unknown post_process rule: {rule}")

def write_jsonl(path, records):
    with open(path, "w", encoding="utf-8") as fp:
        for r in records:
            fp.write(json.dumps(r) + "\n")        # سطر = تاسك

def load_fixtures(out_dir):
    good = os.path.join(out_dir, "tasks.jsonl")
    bad = os.path.join(out_dir, "tasks_bad.jsonl")
    write_jsonl(good, fixture_tasks())
    write_jsonl(bad, bad_fixture_tasks())
    return good, bad

def demo():
    import tempfile
    good, bad = load_fixtures(tempfile.mkdtemp(prefix="aie_l70_"))
    ok_tasks, ok_errors = validate_file(good)
    print(f"good fixture: validated={len(ok_tasks)} errors={len(ok_errors)}")
    bad_tasks, bad_errors = validate_file(bad)
    print(f"bad fixture: validated={len(bad_tasks)} errors={len(bad_errors)}")
    for err in bad_errors[:5]:

    if ok_tasks:
        rendered = render_prompt(ok_tasks[0])
        print(f"sample render len={len(rendered)} pp={post_process('  4  \n', 'strip_whitespace')!r}")
    if ok_errors:
        return 1                                  # الـ fixture السليم فيه غلط
    if len(bad_errors) != len(bad_fixture_tasks()):

إضافة مني: أخطاء هتقع فيها، وفين ده في شغل الـ LLMs

  
    
    
  • الـ fallback بتاع extract_letter: زي ما شفت في المعمل ٣، "Definitely not sure" بيطلع D. يعني موديل رد بكلام إنجليزي عادي ممكن ياخد درجة بالصدفة. في eval حقيقي فكّر تخلّي الموديل يرد بصيغة محددة، أو تراجع عيّنة من الحالات اللي عدّت من الـ fallback.
    • 
    
  • الـ trailing whitespace مش تفصيلة: مسافة في آخر الـ prompt بعد Answer: بتغيّر الـ tokenization، وده ممكن يغيّر أول token الموديل بيطلّعه. عشان كده الـ validator بيرفضها.
    • 
    
  • «هضيف الحقل ده بس مؤقتًا»: أول ما تسمح بحقول مجهولة، كل واحد هيحط حقله، وبعد شهور الـ schema الحقيقي بقى «اللي في الداتا». الرفض الصارم هو اللي بيخلي الـ spec المصدر الوحيد للحقيقة.
    • 
    
  • الـ validator مش بيشيك إن الـ post_process مناسب للـ category: مثلًا mcq مع lower هيعدّي من البوابة، بس الـ target حرف كبير، فـ exact_match هيقع دايمًا. ده مكان كويس تضيف فيه قاعدة بنفسك.
    • 
    
  • فين بتشوف ده في الدنيا: أي benchmark بيتوزع كـ JSONL، أي «eval set» بيتعمل لـ RAG أو agent في شركة، والـ regression suites اللي بتشتغل في CI قبل ما تغيّر prompt أو موديل. لو الـ spec مش ثابت، مش هتعرف هل الموديل الجديد أحسن ولا الـ eval اتغيّر.

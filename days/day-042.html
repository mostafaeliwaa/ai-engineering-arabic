02

أنواع الـ drift التلاتة

التوزيع المشترك للـ inputs x والـ labels y ممكن تكتبه بطريقتين:

P(x, y) = P(x) · P(y | x) = P(y) · P(x | y)

كل نوع drift بيغيّر حتة مختلفة من دول:

النوعاللي اتغيراللي ثابتمثال الدفعمين يشوفه
Covariate driftP(x)P(y | x)يوزرز app أكتر بسلّات أكبرInput monitors
Prior driftP(y)P(x | y)نسبة الـ fraud اتضاعفت في هجمة، والـ fraud شكله زي ما هوPrediction و outcome monitors
Concept driftP(y | x)ممكن يفضل ثابتنفس السلة بقى ليها risk مختلفOutcome monitors بس
تشبيه: مدرس بيصحح امتحانات. Covariate: جاله طلبة من مدرسة تانية مستواهم مختلف، بس الإجابة الصح هي هي. Prior: نسبة الطلبة الشاطرين في الدفعة زادت. Concept: الوزارة غيرت نموذج الإجابة، فنفس الورقة اللي كانت صح بقت غلط، والمدرس مش هيعرف غير لما حد يقوله.

Gama وزمايله بيسموا تغيير P(y | x) real concept drift، وتغيير P(x) اللي ما بيلمسش P(y | x) virtual drift. وكمان بيقسموا الـ drift حسب شكله مع الوقت: sudden (فجأة)، incremental (شوية شوية)، gradual (القديم والجديد بيتبادلوا لحد ما الجديد يكسب)، أو recurring (concept بيرجع تاني، زي موسم).

مش كل covariate drift بيأذي. لو الموديل اتعلم P(y | x) كويس، هيفضل صح لكل input. بس ممكن يخسر دقة لو الترافيك راح لمناطق كان فيها داتا تدريب قليلة، أو قريبة من الـ decision boundary.

معمل ١: حرّك العالم وشوف مين يلاحظ

كل نقطة دفعة: مكانها الأفقي هو الـ amount، ولونها هو الـ label الحقيقي (برتقالي = fraud). الخط الأزرق هو الموديل الثابت (اتدرب على amount > 120). الخط المتقطع هو الحدود الحقيقية في الدنيا.

حرّك متوسط الـ amount (ده covariate drift) وبعدين رجّعه وحرّك الحدود الحقيقية (ده concept drift). بص على الـ PSI وعلى الـ accuracy.

هتلاحظ: الـ covariate drift بيولّع الـ PSI والدقة تقريبًا ثابتة. الـ concept drift الـ PSI ساكت خالص والدقة بتقع. ده بالظبط اللي الديمو في الكود هيوريهولك.

Reference window و current window

  • • Reference window: داتا التدريب، أو فترة production راجعتها بإيدك. ثابتة لحد ما تعمل retrain.
  • • Current window: آخر N event، أو آخر T ساعة.

الـ sliding window بيتحرك بخطوة أصغر من حجمه، فالـ windows المتتالية بتتداخل. الـ tumbling window بيتحرك بحجمه كله. حجم الـ window trade-off: صغير = بيلاحظ بسرعة بس بيحسب الـ noise على إنه drift. كبير = مستقر بس بيبلّغ متأخر.

خلي بالك من الـ seasonality: ترافيك الاتنين غير ترافيك السبت في منتجات كتير. خلي الـ reference يغطي دورة كاملة، أو قارن كل window بنفس الفترة في دورة قبلها. وإلا كل أسبوع هيصحيك alert على حاجة طبيعية.

PSI و KS: تقيس الفرق بين توزيعين

Population Stability Index (PSI)

جاي من الـ credit scoring. قطّع قيم الـ reference لـ bins، عادة ١٠ bins عند الـ deciles، بحيث كل bin فيه ١٠٪ من الـ reference. عدّ نسبة قيم الـ current في كل bin. وبعدين اجمع term لكل bin:

PSI = Σ (current_share − reference_share) · ln(current_share / reference_share)

لو bin نسبته صفر، الـ log هيبقى لانهائي، فبنقص (clip) كل نسبة لقيمة صغيرة زي 0.0001. الـ PSI symmetric: بيساوي KL divergence من current لـ reference + KL من reference لـ current.

PSIالقراءة المتعارف عليها
< 0.1مستقر
0.1 – 0.25تغيير متوسط
> 0.25تغيير كبير

دي عُرف مش test إحصائي. الـ PSI بيكبر مع عدد الـ bins وبيصغر مع حجم العينة. في الديمو، windows من ٥٠٠ event من غير drift بتدي بين 0.01 و0.04.

Kolmogorov-Smirnov (KS)

الـ D هو أكبر فرق رأسي بين الـ empirical CDF بتاعة العينتين. تخيل خطين بيطلعوا سلالم من ٠ لـ ١، والـ D هو أطول مسافة رأسية بينهم.

D = max_x | F_reference(x) − F_current(x) |

D = 0 لو العينتين متطابقين، وD = 1 لو مفيش أي تداخل. مش محتاج bins. الـ p-value بيجي من توزيع Kolmogorov بحجم عينة فعّال n·m / (n+m).

فخ العينات الكبيرة: مع مليون event في الـ window، الـ p-value بيروح للصفر على فرق محدش يهتم بيه، زي shift قدره 0.02 standard deviation. فاستخدم D نفسه كـ effect size، وما تعملش alert غير لما الـ D والـ p-value الاتنين يعدّوا الـ thresholds.

معمل ٢: اسحب التوزيع وشوف PSI و D

Chi-square للـ categorical features

لـ feature زي الـ payment channel، اعمل جدول بصفين (reference و current) وعمود لكل category. الـ expected count في كل خانة جاي من مجاميع الصف والعمود:

expected[r][c] = row_total[r] · column_total[c] / grand_total
chi2 = Σ (observed − expected)² / expected

درجات الحرية k − 1 لـ k categories. category ظهرت في الـ current بس بتضيف term كبير، فالـ test بيتفاعل مع القيم الجديدة. والـ effect size هو Cramér's V، ولجدول بصفين بيساوي √(chi2 / grand_total).

مثال: reference = [1000, 700, 300] current = [140, 290, 70]

الـ alerts والإنذارات الكدابة

كل test عنده false-alarm rate قدره alpha لما مفيش حاجة اتغيرت. والمراقبة بتشغل tests كتير. ٥٠ feature كل ساعة عند alpha = 0.05 يعني 50 × 24 = 1200 test في اليوم، و٥٪ منهم = حوالي ٦٠ إنذار كداب كل يوم. الناس بتبطل تقرا الـ alerts قبل كده بكتير (ده اسمه alert fatigue).

أربع قواعد بيخلوا الـ alerts مفيدة:

  1. صحّح لتعدد الـ tests: Bonferroni بيقسم الـ alpha على عدد الـ tests. الديمو: family alpha = 0.01 على ٢ tests، يعني كل test بـ 0.005.
  2. اطلب effect size: ما تعملش alert غير لو PSI أو D أو Cramér's V كمان عدّى threshold.
  3. اطلب persistence: alert بس بعد k windows drift ورا بعض. الديمو: k = 2.
  4. افصل الـ warnings عن الـ alerts: الـ warning يروح dashboard، والـ alert يروح لبني آدم.

الديمو بيوري القاعدة ٢ شغالة: window نضيف طلع chi-square p-value = 0.0009، أقل من الـ alpha. بس الـ Cramér's V أقل من 0.1، فالسياسة سجلته warning مش alert.

إمتى تعمل retrain؟

  • • Schedule: كل أسبوع أو شهر. بسيط، بس بيعمل retrain لما مفيش حاجة اتغيرت، وبيستنى لما حاجة اتغيرت.
  • • Drift: لما الـ input drift على features مهمة يفضل فوق الـ threshold.
  • • Performance: لما outcome metric ينزل تحت قيمة الـ reference ناقص tolerance.

خطوة ١: الـ bins و PSI

  
import bisect, math

def quantile_edges(reference, bins=10):
    ordered = sorted(reference)
    n = len(ordered)
    # حدود الـ bins عند الـ deciles بتاعة الـ reference
    edges = [ordered[min(n - 1, (n * i) // bins)] for i in range(1, bins)]
    return sorted(set(edges))

def bin_fractions(values, edges):
    counts = [0] * (len(edges) + 1)
    for value in values:
        counts[bisect.bisect_right(edges, value)] += 1   # رقم الـ bin
    total = len(values)
    return [c / total for c in counts]

def psi_from_fractions(expected, actual, eps=1e-4):
    total = 0.0
    for e, a in zip(expected, actual):
        e, a = max(e, eps), max(a, eps)                  # clip عشان الـ log
        total += (a - e) * math.log(a / e)
    return total

def psi(reference, current, bins=10):
    edges = quantile_edges(reference, bins)
    return psi_from_fractions(bin_fractions(reference, edges), bin_fractions(current, edges))


  
خطوة ٢: KS statistic والـ p-value

  
def ks_statistic(sample_a, sample_b):
    a, b = sorted(sample_a), sorted(sample_b)
    n, m = len(a), len(b)
    i = j = 0
    d = 0.0
    while i < n and j < m:
        x = min(a[i], b[j])
        while i < n and a[i] <= x:      # عدّي كل النسخ المتكررة (ties)
            i += 1
        while j < m and b[j] <= x:
            j += 1
        d = max(d, abs(i / n - j / m))   # الفرق بين الـ CDFs
    return d

def ks_pvalue(d, n, m):
    effective_n = n * m / (n + m)
    lam = math.sqrt(effective_n) * d
    if lam < 1e-3:
        return 1.0
    total = 0.0
    for k in range(1, 101):              # سلسلة توزيع Kolmogorov
        term = 2 * (-1) ** (k - 1) * math.exp(-2 * k * k * lam * lam)
        total += term
        if abs(term) < 1e-12:
            break
    return min(1.0, max(0.0, total))


  
خطوة ٣: Chi-square

  
chi2_sf بتحسب الـ survival function عن طريق الـ regularized upper incomplete gamma: series للقيم الصغيرة و continued fraction للكبيرة. انقلها من الملف الأصلي (_gamma_p_series و _gamma_q_fraction)، وركّز انت على الـ test نفسه:

  
from dataclasses import dataclass

@dataclass(frozen=True)
class ChiSquareResult:
    statistic: float
    dof: int
    p_value: float
    cramers_v: float

def chi_square_test(reference_counts, current_counts):
    categories = [c for c in sorted(set(reference_counts) | set(current_counts))
                  if reference_counts.get(c, 0) + current_counts.get(c, 0) > 0]
    rows = [[reference_counts.get(c, 0) for c in categories],
            [current_counts.get(c, 0) for c in categories]]
    row_totals = [sum(r) for r in rows]
    grand = sum(row_totals)
    if len(categories) < 2 or 0 in row_totals:
        return ChiSquareResult(0.0, 0, 1.0, 0.0)
    statistic = 0.0
    for col, _ in enumerate(categories):
        col_total = rows[0][col] + rows[1][col]
        for r in range(2):
            expected = row_totals[r] * col_total / grand    # المتوقع لو مفيش drift
            statistic += (rows[r][col] - expected) ** 2 / expected
    dof = len(categories) - 1
    return ChiSquareResult(statistic, dof, chi2_sf(statistic, dof),
                           math.sqrt(statistic / grand))   # Cramér's V

from collections import deque

class SlidingWindow:
    def __init__(self, size):
        if size < 1:
            raise ValueError(f"window size must be at least 1, got {size}")
        self.items = deque(maxlen=size)      # القديم بيقع لوحده
    def add(self, item): self.items.append(item)
    def full(self): return len(self.items) == self.items.maxlen
    def column(self, key): return [item[key] for item in self.items]

class DriftMonitor:
    def __init__(self, reference, numeric, categorical, bins=10):
        self.numeric, self.categorical = numeric, categorical
        # كل حاجة عن الـ reference بتتحسب مرة واحدة
        self.reference_values = {f: [r[f] for r in reference] for f in numeric}
        self.edges = {f: quantile_edges(v, bins) for f, v in self.reference_values.items()}
        self.expected = {f: bin_fractions(self.reference_values[f], self.edges[f]) for f in numeric}
        self.reference_counts = {f: count_categories([r[f] for r in reference]) for f in categorical}

    def check(self, window):
        report = {}
        for f in self.numeric:
            current = window.column(f)
            d = ks_statistic(self.reference_values[f], current)
            report[f] = {"psi": psi_from_fractions(self.expected[f], bin_fractions(current, self.edges[f])),
                         "ks": d, "ks_p": ks_pvalue(d, len(self.reference_values[f]), len(current))}
        for f in self.categorical:
            res = chi_square_test(self.reference_counts[f], count_categories(window.column(f)))
            report[f] = {"chi2": res.statistic, "p": res.p_value, "v": res.cramers_v}
        return report

خطوة ٥: سياسة الـ alerts

  
from dataclasses import field

@dataclass
class AlertPolicy:
    n_tests: int
    family_alpha: float = 0.01
    psi_warn: float = 0.10
    psi_drift: float = 0.25
    ks_drift: float = 0.10
    min_cramers_v: float = 0.10
    patience: int = 2
    streaks: dict = field(default_factory=dict)

    @property
    def alpha(self):                       # Bonferroni
        return self.family_alpha / self.n_tests

    def level(self, metrics):
        if "psi" in metrics:
            if metrics["psi"] >= self.psi_drift or (metrics["ks"] >= self.ks_drift and metrics["ks_p"] < self.alpha):
                return "drift"
            return "warn" if metrics["psi"] >= self.psi_warn else "ok"
        if metrics["p"] < self.alpha and metrics["v"] >= self.min_cramers_v:   # p + effect size
            return "drift"
        return "warn" if metrics["p"] < self.alpha else "ok"

    def update(self, name, level):
        previous = self.streaks.get(name, 0)
        streak = previous + 1 if level == "drift" else 0
        self.streaks[name] = streak
        if streak == self.patience:        # persistence
            return "ALERT"
        if previous >= self.patience and streak == 0:
            return "resolved"
        return None

def make_stream(n=9000, seed=7, segments=SEGMENTS):
    rng = random.Random(seed)
    events = []
    for t in range(n):
        s = segment_at(t, segments)                       # أنهي segment احنا فيه
        amount = rng.gauss(s.amount_mean, s.amount_sd)
        channel = rng.choices(CHANNELS, weights=s.channel_mix)[0]
        label = 1 if amount + rng.gauss(0, 6) > s.boundary else 0   # الحقيقة + noise
        events.append({"t": t, "amount": amount, "channel": channel, "label": label})
    return events

الدرس بيقول إن الـ KS statistic والـ chi-square statistic والـ p-value بتاعه طابقوا scipy. أما الـ KS p-value فاختلف لحد ١٨٪ من قيمة scipy، أكتر عند الـ p-values الصغيرة جدًا، لأن كودنا بيستخدم التوزيع الحدّي (limiting) بتاع Kolmogorov، وks_2samp بيستخدم exact method لو العينتين ≤ 10,000. ولو فيه category اتنين بس، chi2_contingency بيطبق Yates' correction افتراضيًا فالأرقام هتختلف.

التمارين

  
    
    
  1. حجم الـ window: شغّل الـ stream بـ windows ٢٠٠ و٢٠٠٠. سجّل الـ warnings الكدابة قبل ٣٠٠٠ وتأخير الـ alert.
      
    تلميحغيّر window_size في run_monitoring. خلي بالك إن الـ step ٢٥٠ ثابت. المتوقع: ٢٠٠ = warnings أكتر بس alert أسرع، ٢٠٠٠ = هادي بس متأخر (لأن الـ window محتاج يتملي بداتا الـ drift). جرب ده الأول في معمل ٣.
    2. 
    
  2. شيل الحمايات: خلي n_tests=1 وpatience=1 وmin_cramers_v=0. عدّ الـ alerts في الفترة النضيفة ٥٠٠٠–٦٥٠٠.
      
    تلميحهتشوف alerts ظهرت على windows نضيفة، زي الـ window اللي كان p = 0.0009 وكان warning بس. ده بيوريك ليه الـ ٤ قواعد موجودين.
    3. 
    
  3. Drift تدريجي: ضيف feature متوسطها بيزيد 0.01 كل ١٠٠ event. مين يتفاعل الأول، PSI ولا KS؟
      
    تلميحضيفه في make_stream وnumeric. اطبع أول window كل واحد فيهم عدّى الـ threshold بتاعه (PSI ≥ 0.25 مقابل D ≥ 0.10 و p < alpha). قيس بنفسك وما تفترضش.
    4. 
    
  4. Jensen-Shannon: اعمل JS distance على نفس الـ decile bins وقارنه بالـ PSI على كل window.
      
    تلميحM = (P+Q)/2، JS = ½KL(P‖M) + ½KL(Q‖M)، والـ distance = √JS. استخدم نفس الـ eps clipping. الـ JS محدود (bounded) عكس الـ PSI.
    5. 
    
  5. Positive-prediction rate: ضيف monitor لنسبة الـ predictions الموجبة. اشرح ليه بيفضل ساكت في الـ concept drift.
      
    الإجابةالـ prediction دالة في الـ amount بس، والـ amount ما اتغيرش في الـ concept drift. يعني نسبة الـ predictions الموجبة ثابتة، اللي اتغير هو الـ labels. (في الـ covariate drift بقى هيتحرك لأن amounts أكبر = predictions موجبة أكتر.)
    6. 
    
  6. إضافة مني · مراقبة RAG/LLM app: عندك chatbot بيستقبل أسئلة. اكتب monitor بيعمل chi-square على توزيع الـ "topic" (حطه انت بكلمات مفتاحية: billing، shipping، tech، other) بين أسبوع reference وآخر يوم، و PSI على طول السؤال بالكلمات. شغّله على داتا وهمية فيها يوم ظهر فيه topic جديد اسمه "refund".

الحدس

  
فكّر في الـ monitoring كـ «جهاز إنذار دخان» و«ميزان حرارة». الـ input drift هو الدخان: بيجي بدري وساعات بيكون شوية بخار من المطبخ. الـ outcome metric هو الحرارة: الحقيقة، بس لما توصلك يكون الحريق بدأ. محتاج الاتنين، ومحتاج تعرف إن ممكن يبقى في حريق من غير دخان (concept drift).

  
أخطاء شائعة

  
    
    
  • • الـ reference هو داتا التدريب بعد الـ preprocessing والـ live هو الـ raw: هتلاقي drift وهمي. قارن نفس المرحلة من الـ pipeline بنفس الكود (ده موضوع بكرة).
    • 
    
  • • نسيان الـ missing values: لو feature بقت null فجأة، والكود بيحطها 0، الـ PSI هيعلى بس مش هتعرف السبب. راقب نسبة الـ missing لوحدها.
    • 
    
  • • Retrain أوتوماتيك على أي drift: في الـ concept drift من غير labels جديدة، أنت بتصرف compute عشان تعلّمه نفس الحاجة القديمة.
    • 
    
  • • Feedback loop: لو الموديل بيبلوك الـ fraud، الدفعات المبلوكة مالهاش chargeback، فالـ outcome metric نفسه بيبقى متحيز. خلي جزء صغير random (زي ما قلنا امبارح).
    • 
    
  • • تثبيت الـ reference للأبد: لازم يتصفّر بعد كل retrain.
    • 
  

  
فين ده في الـ LLMs والـ Agents؟

  
نفس الأفكار بالظبط على inputs و outputs الأنظمة دي: توزيع طول الـ prompts، لغة اليوزرز، الـ topics، نسبة الـ refusals، نسبة الـ tool calls اللي بتفشل، طول الردود، و scores الـ retrieval في الـ RAG. الـ concept drift هنا مثلًا لما الـ API اللي الـ agent بيكلمه يغير الـ response format، أو لما سياسة الشركة تتغير فالإجابة «الصح» تتغير. الـ input monitors مش هتشوف ده، محتاج evaluation على عينة من المحادثات (ده في درس LLM observability في فيز ١٧).

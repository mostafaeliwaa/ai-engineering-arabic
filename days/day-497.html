تسخين ٥ دقايق: فاكر امبارح؟

امبارح بنيت الـ eval بتاع الـ RAG. جاوب في دماغك الأول وبعدين افتح.

  1. الـ gold فيه ٣ documents، والـ top-5 جاب الـ ٣ كلهم. الـ recall@5 كام؟ وليه الـ recall هو الرقم اللي الناس بتقوله أكتر في الـ RAG؟
    الإجابةrecall@5 = 3/3 = 1.0. لأن الـ generator يقدر يتجاهل chunk زيادة مش مهمة، لكن مستحيل يطلّع إجابة من chunk عمره ما شافها.
  2. الـ gold doc طلع في المركز التاني. الـ reciprocal rank بتاع السؤال ده كام؟
    الإجابة1/2 = 0.5. والـ MRR هو متوسط الرقم ده على كل الأسئلة، وبيدّي وزن كبير جدًا للمركز الأول.
  3. إيه الفرق بين faithfulness وanswer relevance؟
    الإجابةالـ faithfulness: هل كل claim في الإجابة متسند على الـ context اللي اتجاب؟ (مفيش اختراع). الـ answer relevance: هل الإجابة أصلًا بترد على السؤال؟ ممكن إجابة تبقى faithful ١٠٠٪ ومش relevant خالص.

01

المشكلة: ست قطع شغالة لوحدها مش بتثبت أي حاجة

كل قطعة كسبت في الـ demo بتاعها. بس ده مش معناه إن السيستم كسبان:

  • • الـ chunker ممكن يكسب في recall@5 على الـ corpus، ويخسر في recall@5 بتاع السيستم كله، لأن الـ retriever مش عارف يرتّب الـ chunks اللي هو طلّعها.
  • • الـ reranker ممكن يرفع الـ MRR على candidates صناعية، ويفشل على candidates حقيقية جاية من الـ bi-encoder، لأن الـ recall بتاع الـ bi-encoder عند الـ budget بتاع الـ rerank أصلًا قليل (الـ reranker مش هيرتّب حاجة مش موجودة قدامه).
  • • الـ query rewriter ممكن يطلّع الـ gold doc لفوق في سؤال، ويبوّظ السؤال اللي بعده لأن الـ LLM الـ mock رجّع hypothetical بايظ.
تشبيه: فريق كورة كل لاعب فيه بطل في التمرين لوحده. ده مش بيقولك الفريق هيكسب الماتش. الماتش نفسه هو الاختبار. هنا الماتش = الـ pipeline كله شغال end to end على نفس الـ qrels، بنفس الـ metric، من ملف orchestrator واحد بيوصّل كل حاجة ببعض.

لو الأرقام على الـ pipeline المتجمّع عدّت الأرقام في الـ demos المنفصلة، تبقى أثبتّ إن السيستم شغال. ده اللي بيتسمى integration test.

02

التوصيل: الـ pipeline جراف صغير، وكل stage دالة ليها توقيع ثابت

المستندات بتدخل Chunker → بتتحط في Hybrid Index. السؤال بيدخل Query Rewriter → Hybrid Retriever (بيقرا من الـ index) → Cross-Encoder Reranker → Answer Generator (اللي بياخد السؤال الأصلي كمان) → إجابة بمصادر → Eval → تقرير الـ demo.

الـ Stageبياخدبيطلّع
Chunkerنص الـ documentList of Chunk
Retrieverالـ query stringأحسن N chunk (top-N)
Rewriter (اختياري)الـ query stringrewrites + hypothetical
Rerankerquery + candidatesأحسن K chunk ومعاهم cross scores
Generatorquery + الـ top-Kإجابة نصية فيها citations

لما كل توقيع ثابت، التركيب بيبقى سهل. كلاس Pipeline شايل الخمس stages، وفيه method اسمها query بتشغّلهم بالترتيب. وكل stage ممكن تتبدّل: حط chunker أو retriever أو reranker تاني والـ pipeline لسه شغال.

تشبيه: زي فيش الكهربا الموحّد. طالما كل جهاز ليه نفس الفيشة، تقدر تشيل التلاجة وتحط واحدة جديدة من غير ما تعيد تمديد البيت. الـ stage interface هي الفيشة.

معمل ١: الطلب ماشي جوه الـ pipeline

دوس «شغّل سؤال» وتابع الطلب وهو بيعدّي على كل stage. دوس على أي مربع في الرسم عشان تشوف بياخد إيه ويطلّع إيه، وزمنه التقريبي في الكود (الـ latency_ms).

جرّب «بدّل الـ reranker»: الـ stage بيتغير لونها بس كل الأسهم زي ما هي. ده معنى إن الـ interface ثابتة.

لاحظ: فيه سهم من السؤال الأصلي على طول للـ Generator. الـ generator بيستخدم السؤال الأصلي مش الـ rewrite، عشان الإجابة ترد على اللي اليوزر سأله فعلًا.

03

الـ Answer Generator: بيستشهد بمصادره، وبيرفض لما مش واثق

الـ generator آخر stage، وأسهل واحدة تبوظ. الدرس بيشحن mock generator ثابت (deterministic) بيعمل كده:

  1. بياخد الـ top-K chunks بعد الـ rerank.
  2. بيختار لحد chunk-ين فيهم أعلى تداخل في الكلمات المهمة (content tokens، يعني من غير stop words زي the وis) مع السؤال. (في الكود بيبص على أول ٣ بس.)
  3. بيطلّع إجابة = أول جملة من كل chunk مختارة، وبعد كل جملة anchor بالشكل [doc_id:chunk_index].
  4. لو مفيش chunk عدّت الـ refuse threshold، بيرجّع «I do not know» من غير أي citation.

الـ citation anchor هو المرجع (doc_id, chunk_index) اللي متعلّق في كل claim، عشان أي UI أو مراجع يقدر يرجع لكل جملة ويلاقي مصدرها بالظبط.

في الـ production بتبدّل الـ mock بـ LLM حقيقي، بالـ prompt ده:

You are answering a question using only the snippets below.
Cite every claim with the anchor in parentheses.
If the snippets do not answer the question, say "I do not know".

Question: {query}

Snippets:
{enumerated chunks with anchors}

Answer:

Refuse-on-low-confidence: ده السبب الوحيد إن الـ score بتاع المركز الأول من الـ cross-encoder بيتسجّل. لو الـ score ده تحت الـ threshold بتاع الـ corpus، الـ generator بيرفض. ده صمام الأمان ضد الإجابات المتألّفة (hallucination). لو الـ rank-1 score واطي باستمرار، فده الموديل بيقولك إن مفيش حاجة في الـ corpus بترد على السؤال ده.

تشبيه: موظف خدمة عملا كويس بيقولك «مش متأكد، هراجع» بدل ما يألّف رد. الـ «I do not know» مش فشل، ده حماية.

    خطوة ١: الـ Chunk والـ Chunker
    
  
    @dataclass
class Chunk:
    doc_id: str
    chunk_index: int
    text: str

    def anchor(self) -> str:          # ده الـ citation anchor
        return f"{self.doc_id}:{self.chunk_index}"

@dataclass
class Chunker:
    target: int = 400                 # أقصى طول للـ chunk بالحروف
    separators: tuple = ("\n\n", "\n", ". ", " ")   # recursive split من درس 64

    def chunk(self, doc_id, text):
        pieces = _recursive_split(text, self.separators, self.target)
        return [Chunk(doc_id, i, p.strip()) for i, p in enumerate(pieces) if p.strip()]
    

  
    خطوة ٢: الـ Hybrid Index (BM25 + dense + RRF)
    
  
    def rrf(rankings, k=60):
    score = defaultdict(float); by_anchor = {}
    for ranks in rankings:
        for rank, (c, _) in enumerate(ranks):
            score[c.anchor()] += 1.0 / (k + rank + 1)   # المركز بس اللي بيفرق
            by_anchor[c.anchor()] = c
    fused = sorted(score.items(), key=lambda x: -x[1])
    return [(by_anchor[a], s) for a, s in fused]

@dataclass
class HybridIndex:
    bm25: BM25Index = field(default_factory=BM25Index)
    dense: DenseIndex = field(default_factory=DenseIndex)

    def add(self, c):
        self.bm25.add(c); self.dense.add(c)

    def search(self, query, k_each=8, k_out=12):
        b = self.bm25.search(query, k_each)
        d = self.dense.search(query, k_each)
        return [c for c, _ in rrf([b, d])[:k_out]]

    def search_with_hypothetical(self, query, hypothetical, k_each=8, k_out=12):
        b = self.bm25.search(query, k_each)                     # BM25 على السؤال الأصلي
        d = self.dense.search_vec(mock_embed(hypothetical), k_each)  # dense على إجابة HyDE
        return [c for c, _ in rrf([b, d])[:k_out]]
    

  
    خطوة ٣: الـ Rewriter بيختار استراتيجية
    
  
    class Rewriter:
    def pick_strategy(self, query):
        if " and " in query.lower():
            return "decompose"        # سؤالين في سؤال: قسّمه
        if any(t in tokenize(query) for t in ("api", "function", "endpoint", "config")):
            return "hyde"             # كلام تقني: ولّد إجابة افتراضية
        return "multiquery"           # الافتراضي

    def rewrite_multiquery(self, query):
        base = query.strip().rstrip("?")
        toks = [t for t in tokenize(base) if t not in _STOP]
        variants = [base]
        if toks:
            variants.append(" ".join(toks))   # نسخة من غير stop words
        return list(dict.fromkeys(v for v in variants if v))

    def rewrite_decompose(self, query):
        parts = re.split(r"\s+and\s+", query, flags=re.IGNORECASE)
        out = [p.strip().rstrip("?") for p in parts if p.strip()]
        return out or [query.strip().rstrip("?")]
    

  
    خطوة ٤: الـ rerank بيخلط الـ cross-encoder مع الـ overlap
    
  
    الـ cross-encoder الصغير ده (طبقة attention واحدة، متدرّب ٨٠ epoch على ١٧ triple فيهم hard negatives) بيبقى noisy على أسئلة برا التدريب. فالكود بيضيف إشارة lexical overlap بوزن overlap_weight=0.3.
    
  
    def rerank(model, query, candidates, top_k, overlap_weight=0.3):
    if not candidates:
        return []
    model.eval()
    ids, tids = [], []
    for c in candidates:
        a, b = tokenize_pair(query, c.text, max_len=model.max_len)  # [CLS] q [SEP] d [SEP]
        ids.append(a); tids.append(b)
    with torch.no_grad():
        ce_scores = model(torch.tensor(ids), torch.tensor(tids)).tolist()
    q_tokens = _content_tokens(query)
    blended = []
    for c, ce in zip(candidates, ce_scores):
        overlap = len(q_tokens & _content_tokens(c.text)) / max(1, len(q_tokens))
        blended.append((c, ce + overlap_weight * overlap))   # الخلطة
    blended.sort(key=lambda x: -x[1])
    return blended[:top_k]
    

  
    خطوة ٥: الـ generator بالـ citations والرفض
    
  
    REFUSE_THRESHOLD = 0.05
REFUSE_TEXT = "I do not know."

def generate_answer(query, ranked):
    if not ranked:
        return REFUSE_TEXT, []
    top_chunk, top_score = ranked[0]
    if top_score < REFUSE_THRESHOLD:        # صمام الأمان
        return REFUSE_TEXT, []
    q_tokens = _content_tokens(query)
    scored = [(c, len(q_tokens & _content_tokens(c.text)), s) for c, s in ranked[:3]]
    scored.sort(key=lambda x: (-x[1], -x[2]))   # الأكتر overlap الأول
    selected = [t for t in scored if t[1] > 0][:2] or [scored[0]]
    sentences, citations = [], []
    for c, _, _ in selected:
        first = re.split(r"(?<=[.!?])\s+", c.text.strip(), maxsplit=1)[0]
        sentences.append(f"{first} [{c.anchor()}]")   # جملة + anchor
        citations.append(c.anchor())
    return " ".join(sentences), citations
    

  
    خطوة ٦: الـ Pipeline نفسه
    
  
    @dataclass
class Pipeline:
    chunker: Chunker = field(default_factory=Chunker)
    index: HybridIndex = field(default_factory=HybridIndex)
    rewriter: Rewriter = field(default_factory=Rewriter)
    reranker: CrossEncoder = field(default_factory=CrossEncoder)
    top_n: int = 12      # candidates داخلة الـ rerank
    top_k: int = 5       # اللي طالعة للـ generator

    def ingest(self, docs):
        for doc_id, text in docs:
            for chunk in self.chunker.chunk(doc_id, text):
                self.index.add(chunk)

    def query(self, question):
        lat = {}
        t0 = time.perf_counter()
        strategy = self.rewriter.pick_strategy(question)
        hypothetical = self.rewriter.rewrite_hyde(question) if strategy == "hyde" else None
        subqueries = []
        if strategy == "multiquery":
            subqueries = self.rewriter.rewrite_multiquery(question)
        elif strategy == "decompose":
            subqueries = self.rewriter.rewrite_decompose(question)
        t1 = time.perf_counter(); lat["rewrite"] = (t1 - t0) * 1000

        if hypothetical:
            candidates = self.index.search_with_hypothetical(question, hypothetical, k_out=self.top_n)
        elif len(subqueries) > 1:
            rankings = [[(c, 1.0) for c in self.index.search(q, k_out=self.top_n)] for q in subqueries]
            candidates = [c for c, _ in rrf(rankings)[: self.top_n]]   # دمج نتايج كل subquery
        else:
            candidates = self.index.search(question, k_out=self.top_n)
        t2 = time.perf_counter(); lat["retrieve"] = (t2 - t1) * 1000

        ranked = rerank(self.reranker, question, candidates, self.top_k)
        t3 = time.perf_counter(); lat["rerank"] = (t3 - t2) * 1000

        answer, citations = generate_answer(question, ranked)   # السؤال الأصلي
        t4 = time.perf_counter(); lat["generate"] = (t4 - t3) * 1000
        return Result(answer, citations, ranked, strategy, lat)

            return 1.0 / rank
    return 0.0

    • بص على الـ strategy اللي بتتختار فعلًا: لو تتبعت pick_strategy على الأربع أسئلة بتوع الـ eval، مفيش واحد فيهم فيه " and " ولا كلمة من (api, function, endpoint, config)، فالأربعة بيروحوا multiquery. يعني جدول _REWRITE_HYDE اللي في الكود مش بيتستخدم في الـ eval ده خالص. الدرس: لما تضيف stage، اتأكد إنها بتشتغل فعلًا في الـ eval، واطبع الـ strategy في الـ trace زي ما الـ demo بيعمل.

    • الـ refuse threshold مش رقم عالمي: الـ 0.05 ده مظبوط على score الـ cross-encoder الصغير ده بالخلطة بتاعته. أي تغيير في الـ reranker (موديل تاني، overlap_weight تاني) بيغيّر توزيع الـ scores، ولازم تعيد ظبط الـ threshold. الطريقة: شوف توزيع الـ top-1 score للأسئلة اللي ليها إجابة مقابل أسئلة مالهاش، وحط الحد في النص.

    • فين ده في الـ agents: أي agent بيستخدم أداة search_docs هو بالظبط الـ pipeline ده متغلّف كـ tool. الـ citations بتخلي الـ agent يقدر يرجّع المصدر لليوزر، والـ «I do not know» بتخلي الـ agent يقرر يدوّر بطريقة تانية بدل ما يكمّل على معلومة غلط.

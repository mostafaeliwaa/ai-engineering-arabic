Phase 19 · Lesson 44 · Cosine LR with Linear Warmup

اليوم ٤٧٢: الـ learning rate مش رقم ثابت، ده منحنى لازم تتحكم فيه

النهاردة بنبني الـ schedule الأشهر في تدريب الـ LLMs: linear warmup بيطلّع الـ learning rate من صفر لـ lr_max، وبعدين cosine decay بينزّله بنعومة لـ lr_min. هنوصله بـ AdamW، ونسجّل الـ gradient norm جنب الـ lr في كل خطوة، ونثبت بالتست إن الحدود (boundaries) سليمة. ده مشروع (capstone) فاليوم مقسوم لـ milestones.

المشكلة: أول ألف update هما الأعلى صوتًا

في أول الألف خطوة تدريب: الـ weights لسه قريبة من الـ initialization، وتقدير الـ optimizer للـ second moment لسه ما استقرّش، والـ gradient norm كبير ومتذبذب. لو الـ learning rate على القمة في اللحظات دي، الموديل يا بيـdiverge خالص، يا بيستقر في plateau ما بيطلعش منه.

فيه علاجين معروفين: gradient clipping (موضوع درس بكرة)، وschedule بيبدأ صغير ويكبر. ده اللي بنبنيه النهاردة.

تشبيه: بتسوق عربية باردة في الشتا. ما بتدوسش بنزين للآخر من أول ثانية. بتبدأ بشويش لحد ما الموتور يسخن (warmup)، وبعدين بتمشي بسرعتك العالية (peak)، وقرب الوصول بتهدّى تدريجيًا (cosine decay) مش بتفرمل مرة واحدة.

المناطق التلاتة

المنطقةالـ stepالـ learning rate
Warmup0 → warmup_stepsبيطلع خطيًا من 0 لـ lr_max
Cosine decaywarmup_steps → total_stepsنص الـ cosine الأعلى: بينزل من lr_max لـ lr_min
Floor> total_stepsثابت على lr_min (من غير error ومن غير extrapolation)
02

الصيغ بالظبط (ومعاها كل الحدود)

Warmup

لـ step في [0, warmup_steps] مع warmup_steps > 0:

lr = lr_max * step / warmup_steps

لو warmup_steps = 0 يعني «من غير warmup»: الـ schedule بيبدأ من lr_max عند step صفر ويدخل في الـ cosine على طول.

Cosine

لـ step في (warmup_steps, total_steps]:

progress = (step - warmup_steps) / max(1, total_steps - warmup_steps) lr = lr_min + 0.5 * (lr_max - lr_min) * (1 + cos(pi * progress))

عند step = warmup_steps الـ progress = 0 فـ cos(0)=1 فالـ lr = lr_max، وده بيطابق نهاية الـ warmup بالظبط. وعند step = total_steps الـ progress = 1 فـ cos(pi) = -1 فالـ lr = lr_min، وده بيطابق نهاية الـ decay.

ليه دالة واحدة مش تلات دوال ملزوقين؟ الاتصال (continuity) عند الحدين مش صدفة: هو ناتج إن الصيغة closed-form واحدة على step. لو لزقت ٣ دوال، أول ما تغيّر lr_max تخسر حد منهم. (دي إجابة سؤال من الكويز.)

الـ Floor

لـ step > total_steps الـ lr بيثبت على lr_min. العقد صريح: الـ schedule ما بيعملش error ولا extrapolation، بيثبت عند الأرضية، والـ trainer يسجّل warning. لو عايز تكمّل تدريب، غيّر total_steps في الـ schedule، مش في الـ loop.

تنبيه على الـ off-by-one: الـ schedules سهل تغلط فيها بـ step واحد، والغلطة بتظهر بعد ٦ ساعات تدريب كـ lr أعلى أو أقل بـ 1% في اللحظة اللي الموديل بيبدأ فيها overfit. وده بيتكشف بس باختبار الحدود بشكل شامل (فيه test في الدرس لده).

معمل ١: ارسم الـ schedule

حرّك الـ warmup والـ total وlr_max وlr_min (كنسبة من الـ max). المحور الأفقي ممتد لبعد الـ total_steps عشان تشوف الـ floor.

لاحظ: الـ lr عند step = warmup بيساوي lr_max بالظبط، وعند step = total بيساوي lr_min، وبعدها خط أفقي. جرّب warmup = 0 وشوف إن المنحنى بيبدأ من القمة.

ملاحظة على step صفر: حسب تعريف الدرس، الـ lr عند step صفر = 0 بالظبط (لو فيه warmup). يعني أول update عمليًا ما بيغيّرش الـ weights. ده طبيعي وده معنى «الـ warmup بيبدأ من الصفر».

03

الـ gradient norm: نص صحة التدريب التاني

الـ schedule هو نص صحة التدريب. النص التاني هو الـ gradient L2 norm: الطول الإقليدي للـ gradient vector كله (كل الـ parameters ملصوقة في vector واحد). الـ loop بيسجّل الاتنين في كل step:

  • التدريب اللي بيـ diverge بيعمل spike في الـ norm قبل ما الـ loss يبوّظ.
  • warmup كويس بيخلي الـ norm يطلع مع الـ rate.
  • peak عالي زيادة بيبان كـ norm بيفضل عالي بعد انتهاء الـ warmup.

الـ CSV بتاع الـ log شكله ثابت: step, lr, grad_l2_norm, loss. وده السجل الدائم الوحيد.

grad_l2_norm = sqrt( sum over all params of sum(grad²) )

معمل ٢: خطوة تدريب واحدة، ترتيب الأحداث

دوس «التالي» وشوف إيه اللي بيحصل في TrainState.step بالترتيب، ومين بيلمس مين.

05

إضافة مني: AdamW في ٣ دقايق

الـ schedule بيتحكم في الـ lr، لكن اللي بيستخدمه هو AdamW. مرجعه الورقي: Loshchilov & Hutter, Decoupled Weight Decay Regularization (الدرس بيذكرها). الفكرة: بدل ما الـ weight decay يتحط جوه الـ gradient (فيتأثر بتقديرات Adam)، AdamW بيطبّقه مفصول مباشرة على الـ weights.

في الكود: betas=(0.9, 0.95) وweight_decay=0.01 وeps=1e-8 كـ defaults في TrainState. وفيه helper اسمه split_decay_groups بيقسّم الـ parameters لمجموعتين: الـ weight matrices بـ decay، والـ biases وLayerNorm gains من غير decay (لأن decay عليهم مش مفيد في العُرف المعتاد لتدريب الـ transformers).

الملف الأصلي فيه كمان LinearWarmupConstant وInverseSqrtWarmup (schedules بديلة)، وEWMA (متوسط متحرك أسّي) وsummarize_step_log. افتح الأصل وشوفهم بعد ما تخلّص الأساسيات، وهتحتاجهم في تمرين ١.

Milestone 1: الـ CosineWithWarmup (دالة stateless)

import math
from dataclasses import dataclass

@dataclass
class CosineWithWarmup:
    warmup_steps: int
    total_steps: int
    lr_max: float
    lr_min: float = 0.0

    def __post_init__(self):               # validation للمدخلات
        if self.warmup_steps < 0: raise ValueError("warmup_steps must be non-negative")
        if self.total_steps <= 0: raise ValueError("total_steps must be positive")
        if self.warmup_steps >= self.total_steps:
            raise ValueError("warmup_steps must be less than total_steps")
        if self.lr_max <= 0: raise ValueError("lr_max must be positive")
        if self.lr_min < 0: raise ValueError("lr_min must be non-negative")
        if self.lr_min > self.lr_max: raise ValueError("lr_min must not exceed lr_max")

    def lr(self, step):
        if step < 0:
            raise ValueError("step must be non-negative")
        if self.warmup_steps > 0 and step <= self.warmup_steps:
            return self.lr_max * (step / self.warmup_steps)    # warmup خطي
        if step >= self.total_steps:
            return self.lr_min                                 # الأرضية
        decay_span = max(1, self.total_steps - self.warmup_steps)
        progress = (step - self.warmup_steps) / decay_span
        cosine = 0.5 * (1.0 + math.cos(math.pi * progress))
        return self.lr_min + (self.lr_max - self.lr_min) * cosine

Milestone 3: TrainState (الموديل + AdamW + schedule)

class TrainState:
    def __init__(self, model, schedule, loss_fn,
                 weight_decay=0.01, betas=(0.9, 0.95), eps=1e-8):
        self.model, self.schedule, self.loss_fn = model, schedule, loss_fn
        self.optimizer = torch.optim.AdamW(
            model.parameters(), lr=schedule.lr(0),
            betas=betas, eps=eps, weight_decay=weight_decay)
        self.global_step = 0              # المحور الدائم للـ schedule
        self._log = []

    def set_lr(self, lr):
        for group in self.optimizer.param_groups:
            group["lr"] = lr

    def step(self, batch_inputs, batch_targets):
        self.model.train()
        self.optimizer.zero_grad(set_to_none=True)
        loss = self.loss_fn(self.model(batch_inputs), batch_targets)
        loss.backward()
        grad_norm = gradient_l2_norm(self.model.parameters())  # قبل الـ step
        rate = self.schedule.lr(self.global_step)
        self.set_lr(rate)                 # نضبط الـ lr قبل optimizer.step
        self.optimizer.step()
        record = StepLog(step=self.global_step, lr=rate,
                         grad_l2_norm=grad_norm, loss=float(loss.detach().item()))
        self._log.append(record)
        self.global_step += 1
        return record

التمارين

  1. أضف نسخة inverse-square-root من الـ schedule وقارنها على تدريب toy بـ 200 step. أنهي منحنى بيطلّع loss نهائي أقل؟
    تلميحالأصل فيه كلاس InverseSqrtWarmup تقدر تبص عليه. شغّل نفس الموديل ونفس الـ seed ونفس الـ batch مرتين، مرة بكل schedule، وقارن آخر loss (وكمان منحنى الـ loss كله). متنساش إن النتيجة على toy مش بالضرورة تتعمم على موديل كبير.
  2. أضف flag --restart بيضيف warmup تاني عند total_steps / 2. دافع: الـ warm restarts بتفيد ولا بتضر على الـ toy run؟
    تلميحالفكرة تيجي من ورقة SGDR (Loshchilov & Hutter). اعمل الـ schedule يبقى دالة على step mod (total/2) لحد نص التدريب، وقارن الـ loss. الإجابة بتعتمد على الداتا، فالمهم تعرض الأرقام وتقول رأيك بناءً عليها.
  3. أضف unit test إن الـ schedule متصل (continuous): مع warmup_steps > 0، لكل step في [0, total_steps] الفرق |lr(step+1) - lr(step)| محدود بالأكبر من slope الـ warmup (lr_max / warmup_steps) وأشد slope في الـ cosine (pi * (lr_max - lr_min) / (2 * (total_steps - warmup_steps))).
    تلميحاحسب الـ bound ده في test، ولف على كل الـ steps وتأكد abs(diff) <= bound + 1e-12 (الـ 1e-12 للـ floating point). والدرس نفسه بيقول إن slope الـ warmup لوحده مش bound آمن لأن الـ cosine القصير ممكن يبقى أشد. استخدم معمل ٣ تشوف ده.
  4. اربط الـ schedule بـ torch.optim.lr_scheduler.LambdaLR عشان يتركّب مع كود الـ frameworks. الـ wrapper بيغيّر إيه؟
    تلميحLambdaLR بياخد دالة step → multiplier بتضرب في الـ lr الأساسي للـ optimizer، يعني ممكن تديه lambda s: schedule.lr(s) / schedule.lr_max وتحط الـ lr بتاع الـ optimizer = lr_max. الفرق: الـ scheduler هو اللي بيملك الـ counter (scheduler.step()) ويتحفظ في الـ state_dict، بدل ما تنادي set_lr بإيدك.
  5. أضف flag --plot-png بيكتب رسمة حقيقية بـ matplotlib. دافع: الـ text plot ولا الـ PNG أحسن كـ default للـ CI؟
    تلميحالـ text plot ما بيحتاجش dependency زيادة وبيتقري في log الـ CI وبيتعمل diff. الـ PNG أوضح للبني آدم بس بيحتاج matplotlib وبيتخزن كـ artifact. حجتك المهم تبقى واضحة.
  6. تمرين مني · احسب بإيدك: لـ warmup=100, total=1000, lr_max=3e-4, lr_min=3e-5 احسب lr(550) بإيدك ثم اتأكد بالكود.
    الإجابةprogress = (550-100)/900 = 0.5 فـ cos(pi/2) = 0 فـ cosine = 0.5. إذن lr = 3e-5 + (2.7e-4)(0.5) = 3e-5 + 1.35e-4 = 1.65e-4. يعني نص المسافة بين الحدين بالظبط عند نص الـ decay.

إضافة مني: أخطاء، وفين ده بيظهر في الـ LLMs

  • تنسى تضبط الـ lr قبل optimizer.step(): لو ضبطته بعدها، كل step بيستخدم lr الـ step اللي قبله. الـ loop بتاع الدرس بيعمل set_lr قبل الـ step.
  • تحسب الـ step من الـ epoch أو counter محلي: بعد resume من checkpoint الـ schedule هيرجع للبداية. المحور الدائم هو global_step.
  • الـ warmup بالـ steps المطلقة: لو غيّرت طول التدريب، الـ warmup بقى نسبة مختلفة تمامًا. اضبطه كنسبة.
  • تحتاج warmup أكبر لو الـ batch كبير: تقدير الـ second moment في Adam بياخد وقت يستقر، وكل ما الـ peak أعلى كل ما الـ warmup أهم. (ده مبدأ عام ملاحظ في الممارسة، مش رقم من الدرس.)
  • فين بيظهر: تقريبًا كل pretraining لـ LLM بيستخدم warmup + decay (cosine أو غيره) مع AdamW وgradient clipping. ولما تشوف loss curve فيه spike في أول التدريب، أول حاجة تشك فيها هي الـ warmup القصير أو الـ peak العالي.

الـ Tokenizer عقد، مش زرار تلعب فيه

الـ tokenizer هنا: re.findall(r"\w+", text.lower()). يعني: حوّل لـ lowercase، وخد أي سلسلة word characters (حروف وأرقام و underscore)، وارمي أي حاجة تانية (علامات ترقيم، مسافات...). كل metric في الدرس بتستخدم نفس الـ tokenizer ده بالظبط، والـ runner مالوش رأي. لو بدّلته، انت بتشغّل benchmark تاني.

tokenize("The Cat, sat!") → ["the", "cat", "sat"]

ده تبسيط مقصود. في الـ production هتهتم بالـ CJK (صيني/ياباني/كوري) والـ contractions زي don't والـ code identifiers. بس الفكرة الأساسية: الـ tokenizer عقد.

Exact Match: يا أبيض يا أسود

بيرجع 1.0 لو الـ prediction (بعد strip) بيطابق أي target (بعد strip)، وإلا 0.0. على مستوى الـ dataset بناخد المتوسط. ده الحصان الشغيل للحساب والـ MCQ والـ classification القصيرة. لاحظ: الـ exact_match مش بيستخدم الـ tokenizer، المقارنة على النص نفسه بعد شيل المسافات من الأطراف. ولو مفيش targets خالص يرجع 0.0.

Accuracy: نفس الـ EM باسم تاني

في الـ classification الـ accuracy بتتحول لـ exact_match. طب ليه دالة لوحدها؟ عشان الـ dispatcher يعمل dispatch على metric_name مباشرة من غير مقارنات strings جوه الـ runner.

Token-level F1: درجة جزئية

حوّل الـ prediction والـ target لـ multiset من الـ tokens (يعني بنعد التكرار). التقاطع = مجموع أقل عدد لكل token في الاتنين.

precision = overlap / |pred| recall = overlap / |target| F1 = 2·P·R / (P + R)

الحالات الطرفية: الاتنين فاضيين ← 1.0 (اتفاق كامل بالاصطلاح). واحد بس فاضي ← 0.0. مفيش تقاطع ← 0.0. ولو فيه أكتر من target بناخد أعلى F1، وده نفس سلوك SQuAD المعروف.

مثال الدرس: pred = "the cat sat"، target = "a cat sat on the mat". التقاطع 3 (the, cat, sat). P = 3/3 = 1، R = 3/6 = 0.5، F1 = 0.667.

BLEU-4 من الأرض

BLEU هو الـ metric الكلاسيكي للـ machine translation، ولسه بيظهر في شغل الـ summarisation. اللي هنكتبه هو sentence-level BLEU-4: بيتحسب لكل زوج (prediction, reference)، ومعاه الـ brevity penalty العادي، ومعاه smoothing بإضافة واحد.

١. Modified n-gram precision

لكل n من 1 لـ 4: عدّ الـ n-grams في الـ candidate. كل n-gram عدده بيتقص (clip) عند أقصى عدد ظهر بيه في الـ reference. يعني الـ candidate مينفعش ينفخ الـ score بتكرار كلمة واحدة مضمونة.

p_n = Σ min(count_cand(g), count_ref(g)) / Σ count_cand(g)
تشبيه: زي امتحان «اكتب أسماء ٣ عواصم». لو كتبت «القاهرة» ١٠ مرات، المصحح هيحسبهالك مرة واحدة بس. ده الـ clipping.

٢. المتوسط الهندسي على n = 1..4

بناخد log لكل precision ونجمعهم ونقسم على 4 ونرجع بالـ exp. الـ geometric mean معناه إن لو precision واحدة صفر، الكل يبقى صفر. وهنا ييجي دور الـ smoothing.

٣. الـ Smoothing (method 1)

الدرس بيسميها method 1 بتاعة Lin وOch: ضيف 1 على البسط والمقام لكل n-gram precision قبل الـ log. ده بيمنع log 0 لما مفيش ولا 4-gram مطابق، وبيفضل قريب من القيمة الأصلية في الجمل الطويلة.

p̃_n = (clipped_n + 1) / (total_n + 1)

٤. الـ Brevity Penalty

الـ precision لوحدها بتكافئ الإجابات القصيرة: لو قلت كلمتين صح بس، الـ precision عالية جدًا. فالـ BP بيعاقب أي candidate أقصر من الـ reference:

BP = 1 if c ≥ r else exp(1 − r / c) (BP = 0 لو c = 0)
BLEU = BP · exp( (1/4) · Σ log p̃_n )

c = طول الـ candidate بالـ tokens، r = طول الـ reference. ولو الـ candidate فاضي، BLEU = 0 على طول.

معمل ٢: الـ Brevity Penalty بعينك

الـ reference طوله r. حرّك طول الـ candidate (c) وشوف منحنى exp(1 − r/c). الخط المتقطع هو «precision بس» لو كل كلمة قلتها صح: دايمًا 1، حتى لو قلت كلمة واحدة. الـ BP هو اللي بيكسر الغش ده.

لاحظ: لما c ≥ r المنحنى بيبقى 1 ثابت. BLEU مش بيعاقب الطول الزيادة بالـ BP؛ الطول الزيادة بيتعاقب لوحده لأن الـ precision بتقل.

ROUGE-L: أطول subsequence مشترك

ROUGE-L بيقارن الـ Longest Common Subsequence (LCS) بين tokens الـ candidate وtokens الـ reference. الـ subsequence معناها الكلمات بنفس الترتيب بس مش لازم ورا بعض. عشان كده بيمسك ترتيب الكلام من غير ما يجبره يبقى متلاصق، وده سبب إنه الـ default في الـ summarisation.

R = LCS / |ref| P = LCS / |cand| F_β = (1+β²)·P·R / (R + β²·P) (β = 1 → F1)

الـ LCS بيتحسب بجدول dynamic programming: الخانة dp[i+1][j+1] = لو الكلمتين زي بعض ← dp[i][j] + 1، غير كده ← max(dp[i+1][j], dp[i][j+1]). والإجابة في آخر خانة. التكلفة O(n·m) لكل task، ولأطوال الملخصات العادية ده أقل من millisecond. الدرس بيستخدم جدول numpy عشان الكود يبقى واضح، بس lists عادية تنفع برضه.

تشبيه: زي ما تقارن قايمتين مشتريات: أطول قايمة كلمات تقدر تشطب عليها في الاتنين بنفس الترتيب، ومسموحلك تفوّت حاجات في النص.

معمل ٣: املا جدول الـ LCS

دوس «شغّل» وشوف الجدول بيتملي خانة خانة. الخانات الخضرا هي اللي الكلمتين فيها متطابقين (قطري +1). وفي الآخر هيتلوّن المسار اللي بيطلّع الـ LCS نفسه.

جرّب «معكوس»: "c b a" مقابل "a b c d". الـ LCS = 1 بس، رغم إن F1 كان هيشوف 3 كلمات مشتركة. ده بالظبط الـ test اسمه test_word_order_matters.

خطوة ١: الـ tokenizer وEM وaccuracy

import math
import re
import sys
from collections import Counter

import numpy as np

TOKEN_RE = re.compile(r"\w+", re.UNICODE)

def tokenize(text):
    return TOKEN_RE.findall(text.lower())     # العقد: lowercase + \w+

def exact_match(prediction, targets):
    if not targets:
        return 0.0
    pred = prediction.strip()                 # strip بس، من غير lowercase
    return 1.0 if any(pred == t.strip() for t in targets) else 0.0

def accuracy(prediction, targets):
    return exact_match(prediction, targets)   # اسم تاني عشان الـ dispatch

خطوة ٢: Token F1

def f1_score(prediction, target):
    pred_tokens = tokenize(prediction)
    tgt_tokens = tokenize(target)
    if not pred_tokens and not tgt_tokens:
        return 1.0                            # فاضي + فاضي = اتفاق كامل
    if not pred_tokens or not tgt_tokens:
        return 0.0
    pred_counts = Counter(pred_tokens)
    tgt_counts = Counter(tgt_tokens)
    overlap = sum((pred_counts & tgt_counts).values())   # تقاطع multiset
    if overlap == 0:
        return 0.0
    precision = overlap / sum(pred_counts.values())
    recall = overlap / sum(tgt_counts.values())
    return 2.0 * precision * recall / (precision + recall)

خطوة ٣: n-grams والـ clipping والـ BP

def _ngram_counts(tokens, n):
    if n <= 0:
        raise ValueError("n must be positive")
    if len(tokens) < n:
        return Counter()
    return Counter(tuple(tokens[i:i + n]) for i in range(len(tokens) - n + 1))

def _modified_precision(cand_tokens, ref_tokens, n):
    cand_ngrams = _ngram_counts(cand_tokens, n)
    if not cand_ngrams:
        return (0, 0)
    ref_ngrams = _ngram_counts(ref_tokens, n)
    clipped = 0
    for gram, count in cand_ngrams.items():
        clipped += min(count, ref_ngrams.get(gram, 0))   # القص عند عدد الـ reference
    total = sum(cand_ngrams.values())
    return (clipped, total)

def _brevity_penalty(cand_len, ref_len):
    if cand_len == 0:
        return 0.0
    if cand_len >= ref_len:
        return 1.0
    return math.exp(1.0 - ref_len / cand_len)

خطوة ٤: BLEU-4 بالـ smoothing

def bleu4(prediction, reference, max_n=4):
    cand = tokenize(prediction)
    ref = tokenize(reference)
    if not cand:
        return 0.0
    log_p_sum = 0.0
    for n in range(1, max_n + 1):
        clipped, total = _modified_precision(cand, ref, n)
        smoothed_num = clipped + 1            # method 1: +1 فوق وتحت
        smoothed_den = total + 1
        log_p_sum += math.log(smoothed_num / smoothed_den)
    geo_mean = math.exp(log_p_sum / max_n)   # المتوسط الهندسي
    bp = _brevity_penalty(len(cand), len(ref))
    return float(bp * geo_mean)

خطوة ٥: LCS وROUGE-L

def lcs_length(a, b):
    n, m = len(a), len(b)
    if n == 0 or m == 0:
        return 0
    dp = np.zeros((n + 1, m + 1), dtype=np.int32)
    for i in range(n):
        ai = a[i]
        row_prev = dp[i]
        row_curr = dp[i + 1]
        for j in range(m):
            if ai == b[j]:
                row_curr[j + 1] = row_prev[j] + 1                  # تطابق: قطري + 1
            else:
                row_curr[j + 1] = max(row_curr[j], row_prev[j + 1])  # أحسن جار
    return int(dp[n, m])

def rouge_l(prediction, reference, beta=1.0):
    cand = tokenize(prediction)
    ref = tokenize(reference)
    if not cand and not ref:
        return 1.0
    if not cand or not ref:
        return 0.0
    lcs = lcs_length(cand, ref)
    if lcs == 0:
        return 0.0
    precision = lcs / len(cand)
    recall = lcs / len(ref)
    beta_sq = beta * beta
    denom = recall + beta_sq * precision
    if denom == 0:
        return 0.0
    return float((1 + beta_sq) * precision * recall / denom)

ملاحظة: row_prev وrow_curr هنا views على صفوف الـ numpy array، فالكتابة فيهم بتكتب في dp نفسه.

خطوة ٦: الـ dispatcher والـ corpus helpers

def score(metric_name, prediction, targets):
    if not targets:
        return 0.0
    if metric_name == "exact_match":
        return exact_match(prediction, targets)
    if metric_name == "accuracy":
        return accuracy(prediction, targets)
    if metric_name == "f1":
        return max(f1_score(prediction, t) for t in targets)   # أحسن target
    if metric_name == "bleu_4":
        return max(bleu4(prediction, t) for t in targets)
    if metric_name == "rouge_l":
        return max(rouge_l(prediction, t) for t in targets)
    raise ValueError(f"unknown metric_name: {metric_name}")

def corpus_mean(scores):
    if not scores:
        return 0.0
    return float(np.mean(scores))

def corpus_bleu(predictions, references, max_n=4):
    if len(predictions) != len(references):
        raise ValueError("predictions and references must align")
    if not predictions:
        return 0.0
    total_cand_len = total_ref_len = 0
    clipped_sums = [0] * max_n
    total_sums = [0] * max_n
    for cand_text, ref_text in zip(predictions, references):
        cand, ref = tokenize(cand_text), tokenize(ref_text)
        total_cand_len += len(cand)
        total_ref_len += len(ref)
        for n in range(1, max_n + 1):           # اجمع العدّ على كل الجمل
            clipped, total = _modified_precision(cand, ref, n)
            clipped_sums[n - 1] += clipped
            total_sums[n - 1] += total
    if total_cand_len == 0:
        return 0.0
    log_p_sum = 0.0
    for n in range(1, max_n + 1):
        log_p_sum += math.log((clipped_sums[n - 1] + 1) / (total_sums[n - 1] + 1))
    geo = math.exp(log_p_sum / max_n)
    return float(_brevity_penalty(total_cand_len, total_ref_len) * geo)

    الإجابةالتقاطع = min(3,1) = 1. الأولى: P = 1/3، R = 1/1 ← F1 = 0.5. العكس: P = 1، R = 1/3 ← F1 = 0.5. متساويين، وده بالظبط test_repeated_token_counts_once_per_overlap: الـ F1 متماثل لأن الـ harmonic mean مش بيفرق مين P ومين R.
  2. BLEU يدوي: احسب الـ BP لـ candidate طوله 5 والـ reference طوله 10.
    الإجابةexp(1 − 10/5) = exp(−1) ≈ 0.368. يعني حتى لو كل الـ n-grams صح، أقصى BLEU حوالي 0.37. جرّبها في معمل ٢.
  3. ROUGE-L بـ β مختلفة: غيّر beta لـ 2 واحسب rouge_l("the cat sat", "the cat sat on the mat", beta=2). الرقم زاد ولا قل؟ وليه؟
    الإجابةP = 1، R = 0.5. بـ β = 2: (1+4)·1·0.5 / (0.5 + 4·1) = 2.5/4.5 ≈ 0.556، أقل من 0.667. β أكبر من 1 بتدي وزن أكبر للـ recall، والـ recall هنا ضعيف (الملخص فوّت نص الـ reference).
  4. Corpus مقابل متوسط: احسب corpus_bleu على الجملتين في الـ demo، وقارنه بـ corpus_mean لـ bleu4 على كل جملة لوحدها.
    تلميحالـ corpus بيجمع العدّ والأطوال الأول ويحسب BP مرة واحدة على الطول الكلي. الجملة التانية قصيرة عن الـ reference بتاعها، فالـ BP بتاعها لوحدها بيعاقبها أكتر، بس في الـ corpus الجملة الأولى (المطابقة) بتخفف العقاب. هتلاقي الرقمين مختلفين، وده الدرس: لازم تكتب في التقرير أنهي واحد استخدمت.
  5. إضافة مني · تقرير eval حقيقي: عندك 20 سؤال QA من الـ RAG system بتاعك، كل واحد ليه 2–3 إجابات مقبولة. اكتب script يقرا JSONL بحقول prediction, targets, metric_name، ويطلّع جدول: متوسط كل metric، وعدد الـ tasks اللي EM = 0 بس F1 > 0.5 (يعني «صح تقريبًا»).
    تلميحاستخدم score لكل سطر، وخزّن النتايج في dict بالـ metric_name، وفي الآخر corpus_mean. الحالات «EM صفر وF1 عالي» غالبًا مشكلة formatting (نقطة زيادة، حروف كبيرة) مش مشكلة معرفة، وده بيقولك تراجع قاعدة الـ post_process في الـ task spec بدل ما تلوم الموديل.

إضافة مني: الحدس، والأخطاء الشائعة، وفين بتقابلهم

  • الحدس في جملة: EM بيسأل «هو هو؟»، F1 بيسأل «الكلمات قريبة؟»، BLEU بيسأل «العبارات الصغيرة (n-grams) موجودة في الـ reference؟» (precision)، وROUGE-L بيسأل «قد إيه من الـ reference اتغطى بنفس الترتيب؟».
  • خطأ: تقارن BLEU بمقياس 0–100 مع BLEU بمقياس 0–1. الدالة هنا بترجع 0–1. اكتب المقياس صريح في أي تقرير.
  • خطأ: تغيّر الـ tokenizer «بس عشان العربي». لو عايز تقيس عربي، ده benchmark جديد بتعريف جديد. متقارنش أرقامه بأرقام قديمة. (للعلم: \w في Python بالـ Unicode بيمسك الحروف العربية.)
  • خطأ: تفتكر BLEU/ROUGE عالي = إجابة صح. الـ metrics دي بتكافئ التشابه السطحي. إجابة بتقول «الدواء آمن» وreference بيقول «الدواء مش آمن» هيطلعوا متشابهين جدًا. الدرس نفسه بيقول إنهم «ضروريين مش كفاية»، والخطوة اللي بعدها model-based metrics زي BLEURT وBERTScore.
  • في الـ LLMs: الـ EM والـ accuracy هما الأساس في benchmarks الحساب والـ MCQ، والـ F1 بأسلوب SQuAD في الـ QA، وROUGE في الـ summarisation. في الـ agents والـ RAG هتستخدم EM/F1 كـ regression test سريع ورخيص قبل ما تدفع على LLM-as-judge.

المشكلة: الـ optimizer أكبر من الموديل نفسه

في الـ mixed precision بنعمل الـ forward والـ backward بأرقام 16-bit (أسرع وأصغر)، بس الـ optimizer محتاج دقة 32-bit عشان التحديثات الصغيرة ما تضيعش. فبيبقى عندنا نسخة float32 من الأوزان اسمها master copy، والـ Adam عنده رقمين لكل parameter: first moment (متوسط الـ gradients) و second moment (متوسط مربعاتها). لموديل فيه P parameter:

الحاجةDDP العاديZeRO-1ليه
fp16 params2P2Pمحتاجينها في الـ forward
fp16 grads2P2Pمحتاجينها في الـ backward
fp32 master copy4P4P/Nالـ optimizer بس اللي بيلمسها
fp32 first moment4P4P/Nالـ optimizer بس اللي بيلمسها
fp32 second moment4P4P/Nالـ optimizer بس اللي بيلمسها
المجموع16P bytes4P + 12P/N

الـ optimizer state هو أكبر بند (12P من 16P)، وفي نفس الوقت أسهل بند يتقسم، لأنه مش بيتلمس في الـ forward ولا الـ backward، بس في الـ step. زي شنط سفر فريق كامل: بدل ما كل واحد يشيل شنط الفريق كله، كل واحد يشيل شنطته بس، ولما حد يحتاج حاجة الفريق يتبادل.

N=8: 16P → 5.5P (−65%) · N=64: 16P → 4.19P (−74%)

الـ Stageبيقسّم إيهالذاكرة لكل rankالـ communication في الـ step
DDPولا حاجةparams + grads + optim1 allreduce
ZeRO-1optimizer stateparams + grads + optim/N1 reduce_scatter + 1 allgather
ZeRO-2optim + gradsparams + grads/N + optim/N1 reduce_scatter + 1 allgather

  • Stage 1 أرخص مكسب، لأن الـ optimizer state هو اللي واكل الميزانية. الدرس بيبنيه كامل.
  • Stage 2 محتاج منطق إضافي لتجميع shards الـ gradients، بس الـ bandwidth هو هو.
  • Stage 3 (اللي PyTorch بيسميه FSDP) بيقسّم الـ parameters نفسها، وبيدفع تمنها communication لكل layer في كل forward و backward.

ليه reduce_scatter أحسن من allreduce وبعدين تقطيع؟

الـ allreduce بيدّي كل rank الـ gradient المجموع كامل. لو rank r محتاج الـ shard بتاعه بس، يبقى (N−1)/N من اللي وصله ضايع عليه. الـ reduce_scatter بيوصّل لكل rank الـ shard بتاعه بس. والـ bytes لكل rank هي نفسها (لأن allreduce = reduce_scatter + allgather)، بس النص التاني بيتبدل بـ allgather للـ parameters المحدّثة بعدين. يعني نفس السلك، والذاكرة اتقسمت.

DDP: allreduce(grads) → Adam(full)
ZeRO-1: reduce_scatter(grads) → Adam(my shard) → allgather(params)
03

خطوة ZeRO-1 بالتفصيل

  1. forward + backward على الموديل الكامل. كل rank عنده gradient كامل (مختلف، لأن الداتا مختلفة).
  2. reduce_scatter على الـ gradient المفرود (flat). rank r ياخد مجموع الـ shard r بس، ويقسمه على N.
  3. Adam step على الـ shard r بس، بالـ m و v والـ master اللي عند rank r بس.
  4. allgather للـ shards المحدّثة. كل rank يرجع عنده الموديل كامل للـ forward الجاي.

الـ flat vector والـ shards والـ padding

عشان التقسيم يبقى مجرد slice، الكود بيفرد كل الـ parameters ورا بعض في vector واحد طويل (gather_flat_params)، ويرجّعهم لمكانهم بعدين (scatter_flat_to_params). لو الطول مش بيتقسم على N، بيكمّل بأصفار في الآخر، والـ shard_bounds بترجع (start, end, chunk) لكل rank.

وفيه نقطة دقيقة بتظهر في تمرين ٤: الـ gradient clipping. الـ L2 norm لازم يتحسب على الـ gradient كله، بس كل rank شايل shard بس. الحل: كل rank يحسب مربع الـ norm المحلي، allreduce للمربعات، وبعدين جذر.

معمل ٣: قسّم، وبعدين احسب الـ norm صح

كل خانة = رقم في الـ flat gradient، ولونها = الـ rank المسؤول عنها. الخانات المخططة = padding. تحت: ‖g_r‖² لكل rank، والـ norm الحقيقي.

جرب: (١) total = 17 و N = 4: chunk = 5 والأخير فيه 3 padding. (٢) total = 5 و N = 4: شوف rank 3 بيطلع shard فاضي خالص. (٣) قارن الـ norm المحلي بتاع أي rank بالـ norm الحقيقي: لو قصّيت بالمحلي، كل rank هيقص بنسبة مختلفة.

    ٣ حاجات بتخلّي ZeRO يتشحن

    1. الـ checkpoint لازم يبقى مقسّم. الـ optimizer state متوزع على الـ ranks، فالـ checkpoint لازم يسجّل مين شايل إيه. من غير كده الحالة المحفوظة مش هتتقري وقت الـ restart. درس ٨٠ بيبني الـ manifest ده عشان تكمّل على نفس الـ world size.
    2. الـ mixed precision هي الفكرة كلها. ZeRO تقنية mixed precision، والـ fp32 master هو اللي بيتقسم. لو شغّلت ZeRO من غير mixed precision، بتدفع ضريبة الـ fp32 master من غير مكسب الـ forward بـ fp16. الـ production دايمًا بيجمع ZeRO مع autocast أو أوزان bf16.
    3. Stage 1 مكسب تقريبًا ببلاش. الـ bandwidth زي DDP، والتوفير خطي في N، والتمن الوحيد bookkeeping الـ shard. عشان كده الـ stacks بتبدأ بـ stage 1 إلا لو ذاكرة الـ gradients أو الـ parameters كمان مشكلة. Stage 2 بيقسّم الـ gradients بنفس الـ bandwidth، و stage 3 بس هو اللي بيدفع communication لكل layer.

    def flat_param_numel(module):
    return sum(p.numel() for p in module.parameters())

def gather_flat_params(module):
    # كل الـ parameters ورا بعض في vector واحد fp32
    return torch.cat([p.detach().to(torch.float32).flatten() for p in module.parameters()])

def scatter_flat_to_params(module, flat):
    # رجّع كل حتة لمكانها وشكلها
    offset = 0
    for p in module.parameters():
        n = p.numel()
        p.data.copy_(flat[offset:offset + n].reshape(p.shape).to(p.dtype))
        offset += n

def gather_flat_grads(module):
    parts = []
    for p in module.parameters():
        if p.grad is None:                     # parameter ما خدش gradient: أصفار
            parts.append(torch.zeros_like(p.data, dtype=torch.float32).flatten())
        else:
            parts.append(p.grad.detach().to(torch.float32).flatten())
    return torch.cat(parts)

def shard_bounds(total, world_size, rank):
    pad = (-total) % world_size                 # كام صفر نكمّل بيهم
    chunk = (total + pad) // world_size
    start = rank * chunk
    end = min(start + chunk, total)             # ما نعدّيش الطول الحقيقي
    return start, end, chunk

    خطوة ٢: الـ ZeroOptimizer، كل rank شايل الـ shard بتاعه بس

    class ZeroOptimizer:
    def __init__(self, module, world_size, rank, lr=0.05,
                 beta1=0.9, beta2=0.999, eps=1e-8):
        self.module, self.world_size, self.rank = module, world_size, rank
        self.lr, self.beta1, self.beta2, self.eps = lr, beta1, beta2, eps
        self.step_count = 0
        self.total = flat_param_numel(module)
        start, end, chunk = shard_bounds(self.total, world_size, rank)
        self.shard_start, self.shard_end, self.shard_size = start, end, chunk
        full = gather_flat_params(module)
        padded = torch.zeros(chunk * world_size, dtype=torch.float32)
        padded[:self.total] = full
        # الـ 3 حاجات دول بس اللي اتقسموا: master و m و v
        self.master_shard = padded[rank * chunk:(rank + 1) * chunk].clone()
        self.m_shard = torch.zeros_like(self.master_shard)
        self.v_shard = torch.zeros_like(self.master_shard)

    def shard_bytes(self):
        # bytes الـ optimizer state على الـ rank ده بس
        return (self.master_shard.numel() + self.m_shard.numel()
                + self.v_shard.numel()) * 4

    خطوة ٣: الـ step: reduce_scatter → Adam → allgather

        def step(self):
        flat_grad = gather_flat_grads(self.module)
        pad = (-self.total) % self.world_size
        padded_grad = torch.zeros(self.total + pad, dtype=torch.float32)
        padded_grad[:self.total] = flat_grad
        chunks = [c.contiguous() for c in padded_grad.chunk(self.world_size)]
        local_grad = torch.zeros_like(chunks[0])
        # 1) كل rank ياخد مجموع الـ shard بتاعه بس
        dist.reduce_scatter(local_grad, chunks, op=dist.ReduceOp.SUM)
        local_grad.div_(self.world_size)                     # المتوسط زي DDP
        # 2) Adam على الـ shard بس
        self.step_count += 1
        self.m_shard.mul_(self.beta1).add_(local_grad, alpha=1 - self.beta1)
        self.v_shard.mul_(self.beta2).addcmul_(local_grad, local_grad, value=1 - self.beta2)
        m_hat = self.m_shard / (1 - self.beta1 ** self.step_count)   # bias correction
        v_hat = self.v_shard / (1 - self.beta2 ** self.step_count)
        self.master_shard.addcdiv_(m_hat, v_hat.sqrt().add_(self.eps), value=-self.lr)
        # 3) الكل يتبادل الـ shards المحدّثة ويرجّع الموديل كامل
        gathered = [torch.zeros_like(self.master_shard) for _ in range(self.world_size)]
        dist.all_gather(gathered, self.master_shard)
        flat_full = torch.cat(gathered)[:self.total]          # شيل الـ padding
        scatter_flat_to_params(self.module, flat_full)

    def zero_grad(self):
        for p in self.module.parameters():
            if p.grad is not None:
                p.grad.detach_()
                p.grad.zero_()

    def memory_table(p_params, world_size):
    fp16, fp32 = 2, 4
    vanilla = (fp16 + fp16 + fp32 + fp32 + fp32) * p_params        # 16P
    zero1 = (fp16 + fp16) * p_params + (fp32 * 3 * p_params) // world_size   # 4P + 12P/N
    drop = 100 * (vanilla - zero1) / vanilla
    rows = [("vanilla DDP", vanilla), (f"ZeRO-1 (N={world_size})", zero1)]
    out = ["per-rank optimiser memory:"]
    for name, b in rows:
        out.append(f"  {name:<20} {b:>12} bytes")
    out.append(f"  drop: {drop:.1f}%")
    return "\n".join(out)

    التمارين

    1. وسّعه لـ ZeRO-2 بتقسيم الـ gradients: كل rank يخزّن gradient الـ shard بتاعه بس، عن طريق إنك تصفّر الجزء اللي مش بتاعه بعد الـ backward.
      تلميحبعد الـ reduce_scatter انت أصلًا عندك local_grad بتاعك. اعمل p.grad = None لكل الـ parameters (أو صفّرهم) قبل الـ Adam، وخزّن local_grad بس. الـ bandwidth ما اتغيرش لأن نفس الـ reduce_scatter و allgather.
    2. Memory profiler يطبع الـ fp32 bytes الفعلية على rank 0 قصاد المعادلة.
      تلميحاجمع t.numel() * t.element_size() لكل tensor: الـ params، الـ grads، و master/m/v. هتلاقي الفعلي مختلف عن المعادلة لأن الكود كله fp32 (مفيش fp16 حقيقي)، فالـ params والـ grads 4 bytes مش 2. اشرح الفرق ده في التقرير.
    3. قيس الوقت لكل step في DDP قصاد ZeRO-1 وقسّمه لـ forward و backward و comm.
      تلميحtime.perf_counter() حوالين كل جزء، و dist.barrier() قبل ما تقفل التايمر بتاع الـ comm عشان تقيس أبطأ rank. خد الـ median بعد كام step warmup.
    4. Gradient clipping تحت ZeRO-1: الـ L2 norm لازم يتحسب على كل الـ shards بـ allreduce لمربع الـ norm المحلي.
      تلميحبعد الـ reduce_scatter والقسمة: sq = local_grad.pow(2).sum()، dist.all_reduce(sq)، norm = sq.sqrt()، coef = min(1, max_norm / (norm + 1e-6))، local_grad.mul_(coef). الـ padding أصفار فمش بيأثر. معمل ٣ بيوريك الحسبة دي.
    5. «ZeRO ساذج» بـ allreduce بدل reduce_scatter، وقيس فرق وقت السلك. دافع عن الـ reduce_scatter بالأرقام.
      تلميحdist.all_reduce(padded_grad) وبعدين خد الـ slice بتاعك. كده بتدفع allreduce كامل (= reduce_scatter + allgather) وكمان allgather للـ params، يعني حوالي ١.٥ ضعف الـ bytes. عدّ الـ bytes بالمعادلات من درس ٧٦ وبعدين قيس.
    6. إضافة مني · قرار حقيقي قبل حجز cluster: اكتب pick_stage(P, N, gpu_gb, act_gb) ترجع أقل stage يدخل الموديل في الـ GPU (DDP، 1، 2، 3)، وتطبع الذاكرة لكل واحد.
      الحللكل stage احسب: DDP 16P، Z1 4P + 12P/N، Z2 2P + 14P/N، Z3 16P/N، زوّد act_gb (الـ activations ما بتتقسمش بـ ZeRO)، وارجع أول واحد ≤ gpu_gb. مثال: 13B على 8 GPUs بـ 80 GB ومن غير activations: DDP = 208، Z1 = 71.5 GB، فـ stage 1 يكفي. لو الـ activations 20 GB، Z1 = 91.5 ومش هيدخل، و Z2 = 26 + 22.75 + 20 = 68.75 فـ stage 2.
    08

    إضافة مني: اللي الدرس ما قالوش

    الحدس في سطر: في DDP كل الـ N ranks بيعملوا نفس الـ Adam step بالظبط على نفس الأرقام. ده تكرار N مرة لحساب واحد ولذاكرة واحدة. ZeRO-1 بيلغي التكرار ده: كل واحد يعمل جزء، والكل يتبادل النتيجة.

    أخطاء شائعة

    • إنك تفتكر الكود بيستخدم fp16 فعلًا. الـ demo كله fp32. الـ 16P و 4P+12P/N في الجدول معادلة للـ mixed precision، مش قياس من الـ run. وكمان العنوان بيقول «optimiser memory» بس الرقم فيه الـ params والـ grads كمان. (تمرين ٢ بيخليك تقيس الفعلي.)
    • الـ shard الفاضي. لو الـ total صغير جدًا بالنسبة لـ N (مثلًا 5 على 4)، الـ shard_bounds بترجع لآخر rank start = 6 و end = 5: shard كله padding. الكود شغال لأنه بيستخدم الـ chunk مش end − start، بس لو كتبت كود بيعتمد على end − start هيطلع سالب.
    • ZeRO ما بيقللش الـ activations. لو الـ activations هي اللي مالية الـ GPU (sequences طويلة)، ZeRO مش الحل. الحل activation checkpointing أو pipeline (بكرة).
    • إن الـ clipping أو أي حاجة محتاجة «الـ gradient كله» لازم تبقى collective. الـ norm، والـ NaN check، وأي logging لإحصائيات الـ gradient. لو rank حسبها محليًا هيشوف جزء بس.

    بيظهر فين في الـ LLMs

    أغلب الـ fine-tuning الكامل لموديلات 7B وأكبر على أكتر من GPU بيستخدم DeepSpeed ZeRO أو FSDP، وده سبب إن config زي "zero_optimization": {"stage": 2} بتشوفه في scripts كتير. وفي الـ pretraining الكبير، ZeRO-1 بيتجمع مع pipeline و tensor parallel. والفكرة نفسها (اللي مش محتاجه دلوقتي ما تشيلوش) هي اللي ورا الـ CPU offload في DeepSpeed.

03

الـ Discriminative Learning Rates: كل طبقة بسرعتها

لما تفك التجميد، الطبقات الأولى لازم تتدرب أبطأ من الأخيرة. الأولى فيها features عامة عايز تحافظ عليها، والأخيرة فيها هيكل خاص بالمهمة لازم يتحرك كتير.

lr_stage_i = base_lr · decay^(N − 1 − i)

في PyTorch ده مجرد list من الـ parameter groups بتديها للـ optimizer. موديل واحد، كذا learning rate، ومن غير كود زيادة.

ده ResNet18 بمراحله: conv1+bn1، layer1..layer4، وfc (head بـ 10 كلاسات). أعداد الـ parameters حقيقية لـ ResNet18.

جرب: غيّر الـ mode. في «Progressive» حرّك الـ epoch وشوف المراحل بتتفك من الآخر للأول. في «Discriminative» حرّك الـ decay: عند 0.3 الـ conv1 بياخد 0.3⁵ ≈ 0.00243 من الـ base_lr. يبان متطرف، بس عمليًا بيشتغل.

جدول بيفك مرحلة واحدة كل epoch من الآخر للأول: الأول الـ head لوحده، وبعدين layer4، وبعدين layer3… ده بيقلل الـ feature drift على حساب epochs زيادة. نقطة مهمة جدًا: ابني الـ optimizer من جديد كل ما مجموعة الـ parameters المتدربة تتغير، وإلا الـ parameters اللي كانت متجمدة هتفضل شايلة moments متخزنة تلخبطه.

04

Layer-wise LR decay: النسخة الناعمة

نسخة أنعم من الـ discriminative LR بتستخدم في الـ fine-tuning الحديث (BEiT، DINOv2، fine-tunes لـ ViT-B). بدل ما تقسم الطبقات لمراحل، كل طبقة بتاخد LR أصغر شوية من اللي فوقها:

lr_layer_k = base_lr · decay^(L − k)

مع decay = 0.75 و L = 12 transformer block، أول block بيتدرب بـ 0.75¹¹ ≈ 0.04× من LR الـ head. ده بيفرق أكتر في الـ transformers من الـ CNNs، لأن في الـ CNN تقسيم المراحل غالبًا كفاية.

تشبيه: الـ discriminative LR زي سلم بدرجات كبيرة، والـ layer-wise decay زي رامب منحدر ناعم. نفس الفكرة: كل ما تنزل لتحت، تتحرك أبطأ.

05

مشكلة الـ BatchNorm: إحصائيات من عالم تاني

طبقات الـ BN شايلة buffers اسمها running_mean وrunning_var اتحسبت على ImageNet. لو مهمتك ليها توزيع بيكسلز مختلف (إضاءة مختلفة، sensor مختلف، color space مختلف) الـ buffers دي غلط. ٣ حلول بالترتيب ده:

  1. Fine-tune والـ BN في train mode: سيب الـ BN يحدّث الإحصائيات مع باقي الشبكة. الاختيار الافتراضي لما الداتا متوسطة (≥ 5k صورة).
  2. جمّد الـ BN في eval mode: احتفظ بإحصائيات ImageNet ودرّب الأوزان بس. صح لما الداتا صغيرة لدرجة إن المتوسط المتحرك هيبقى noisy.
  3. استبدل BN بـ GroupNorm: بيشيل مشكلة المتوسط المتحرك خالص. بيستخدم في backbones الـ detection والـ segmentation لما الـ batch لكل GPU صغير جدًا.

لو غلطت هنا، الـ accuracy بتنزل 5–15% من غير ما أي error يظهر.

معمل: شوف الـ normalization بيبوظ

المنحنى الرمادي المتقطع هو اللي الطبقات اللي بعد كده متعودة عليه: توزيع طبيعي mean=0 و std=1. المنحنى البرتقالي هو activations داتا مهمتك بعد ما اتعملها normalize بالإحصائيات الحالية.

حرّك الـ domain shift، وبعدين زوّد عدد خطوات التدريب في train mode وشوف الـ running stats بتلحق (momentum = 0.1، زي الـ default في PyTorch). صغّر الـ batch size وشوف الـ noise.

ملاحظة: ده نموذج مبسط لطبقة BN واحدة عشان تشوف الفكرة، مش محاكاة لشبكة كاملة.

06

تصميم الـ head وإيه اللي تقيسه

الـ classifier head هو 1–3 طبقات linear ومعاهم dropout اختياري. كل backbone في torchvision جاي بـ head افتراضي انت بتبدله، ومكانه بيختلف حسب الموديل:

backbone.fc = nn.Linear(backbone.fc.in_features, num_classes)   # ResNet
backbone.classifier[1] = nn.Linear(..., num_classes)             # EfficientNet, MobileNet
backbone.heads.head = nn.Linear(..., num_classes)                # torchvision ViT

للداتا الصغيرة، طبقة linear واحدة غالبًا كفاية. إضافة طبقة مخفية (Linear → ReLU → Dropout → Linear) بتساعد لما توزيع المهمة يبقى أبعد عن اللي الـ backbone اتدرب عليه.

رقمين لازم تطبعهم دايمًا

الرقممعناه
Pretrained-only accuracy (linear probe)دقة الـ head والـ backbone متجمد. ده الأرضية.
Fine-tuned accuracyنفس الموديل بعد تدريب end-to-end. ده السقف.
القاعدة الذهبية: لو الـ fine-tuned طلع أقل من الـ linear probe، يبقى عندك bug في الـ LR أو الـ BN. ليه؟ لأن الـ linear probe نفسه حالة خاصة من الـ fine-tuning فيها LR الـ backbone = صفر. فالـ fine-tune المظبوط لازم يساويه على الأقل.

الدرس بيذكر إن 5 epochs بالوصفة دي على CIFAR-10 بتاخد ResNet18-IMAGENET1K_V1 من حوالي 70% (linear probe) لحوالي 93% (fine-tuned)، والـ head لوحده بيقف عند حوالي 86%.

خطوة ٣: الـ parameter groups بـ LR لكل مرحلة

def discriminative_param_groups(model, base_lr=1e-3, decay=0.3):
    stages = [["conv1", "bn1"], ["layer1"], ["layer2"],
              ["layer3"], ["layer4"], ["fc"]]
    groups = []
    for i, names in enumerate(stages):
        lr = base_lr * (decay ** (len(stages) - 1 - i))   # الـ fc بياخد base_lr، واللي قبله أصغر
        params = [p for n, p in model.named_parameters()
                  if any(n.startswith(k) for k in names) and p.requires_grad]  # المتدرب بس
        if params:
            groups.append({"params": params, "lr": lr, "name": "_".join(names)})
    return groups

خطوة ٤: جمّد إحصائيات الـ BatchNorm

def freeze_bn_stats(model):
    for m in model.modules():
        if isinstance(m, (nn.BatchNorm1d, nn.BatchNorm2d, nn.BatchNorm3d)):
            m.eval()                         # وقّف تحديث running_mean/var
            for p in m.parameters():
                p.requires_grad = False      # وجمّد gamma و beta كمان
    return model

نادِه بعد model.train() في أول كل epoch. الـ model.train() بيقلب كل حاجة لـ training mode، والدالة دي بترجّع الـ BN بس لـ eval.

خطوة ٥: الـ training loop

from torch.optim import SGD
from torch.optim.lr_scheduler import CosineAnnealingLR
import torch.nn.functional as F

def train_and_eval(model, train_loader, val_loader, device, epochs=2, base_lr=1e-3, freeze_bn=False):
    model = model.to(device)
    groups = discriminative_param_groups(model, base_lr=base_lr)
    if not groups:   # احتياطي لو مفيش groups
        groups = [{"params": [p for p in model.parameters() if p.requires_grad], "lr": base_lr}]
    optimizer = SGD(groups, momentum=0.9, weight_decay=1e-4, nesterov=True)
    scheduler = CosineAnnealingLR(optimizer, T_max=max(epochs, 1))

    last_val = 0.0
    for epoch in range(epochs):
        model.train()
        if freeze_bn:
            freeze_bn_stats(model)           # بعد train() مش قبلها
        tr_loss, tr_correct, tr_total = 0.0, 0, 0
        for x, y in train_loader:
            x, y = x.to(device), y.to(device)
            logits = model(x)
            loss = F.cross_entropy(logits, y, label_smoothing=0.1)
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            tr_loss += loss.item() * x.size(0)
            tr_total += x.size(0)
            tr_correct += (logits.argmax(-1) == y).sum().item()
        scheduler.step()

        model.eval()                         # تقييم من غير gradient
        va_total, va_correct = 0, 0
        with torch.no_grad():
            for x, y in val_loader:
                x, y = x.to(device), y.to(device)
                pred = model(x).argmax(-1)
                va_total += x.size(0)
                va_correct += (pred == y).sum().item()
        last_val = va_correct / va_total
        print(f"  epoch {epoch}  train {tr_loss/tr_total:.3f}/{tr_correct/tr_total:.3f}  val {last_val:.3f}")
    return last_val

خطوة ٦: Progressive unfreezing

def progressive_unfreeze_schedule(model):
    stages = ["layer4", "layer3", "layer2", "layer1"]   # من الآخر للأول

    def start():                     # مرة واحدة قبل أول epoch
        for p in model.parameters():
            p.requires_grad = False
        for p in model.fc.parameters():
            p.requires_grad = True

    def unfreeze(epoch):             # في أول كل epoch
        if epoch < len(stages):
            name = stages[epoch]
            for n, p in model.named_parameters():
                if n.startswith(name):
                    p.requires_grad = True
            return name
        return None

    return start, unfreeze
# مهم: ابني optimizer جديد كل ما unfreeze ترجع اسم مرحلة

التمارين

  1. (سهل) Linear probe ضد full fine-tune: درّب ResNet18 بالطريقتين على نفس الـ synthetic dataset وحط الدقتين جنب بعض. أنهي فرق بيقولك إن الـ features بتتنقل كويس، وأنهي بيقولك لأ؟
    تلميحلو الـ linear probe لوحده عالي وقريب من الـ fine-tune: الـ features بتتنقل كويس والـ head كفاية. لو الـ fine-tune أعلى بكتير: المهمة محتاجة الـ features تتأقلم (domain أبعد). لو الـ fine-tune أقل من الـ probe: ده bug مش نتيجة.
  2. (متوسط) اعمل الـ bug بإيدك: حط base_lr = 1e-1 على مرحلة الـ backbone بدل الـ head. شوف الـ loss بينفجر، وبعدين صلّحه بـ discriminative_param_groups. سجّل الـ LR اللي كل مرحلة بتبدأ تنهار عنده.
    تلميحاعمل loop على LRs زي [1e-4, 1e-3, 1e-2, 1e-1] وكل مرة غيّر مرحلة واحدة بس وسيب الباقي متجمد. اطبع الـ loss بعد كام batch. علامة الانهيار: loss بيطلع nan أو بيزيد بدل ما يقل، أو كل التوقعات كلاس واحد.
  3. (صعب) Medical imaging: خد dataset طبي (CheXpert-small أو PatchCamelyon أو HAM10000) وقارن ٣ طرق: (a) backbone متجمد + linear head، (b) fine-tune end-to-end، (c) تدريب من الصفر. سجّل الدقة وتكلفة الـ compute. عند أنهي حجم داتا التدريب من الصفر بيبدأ ينافس؟
    تلميحجرب subsets بأحجام متضاعفة (مثلًا 500، 1k، 2k، 5k…) وارسم الدقة ضد الحجم لكل طريقة. افتكر إن الصور دي domain بعيد، فاتوقع (b) يتفوق على (a) أكتر من العادي. ولو الصور grayscale فكّر في الـ BN.
  4. إضافة مني · Freeze inspector: اكتب inspect(model, optimizer) تطبع لكل top-level module: عدد الـ parameters المتدربة والمتجمدة، وكام BN في eval mode، وبعدين تتأكد إن كل parameter متدرب موجود في الـ optimizer وإن مفيش parameter متجمد فيه. ده بالظبط الفحص اللي هتعمله قبل أي fine-tune حقيقي (ودي فكرة outputs/skill-freeze-inspector.md).
    تلميح opt_ids = {id(p) for g in optimizer.param_groups for p in g["params"]}. لكل model.named_children() اجمع p.numel() حسب p.requires_grad. للـ BN: isinstance(m, nn.BatchNorm2d) and not m.training. جربها مرة بعد model.train() ومرة بعد freeze_bn_stats وشوف الفرق.

إضافة مني: اللي الدرس مقالهوش صريح

الحدس في سطر

الـ pretrained weights مش «إجابة»، هي نقطة بداية ممتازة في فضاء الأوزان. الـ LR الصغير معناه «اتحرك حوالين النقطة دي بس». الـ LR الكبير معناه «انسى النقطة دي»، وده اللي اسمه catastrophic forgetting.

غلطات شائعة

الغلطةالعَرَضالحل
normalize بأرقام غير اللي الموديل اتدرب بيهادقة أقل من المتوقع من غير errorاستخدم نفس mean/std بتوع الأوزان (ImageNet هنا)، أو الـ transforms اللي جاية مع الـ weights
نسيت تبني optimizer جديد بعد unfreezeالمراحل اللي اتفكت مش بتتدرب، أو بتتدرب بشكل غريبابني الـ optimizer بعد كل تغيير في requires_grad
نادِت freeze_bn_stats قبل model.train()الـ BN رجع train mode وانت مش واخد بالكدايمًا بعد train()، في أول كل epoch
LR الـ scratch (زي 0.1) على backbone متدربloss بينفجر أو كل التوقعات كلاس واحدLR أصغر بكتير + discriminative groups
مقارنة بـ fine-tune بس من غير linear probeمش عارف النتيجة كويسة ولا فيه bugاطبع الرقمين دايمًا

ده بيظهر فين في الـ LLMs والـ agents؟

  • • نفس الفكرة بالظبط في الـ NLP: الدرس نفسه بيشاور على ULMFiT، الورقة اللي بدأت discriminative LR و progressive unfreezing في موديلات اللغة.
  • • Fine-tuning الـ LLMs: LoRA (اللي شفته في يوم ١) هو أقصى درجات «جمّد الـ backbone»: الأوزان الأصلية متجمدة خالص وبتدرب مصفوفات صغيرة بس جنبها.
  • • Linear probes: بيستخدموا عشان تختبر «هل المعلومة دي موجودة في الـ hidden states بتاعة الموديل؟» من غير ما تغير الموديل.
  • • Embeddings + classifier: في شغل الـ agents كتير بتاخد embedding model متجمد وتحط فوقه classifier صغير (لتصنيف intents أو routing). ده feature extraction بالحرف.
  • • Catastrophic forgetting: نفس الخطر لما تعمل fine-tune لـ LLM بـ LR كبير: بيتعلم مهمتك وينسى قدرات عامة كانت عنده.

01

المشكلة: من «اضغط على الحاجة» لـ «قولّي اسمها»

أول SAM (2023) كان بياخد visual prompt بس: تضغط نقطة أو ترسم box وهو يرجعلك mask للحاجة دي. لو عايز «كل البرتقان في الصورة» كنت محتاج detector (زي Grounding DINO) يطلّع boxes، وبعدين SAM يعمل segment لكل box. ده اسمه Grounded SAM: موديلين متحطين ورا بعض (cascade)، وأي غلطة من الأول بتتنقل للتاني.

SAM 3 (من Meta، نوفمبر 2025) شال الـ cascade. بتدّيله جملة اسمية قصيرة ("yellow school bus") أو صورة مثال (image exemplar)، وبيرجعلك كل الـ masks المطابقة مع instance ID لكل واحد، في forward pass واحد. المهمة دي اسمها Promptable Concept Segmentation (PCS).

تشبيه: SAM الأول زي موظف استقبال لازم تشاور له على كل كرسي في القاعة. Grounded SAM زي موظفين: واحد يدوّر على الكراسي وواحد يرسمهم، ولو الأول فاته كرسي التاني مش هيعرف. SAM 3 موظف واحد تقوله «هاتلي كل الكراسي الحمرا» فيرجعلك القايمة كلها.

الدرس ده مش عن موديل جديد بس، ده عن تحول هيكلي: الـ segmentation والـ detection وربط النص بالصورة اتجمعوا في موديل واحد. السؤال في الإنتاج بقى «أنهي موديل promptable بيحل حالتي end-to-end؟» مش «أركّب أنهي pipeline؟».

كمان فيه تحديث SAM 3.1 Object Multiplex (مارس 2026) بيخلّي تتبّع (tracking) كذا instance من نفس المفهوم في الفيديو أسرع، وهنوصله بعدين.

إيه هو الـ concept prompt؟

جملة اسمية قصيرة ("striped red umbrella", "hand holding a mug") أو صورة مثال. مش جملة كاملة. الفرق عن SAM الكلاسيك في ٣ حاجات:

  1. مفيش prompt لكل instance: prompt واحد بيرجّع كل المطابقات.
  2. Open-vocabulary: المفهوم أي حاجة تقدر توصفها بالكلام، مش قايمة labels ثابتة.
  3. Multiple instances: بيرجّع كذا instance مرة واحدة بدل mask واحد لكل prompt.

معمل ١: شوف الـ pipeline بتتغير

دوس «التالي» وشوف إزاي الجيل التالت بيشيل خطوات من النص. الدوائر المنوّرة هي اللي شغالة في كل خطوة.

لاحظ: في Grounded SAM فيه عقدة detector منفصلة بين النص والـ mask. في SAM 3 العقدة دي اندمجت في الموديل نفسه.
03

معمارية SAM 3: أجزاء الموديل

  • Shared backbone: ViT واحد بيعالج الصورة. الـ detector والـ tracker الاتنين بيقروا منه، فمفيش حساب مكرر.
  • Presence head: بيتوقع «المفهوم ده موجود في الصورة أصلًا؟» منفصل عن «فين هو؟». ده بيقلل الـ false positives لما تسأل عن حاجة مش موجودة، ويخلّي الموديل يقول «مفيش» بنضافة.
  • Decoupled detector-tracker: الكشف على مستوى الصورة والتتبع على مستوى الفيديو ليهم heads منفصلة، مش بيتخانقوا على نفس الأوزان.
  • Memory bank: بيخزن features كل instance عبر الفريمات للتتبع (نفس فكرة SAM 2).
تشبيه الـ presence head: تخيل حارس بيسأل الأول «فيه قطط في الأوضة؟» قبل ما يبدأ يدوّر على مكانهم. موديل مجبر يطلّع boxes في كل الأحوال هيألّف قطة من أي حاجة قريبة منها. الـ presence head بيدّيله حق يقول «لأ».

معمل ٢: الـ presence وحاجز الـ score

فيه ٥ مرشحين (candidates) بـ score لكل واحد. كل نتيجة نهائية = score × احتمال وجود المفهوم. حرّك احتمال الـ presence وحاجز القبول وشوف مين بينجو.

لاحظ: لما الـ presence يقل (المفهوم غالبًا مش موجود)، كل المرشحين بينزلوا مع بعض ويقعوا تحت الحاجز، فبتحصل «صفر detections» نضيفة. ده بالظبط اللي الـ presence head بيحققه.
04

التدريب على نطاق ضخم: 4 مليون مفهوم

SAM 3 اتدرّب على 4 مليون مفهوم مختلف طلعتهم data engine: دورة بتعمل annotation بالـ AI وبعدين مراجعة وتصحيح بشري، وتتكرر. وفيه benchmark جديد اسمه SA-CO فيه 270 ألف مفهوم، أكبر بـ 50 مرة من الـ benchmarks اللي قبله. SAM 3 بيوصل لـ 75-80% من أداء البشر على SA-CO، وبيضاعف أداء الأنظمة الموجودة في PCS للصور والفيديو.

ليه الأرقام دي مهمة؟ لأن «open-vocabulary» ملهاش معنى لو الموديل شاف 80 كلمة بس. كمية المفاهيم هي اللي بتخلي "striped red umbrella" تشتغل مش بس "umbrella".
05

SAM 3.1 Object Multiplex

قبل كده تتبع N instance كان معناه N memory banks منفصلة، فالتكلفة بتكبر خطيًا مع عدد الأجسام. Object Multiplex (مارس 2026) بيجمعهم في ذاكرة واحدة مشتركة مع query لكل instance بيسحب منها اللي يخصه. النتيجة: تتبع أسرع بكتير للأجسام الكتيرة من غير ما الدقة تقل. مهم للزحمة والمشاهد المتراصة.

معمل ٣: تكلفة الذاكرة، منفصلة ضد مشتركة

الأرقام هنا نموذج مبسّط للفكرة (وحدات ذاكرة افتراضية)، مش قياسات حقيقية من الموديل. حرّك عدد الأجسام وحجم الذاكرة للفريم.

لاحظ: في الطريقة القديمة التكلفة = N × M. في Multiplex ذاكرة واحدة M وبتضيف query صغيير لكل جسم. الفرق بيكبر مع N.

SAM-MI: الكفاءة

  • Sparse point prompting: نقط قليلة مختارة بدل prompts كثيفة، بيقلل نداءات الـ decoder بنسبة 96%.
  • Shallow mask aggregation: بيدمج masks خشنة في mask واحد أحدّ.
  • Decoupled mask injection: الـ decoder بيستلم mask features محسوبة قبل كده بدل ما يشتغل من الأول.

النتيجة: حوالي 1.6× أسرع من Grounded-SAM على benchmarks الـ open-vocabulary.

التبديل من Grounded SAM 2 لـ SAM 3: الـ latency غالبًا متعادلة أو أسرع شوية (شلت forward pass للـ detector بس الموديل أتقل). الدقة أحسن بوضوح على المفاهيم النادرة والمركبة ("striped red umbrella") ومشابهة على الكلمات الشائعة. المرونة أقل: SAM 3 monolithic.

كل الموديلات بترجّع نفس الشكل تقريبًا (boxes + labels + scores + masks + IDs)، فالكود اللي بعدهم مش محتاج يفرّق بين مين اشتغل.

الكود: افتح الملف واكتبه بإيدك

اكتب كل مقطع بنفسك. النسخ بيخليك تحس إنك فاهم من غير ما تكون فاهم فعلًا.

الخطوة ١: تقسيم الجملة لـ concepts

الموديل بياخد مفهوم واحد في كل forward pass. لو المستخدم كتب «قطط وكلاب وبالونات» لازم نقسمها ونلف عليها.

def split_concepts(sentence):
    normalised = sentence
    # نوحّد كل الفواصل في فاصلة واحدة
    for sep in [" and ", " or ", "&", ";"]:
        normalised = normalised.replace(sep, ",")
    if "," in normalised:
        parts = [p.strip() for p in normalised.split(",")]
        return [p for p in parts if p]
    return [sentence.strip()]

الخطوة ٢: RLE، تخزين الـ mask بحجم صغير

الـ mask مصفوفة 0/1. الـ run-length encoding بيخزن «كام صفر ورا بعض وكام واحد» بدل كل خانة، فالـ response يفضل خفيف حتى مع masks كتيرة عالية الدقة.

def rle_encode(binary_mask):
    flat = binary_mask.flatten().astype("uint8")
    if flat.size == 0:
        return ""
    runs = []
    prev = int(flat[0])
    count = 0
    for v in flat:
        iv = int(v)
        if iv == prev:
            count += 1          # لسه نفس القيمة
        else:
            runs.append((prev, count))
            prev, count = iv, 1 # بدأنا run جديدة
    runs.append((prev, count))
    return ";".join(f"{v}x{c}" for v, c in runs)

التمارين

  1. (سهل) شغّل SAM 3 على 10 صور بـ concept prompts من اختيارك. قارن مع SAM 2 + Grounding DINO 1.5 على نفس الصور. مين فاته مفاهيم إيه؟
    الإجابةتلميح: سجّل في جدول: الصورة، الـ prompt، عدد اللي لقاه كل موديل، وعدد اللي كان لازم يلاقيه (عدّه بإيدك). غالبًا الفرق هيظهر في المفاهيم المركبة (لون + نوع + حالة) أكتر من الكلمات الشائعة.
  2. (متوسط) ابني UI «click-to-include / click-to-exclude» فوق SAM 3: الـ text prompt يرجّع candidates، والمستخدم يضغط يقرر مين يتحسب. اطلّع المفاهيم النهائية كـ JSON.
    الإجابةتلميح: خزّن لكل candidate الـ instance_id وحالة included: true/false. الضغطة بتقلب الحالة. الـ JSON النهائي = اللي included بس، بنفس هيكل ConceptDetection.
  3. (صعب) اعمل fine-tune لـ SAM 3 على مفاهيم مخصصة (مثلًا 5 أنواع قطع إلكترونية) بـ 20 صورة لكل نوع. قارن بـ zero-shot على نفس الـ test set بقياس mask IoU.
    الإجابةتلميح: قسّم الصور train/test قبل ما تبدأ ومتلمسش الـ test. قيس IoU لكل mask وخد المتوسط لكل نوع، مش المتوسط الكلي بس، عشان تشوف أنهي نوع استفاد أكتر.
  4. تمرين مني · اختبر الـ presence: اكتب prompt لحاجة مش موجودة أكيد في الصورة (مثلًا zebra في صورة مكتبك). إيه اللي تتوقعه ولو لقيت detections إيه تعمل؟
    الإجابةالصح إن الـ presence head يرجّع «مش موجود» وصفر detections. لو رجّع detections بـ scores واطية، حط حاجز score (والـ presence score لو الـ API بيرجّعه) واعتبر أي نتيجة تحته غير موجودة. وسجّل الحالة دي كـ false positive لو حصلت بـ score عالي.

إضافة مني: حدس، أخطاء شائعة، وفين بتظهر

  • الـ prompt بتاعك هو الـ API: «noun phrase» مش جملة. "the cup that is on the left side of the laptop" جملة علاقات مش مفهوم. جرّب "cup" وبعدين فلتر بالـ boxes بنفسك.
  • متدمجش مفهومين في prompt: "cats and dogs" مش هيتقسم تلقائيًا جوه الموديل. استخدم split_concepts والف على كل مفهوم.
  • RLE مش بتشتغل مع mask مفرود بترتيب مختلف: لازم تفك بنفس الـ shape واترتيب الـ flatten (صفوف أولًا) اللي رمّزت بيه.
  • الحاجز ثابت مش ذكي: score 0.5 مناسب لمفهوم شائع، مش لمفهوم نادر. راقب الـ distribution لكل مفهوم قبل ما تثبت threshold.
  • فين بيظهر في الـ LLMs والـ agents: SAM 3 بيشتغل كـ tool للـ VLM أو الـ agent: الـ agent يقول «هات كل الـ buttons الحمرا»، SAM 3 يرجّع masks، والـ agent يقرر يضغط على أنهي. نفس فكرة open-vocabulary بتاعة CLIP بس بمخرجات pixel-level.

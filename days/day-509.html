تسخين ٥ دقايق: فاكر امبارح؟

امبارح بنيت sharded checkpoint بـ atomic write. جاوب في دماغك الأول.

  1. ليه rename الـ manifest لازم يبقى آخر خطوة؟ وليه فولدر لكل step؟
    الإجابةكل rename لوحده atomic، بس المجموعة مش transaction. فالـ manifest هو لحظة الـ commit: من غيره الـ checkpoint الجديد «مش موجود». والفولدر لكل step بيخلّي crash قبل الـ commit يسيب الـ checkpoint القديم شغال؛ لو نفس الفولدر، الـ shard renames بتبدّل القديم قبل ما الـ manifest الجديد يوصل.
  2. إيه الـ ٣ حقول المهمة في الـ manifest؟
    الإجابةworld_size (resume على عدد مختلف يفشل بصوت عالي)، sha256 لكل shard (بيمسك الكتابة الناقصة)، و param_shard_offset/param_shard_numel (يرجّع كل shard لمكانه في الـ flat tensor).
  3. ليه gather-then-write مش بيكبر مع الـ cluster؟
    الإجابةكل الحالة بتعدّي من port واحد عند rank 0، فالسرعة = أبطأ link واحد. الكتابة المقسّمة بتستخدم كل الـ links بالتوازي.
الربط بالنهاردة: هتلاحظ إن الـ demo بتاع النهاردة بيجمّع الحالة على rank 0 وهو اللي بيكتب الـ ٤ shards. ده بالظبط النمط اللي امبارح قلنا إنه مش بيكبر. ليه مقبول هنا؟ هنرجعله في قسم «إضافة مني».

الـ Mini GPT، وليه مش MLP

الموديل صغير بقصد: ٢ transformer blocks، embed dim 32، ٤ attention heads، vocab 64، sequence length 16، batch 4. كبير كفاية يختبر كل قرار توصيل (masked multi-head attention، LayerNorm ليها weights لازم تتزامن، LM head منفصل يرجع للـ vocab)، وصغير كفاية إن ٢٠ step على ٤ CPU ranks يخلصوا في ثواني.

ليه مش الـ MLP بتاع درس ٧٧؟ الـ MLP كفاية عشان تتأكد من مزامنة الـ gradients. الـ GPT بيضيف ٣ حاجات: LM head منفصل فوق الـ vocab (هنا untied للوضوح؛ الـ GPT الكامل غالبًا بيربطه بالـ token embedding)، و softmax + cross-entropy كـ loss (حالات رقمية أكتر من MSE)، و forward مش متماثل (embeddings ← attention ← MLP في كل layer). لو فضلنا على MLP، كان هيستخبّى علينا هل التركيب بيتعامل صح مع LayerNorm ومع شكل gradient الـ embedding.

قواعد التركيب: كل قطعة ليها واجهة ضيقة

spawn 4 ranks → broadcast init GPT params → for 20 steps: forward + backward (batch خاص بكل rank)
→ ZeRO-1 step: reduce_scatter grads + Adam on shard + allgather params → عند step 10: sharded checkpoint
→ كمّل لـ 20 → memory profile + resume verify + exit 0
القطعةماسكة إيهبتسيب إيه للـ loop
DDP broadcastمزامنة الـ parameters في البدايةنداء واحد وقت البناء
ZeRO-1 stepمزامنة الـ gradients، تحديث الـ master copy، توزيع الـ parametersنداء واحد كل step بدل optimizer.step
Sharded checkpointحفظ حالة كل rank، manifest بـ sha256بيتنادى على rank 0 بالحالة اللي اتجمعت بـ allgather
Training loopforward و backward وتسجيل الـ lossبينادي التلاتة اللي فوق بالترتيب

الـ loop نفسها ما تعرفش حاجة عن reduce_scatter ولا ملفات rendezvous. ولاحظ: الـ allreduce بتاع DDP مش موجود، لأن reduce_scatter بتاع ZeRO-1 هو اللي بيمزامن الـ gradients. الحاجة الوحيدة اللي فاضلة من DDP هي الـ broadcast في الأول.

معمل ٢: امشي مع step واحد

كل صف = rank، والـ flat vector بتاعه متقسّم ٤ chunks (chunk لكل rank). اتبع الألوان: كل rank بيبدأ بـ gradient مختلف (داتا مختلفة)، الـ reduce_scatter بيدّي كل rank مجموع الـ chunk بتاعه بس، الـ Adam بيحدّث الـ chunk ده بس، والـ allgather بيرجّع الموديل كامل ومتطابق عند الكل. وعند step 10 هتشوف الـ checkpoint.

class CausalSelfAttention(nn.Module):
    def __init__(self, embed_dim, num_heads):
        super().__init__()
        assert embed_dim % num_heads == 0
        self.num_heads, self.head_dim = num_heads, embed_dim // num_heads
        self.qkv = nn.Linear(embed_dim, 3 * embed_dim, bias=False)   # Q و K و V في matmul واحد
        self.proj = nn.Linear(embed_dim, embed_dim, bias=False)

    def forward(self, x):
        b, t, e = x.shape
        q, k, v = self.qkv(x).reshape(b, t, 3, self.num_heads, self.head_dim).unbind(dim=2)
        q, k, v = q.transpose(1, 2), k.transpose(1, 2), v.transpose(1, 2)
        attn = (q @ k.transpose(-2, -1)) / math.sqrt(self.head_dim)
        mask = torch.triu(torch.ones(t, t), diagonal=1).bool()       # ممنوع تبص على المستقبل
        attn = attn.masked_fill(mask, float("-inf")).softmax(dim=-1)
        out = (attn @ v).transpose(1, 2).reshape(b, t, e)
        return self.proj(out)

class TransformerBlock(nn.Module):
    def __init__(self, embed_dim, num_heads):
        super().__init__()
        self.ln1 = nn.LayerNorm(embed_dim)
        self.attn = CausalSelfAttention(embed_dim, num_heads)
        self.ln2 = nn.LayerNorm(embed_dim)
        self.mlp = nn.Sequential(nn.Linear(embed_dim, 4 * embed_dim), nn.GELU(),
                                 nn.Linear(4 * embed_dim, embed_dim))
    def forward(self, x):
        x = x + self.attn(self.ln1(x))     # pre-norm + residual
        return x + self.mlp(self.ln2(x))

class MiniGPT(nn.Module):
    def __init__(self):
        super().__init__()
        self.tok_embed = nn.Embedding(VOCAB, EMBED_DIM)
        self.pos_embed = nn.Embedding(SEQ_LEN, EMBED_DIM)
        self.blocks = nn.ModuleList([TransformerBlock(EMBED_DIM, NUM_HEADS) for _ in range(NUM_LAYERS)])
        self.ln_f = nn.LayerNorm(EMBED_DIM)
        self.head = nn.Linear(EMBED_DIM, VOCAB, bias=False)          # untied للوضوح
    def forward(self, ids):
        b, t = ids.shape
        x = self.tok_embed(ids) + self.pos_embed(torch.arange(t))
        for blk in self.blocks:
            x = blk(x)
        return self.head(self.ln_f(x))

M2: الـ flat helpers

def flat_param_numel(module):
    return sum(p.numel() for p in module.parameters())

def gather_flat_params(module):          # كل الـ params في tensor واحد fp32
    return torch.cat([p.detach().to(torch.float32).flatten() for p in module.parameters()])

def scatter_flat_to_params(module, flat): # العكس: رجّع كل جزء لمكانه
    offset = 0
    for p in module.parameters():
        n = p.numel()
        p.data.copy_(flat[offset:offset + n].reshape(p.shape).to(p.dtype))
        offset += n

def gather_flat_grads(module):            # لو param ملوش grad حط أصفار، عشان الطول يفضل ثابت
    return torch.cat([(torch.zeros_like(p.data, dtype=torch.float32) if p.grad is None
                       else p.grad.detach().to(torch.float32)).flatten()
                      for p in module.parameters()])

M3: الـ ZeroOptimizer (stage 1)

class ZeroOptimizer:
    def __init__(self, module, world_size, rank, lr=LR, beta1=0.9, beta2=0.999, eps=1e-8):
        self.module, self.world_size, self.rank = module, world_size, rank
        self.lr, self.beta1, self.beta2, self.eps, self.step_count = lr, beta1, beta2, eps, 0
        self.total = flat_param_numel(module)
        pad = (-self.total) % world_size                    # padding عشان القسمة تبقى بالظبط
        self.chunk = (self.total + pad) // world_size
        padded = torch.zeros(self.chunk * world_size)
        padded[:self.total] = gather_flat_params(module)
        self.master_shard = padded[rank * self.chunk:(rank + 1) * self.chunk].clone()
        self.m_shard = torch.zeros_like(self.master_shard)  # Adam moments للـ shard بتاعي بس
        self.v_shard = torch.zeros_like(self.master_shard)

    def shard_bytes(self):
        return (self.master_shard.numel() + self.m_shard.numel() + self.v_shard.numel()) * 4

    def step(self):
        padded = torch.zeros(self.total + (-self.total) % self.world_size)
        padded[:self.total] = gather_flat_grads(self.module)
        chunks = [c.contiguous() for c in padded.chunk(self.world_size)]
        local_grad = torch.zeros_like(chunks[0])
        dist.reduce_scatter(local_grad, chunks, op=dist.ReduceOp.SUM)  # مجموع الـ chunk بتاعي بس
        local_grad.div_(self.world_size)                               # مجموع ← متوسط
        self.step_count += 1
        self.m_shard.mul_(self.beta1).add_(local_grad, alpha=1 - self.beta1)
        self.v_shard.mul_(self.beta2).addcmul_(local_grad, local_grad, value=1 - self.beta2)
        m_hat = self.m_shard / (1 - self.beta1 ** self.step_count)
        v_hat = self.v_shard / (1 - self.beta2 ** self.step_count)
        self.master_shard.addcdiv_(m_hat, v_hat.sqrt().add_(self.eps), value=-self.lr)
        gathered = [torch.zeros_like(self.master_shard) for _ in range(self.world_size)]
        dist.all_gather(gathered, self.master_shard)                   # رجّع الموديل كامل للكل
        scatter_flat_to_params(self.module, torch.cat(gathered)[:self.total])

    # zero_grad و state_dict (master/m/v/step_count) و load_state_dict زي درس ٧٨

def _train_worker(rank, world_size, init_file, iface, ckpt_dir, steps, out_queue):
    init_distributed(rank, world_size, init_file, iface)   # gloo + file rendezvous (درس ٧٦)
    torch.manual_seed(SEED)
    model = MiniGPT()
    for p in model.parameters():
        dist.broadcast(p.data, src=0)                      # الحاجة الوحيدة الباقية من DDP
    optim = ZeroOptimizer(model, world_size=world_size, rank=rank, lr=LR)
    corpus = make_corpus(SEED + 7, world_size * BATCH * (SEQ_LEN + 1) * steps)
    rank0_losses, master_at_ckpt = [], None
    for step in range(steps):
        # كل rank بياخد block مختلف من 4×17 token في كل step
        offset = step * world_size * BATCH * (SEQ_LEN + 1) + rank * BATCH * (SEQ_LEN + 1)
        block = corpus[offset:offset + BATCH * (SEQ_LEN + 1)].reshape(BATCH, SEQ_LEN + 1)
        x, y = block[:, :-1], block[:, 1:]                  # الهدف = الـ token اللي بعده
        optim.zero_grad()
        loss = F.cross_entropy(model(x).reshape(-1, VOCAB), y.reshape(-1))
        loss.backward()
        optim.step()                                       # ZeRO-1 بدل optimizer.step
        if rank == 0:
            rank0_losses.append(loss.item())
        if step + 1 == CHECKPOINT_STEP:
            state = {"model_state": {k: v.clone() for k, v in model.state_dict().items()},
                     "optim_state": optim.state_dict(), "rank": rank}
            master_at_ckpt = optim.master_shard.clone()      # snapshot للمقارنة بعدين
            dist.barrier()
            payloads = _gather_payloads_to_rank0(_serialize(state), world_size)
            if rank == 0:
                save_sharded([_deserialize(p) for p in payloads], ckpt_dir, step=CHECKPOINT_STEP)
            dist.barrier()                                 # محدش يكمّل قبل ما الكتابة تخلص
    param_norm = sum(p.detach().pow(2).sum().item() for p in model.parameters()) ** 0.5
    out_queue.put((rank, rank0_losses if rank == 0 else [], param_norm,
                   optim.shard_bytes(), master_at_ckpt))
    os._exit(0)

_gather_payloads_to_rank0 بيعمل allgather للأحجام الأول، وبعدين بيعمل padding لكل payload لأكبر حجم ويعمل allgather للـ bytes، ويقص كل واحد على حجمه الحقيقي. ده لأن الـ allgather محتاج tensors بنفس الحجم.

def verify_resume(ckpt_dir, expected_world_size, expected_master_shards):
    loaded = load_sharded(ckpt_dir, expected_world_size=expected_world_size)
    return all(torch.equal(loaded[r]["optim_state"]["master_shard"], expected_master_shards[r])
               for r in range(expected_world_size))

    ٣ حاجات بتكمّل التركيب للـ runs الحقيقية

    1. Checkpoint كل K دقيقة، مش كل K step. وقت الـ step بيتغير مع طول الـ sequence وعدد الـ microbatches. cadence كل ١٠ دقايق بتمسك نفس كمية الحساب مهما كان حجم الموديل. الدرس بيستخدم step عشان البساطة؛ الـ production بيستخدم الوقت.
    2. اكتشف الـ divergence بدري. الـ production بيضيف NaN guard بعد الـ backward، وكاشف loss spike: لو الـ loss قفز أكتر من ٢× في step واحد، ارجع للـ checkpoint اللي قبله بدل ما الـ optimizer يمشي في حالة بايظة. منحنى الدرس هادي فالـ guard مش بيشتغل، بس الـ hook موجود.
    3. اجمع الـ memory profile على كل الـ ranks. في الحقيقة الذاكرة بتختلف من rank لـ rank (اللي ماسك أكبر pipeline stage شايل activations أكتر). الـ production بيسجّل الـ max والـ mean؛ الدرس بيطبع لكل rank عشان يوريك إن المعادلة مظبوطة.
    الأداةعلاقتها بالدرس
    DeepSpeedبيجمع DDP + ZeRO + pipeline + activation checkpointing في config واحد. التركيب بتاعنا هو شكل DeepSpeed مصغّر.
    PyTorch FSDPالمكافئ الأصلي. FullyShardedDataParallel مع ShardingStrategy.SHARD_GRAD_OP = ZeRO-2.
    NeMo و Megatron-LMبيضيفوا tensor parallel للموديلات الأكبر جدًا؛ غير كده نفس الشكل.

    Ship It: التراك خلص هنا. الـ ٦ دروس مع بعض هما الـ distributed-training subsystem اللي فريق حقيقي ممكن يبنيه قبل ما يعتمد DeepSpeed: الـ abstraction اتجرّب على gloo والـ failure modes اتجرّبت. ونقل ده لـ cluster حقيقي مكانه Phase 17 (البنية التحتية والـ production).

    08

    التمارين

    1. Tensor parallel للـ attention heads على ٢ ranks: نص الـ heads على كل rank، و allreduce لناتج الـ attention، والـ loss لازم يطابق baseline على rank واحد.
      تلميحقسّم أعمدة الـ qkv حسب الـ heads (كل rank ياخد heads 0-1 أو 2-3)، وقسّم صفوف الـ proj بنفس الشكل. كل rank يحسب جزء من الـ proj output، والمجموع بـ all_reduce(SUM) = الناتج الكامل.
    2. Gradient accumulation على ٤ microbatches وأثبت إن الـ gradient = gradient batch واحد كبير.
      تلميحاقسم كل loss على ٤ قبل الـ backward، وما تعملش zero_grad بين الـ microbatches، ونادي optim.step() مرة واحدة. قارن بـ torch.allclose مع forward واحد على الـ 16 sequence.
    3. Resume من step 10 يكمّل لحد 20 ويطلّع نفس الـ loss النهائي بتاع الـ run الأصلي.
      تلميححمّل model_state و optim_state لكل rank (load_state_dict، ومتنساش step_count عشان الـ bias correction)، وابدأ الـ loop من step=10. الداتا محسوبة بالـ offset من رقم الـ step، فهتاخد نفس الـ blocks.
    4. Metrics export لـ JSONL (loss و grad norm و step time) عشان تعمل visualization بعدين.
      تلميحعلى rank 0: f.write(json.dumps({...}) + "\n") كل step. الـ grad norm الكامل محتاج all_reduce لمربع الـ norm المحلي (زي تمرين الـ clipping في درس ٧٨).
    5. NaN guard بـ rollback لما الـ loss يقفز، واجبر spike بـ LR multiplier لـ step واحد عشان تجرّب الـ rollback.
      تلميحجرّب «LR × 200» في معمل ٣ الأول. القرار لازم يبقى متفق عليه من كل الـ ranks: اعمل all_reduce لـ flag (1 لو spike) بـ MAX، وبعدين الكل يحمّل الـ checkpoint مع بعض.
    6. إضافة مني · اختبار التكافؤ مع rank واحد: شغّل نفس التدريب بـ world_size=1 و batch 16 (الـ ٤ blocks بتوع الـ ٤ ranks في كل step مع بعض)، وقارن الـ parameters النهائية بالـ run الموزّع. ده الـ invariant (e) من معمل ٣، وهو الوحيد اللي بيمسك bug الـ broadcast.
      تلميحمتوسط gradients ٤ ranks كل واحد متوسط على 4 sequences = متوسط على 16 sequence، فالـ Adam هيشوف نفس الـ gradient رياضيًا. الفرق هيبقى بس من ترتيب جمع الـ floats، فاستخدم torch.allclose(atol=1e-5). اجمع الـ 16 sequence بنفس الـ offsets بتاعة الـ ranks بالترتيب.
    09

    إضافة مني: اللي الدرس ما قالوش

    الحدس في سطر: الـ invariants بتثبت إن الـ ranks متفقين مع بعض، مش إنهم صح. عشان تثبت الصح محتاج مرجع بره السيستم: run على rank واحد.
    • الـ broadcast «زيادة» هنا، بس سيبه. كل الـ ranks بتعمل torch.manual_seed(SEED) بنفس الرقم، فالموديلات أصلًا متطابقة قبل الـ broadcast. الـ broadcast هو اللي بيحميك يوم ما حد يغيّر الـ seed لكل rank أو يحمّل weights مختلفة. والأخطر (شوفته في معمل ٣): لو الـ init اختلف، ZeRO-1 هيخلّي الـ norms تتطابق بعد أول step، لأن الـ allgather بيلزق shards جاية من inits مختلفة. الموديل «متفق» بس مش الموديل اللي كنت فاكره.
    • نسيان القسمة على N ممكن يستخبى. Adam بيقسم m على جذر v، فلو الـ gradient كله اتضرب في ٤، التحديث تقريبًا ما بيتغيرش (إلا من أثر الـ eps). مع SGD نفس الـ bug = learning rate × 4. يعني bug ممكن يعيش شهور ويظهر أول ما حد يغيّر الـ optimizer.
    • الـ loss على الداتا دي مش هينزل كتير. الـ corpus من torch.randint(0, 64)، يعني tokens عشوائية منتظمة، ومفيش حاجة تتعلم. أحسن cross-entropy ممكنة = ln 64 ≈ 4.16، والموديل في الأول تقريبًا عند الرقم ده. فالـ invariant الواقعي هنا هو صياغة الكويز: «يوصل لـ step 20 من غير NaN». لو عايز تشوفه بيتعلم بجد، اعمل corpus فيه pattern (مثلًا token[i+1] = (token[i] + 1) % 64).
    • الـ checkpoint هنا gather-then-write. الحالة كلها بتتجمع على rank 0 وهو اللي بيكتب الـ ٤ shards، وده عكس اللي اتعلمته امبارح. مقبول لموديل 30K parameter، لكن في run حقيقي كل rank يكتب ملفه بنفسه، وrank 0 يكتب الـ manifest بس بعد barrier.

    بيظهر فين في الـ LLMs والـ agents

    كل pre-training أو fine-tuning كبير بيمشي على نفس الشكل: init متزامن، step موزّع، checkpoint دوري، guard للـ divergence، و log تقدر تقراه بعدين. وفكرة «run محدود ينتهي بـ exit 0 ويتقاس بـ invariants» هي نفسها اللي بتخلّي أي agent أو pipeline ينفع يتشغّل في CI من غير بني آدم.
